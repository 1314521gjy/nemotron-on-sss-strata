## Phase 2 · 下一枪：**prefill 借槽（borrow）**（排队，等施工席）

**为什么排第一**：唯一"判据都预注册了却从没实现"的机制（`borrow验收判据与kv-resident估值-20261017.md`，122 行，2026-10-17）；**不依赖命中率**；老师实证 prefill +40%（2997 vs 我们 1938）。

**设计（照老师 T 树）**
- 表存在才借（`generate.cpp:1619`）；借 **cache 尾部 = 最低 rank** 的 k 个槽（`:2455-2492`）
- 借出的槽在 prefill 期间当 prompt 缓冲；**prompt 读完 refill**（`:2511-2535`、`:3112-3152`、`:3484-3559`）
- 借多少：目标 3,252 槽（≈10.07 GB 不必流式）⇒ 预期 prefill **1938.8 → ~2200（+14%）**
- env：`STRATA_PROMPT_BORROW`（0=关）、`STRATA_PROMPT_BORROW_SLOTS`（测试用覆盖）

**验收（预注册，逐条勾）**
- **V1（硬）**：ids 45 逐位同（REF-OFF vs borrow ON）
- **V2a 优先**：只借空槽 ⇒ top-probs 逐位同；做不到走 **V2b**：ids 逐位 + 单点 `max|Δp| ≤ 1e-5`
- **N1/N2/N3**：关掉回旧数；连跑 2 次可复现；可借上限设 0 ⇒ 等价关闭
- **S1–S4**：prompt 后再 decode 32–64 token ids 逐位同；借过的槽回填内容抽检；回填耗时应计入 prefill 墙钟；二次 prefill 仍对
- **C1**：借槽需求 > 可借上限 ⇒ **抛异常非 0 退出**，不许静默少借
- 预算：**1 编译 + 4–6 跑 ≈6–8 分钟**，峰值 ≤31,700

## Phase 3 · 依 Phase 1 结果决定：ReLU² down-T 重排

> **2026-10-18 11:35 用户拍板：选 B（neuron-major 全量，接受 ids 末位漂）**。双模式交付：默认 `STRATA_RELU2_DOWN=0` 无损；性能模式 `=1` 快 +35~40%、ids 漂（class-E，需过质量门）。

- **前提已确认**：s = **0.9206**（R51 实测，和 helgard NVFP4 的 92.5% 几乎一样）
- **Stage A 已过（R53）**：sidecar `E:\sp3-sidecar\downT.bin` = 31,708,938,240 B（20,480 × 1,548,288 B）· **10/10 专家逐字节可逆**（负控翻 1 位变红）· 几何 **2688 神经元 / 84 组 × 2048 B / 页对齐**
- **A0 口径 = 半替换**：sidecar 只服务 **CPU decode 的 down 相**；GPU 的 fill/staging/swap 仍读 GGUF 原布局（4 处代码证据）；**RAM 按需 mmap、不 pin、不整文件 touch**（整文件 touch = +29.53 GiB ⇒ 96.6 GiB 必抖，禁止）
- **位精确已判**：ggml `ggml_vec_dot_iq4_nl_q8_0` 是 even/odd 两路 float 累加 + 8 lane FMA ⇒ **rank-1 不保位精确**；块序 gather 可保块内 int32 一致，跨块 float 顺序保持 ⇒ 漂移仅来自 FMA lane 变化（B 路径接受）
- 做法：down 位级转置成 neuron-major 值 + 组级 scale（sidecar **31.7 GB**）+ 活神经元索引只读活字节 + 新 AVX2 down 内核（150–250 行）
- 预期 **+20~35%**（天花板 +44%，因 gate/up 稠密读不可省）
