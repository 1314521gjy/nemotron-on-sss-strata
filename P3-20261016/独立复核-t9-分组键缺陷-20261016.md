## §3-① 独立复核 — 我自己的读码链（A）

**函数** `cpu_experts()`（`src/poly/cpu_experts.cpp:165`），入参含 `const CpuExpert* experts, int n`。

1. **分组键 = `gate` 指针**：`:193` `std::stable_sort(by…, [](a,b){ return experts[a].gate < experts[b].gate; })`；`:196` 组边界 `experts[by[i]].gate != experts[by[i-1]].gate`。
2. **消费点用「组首专家」的权重**：
   - up：`:209` `const CpuExpert& e = experts[byp[i0]];` → `:214` `up = e.up + r*gu_row`；循环内 `:217` 只借 `experts[j].row` 取**该 use 的激活**，权重用 `e`。
   - down：`:249` `down = experts[byp[runp[u]]].down + r*d_row`（同样取组首专家）。
3. **非门控时 `gate` 恒 `nullptr`**：构造点 **`:1926`** `host[n_host++] = { L.gated ? L.exp_gate + e*L.gu_stride : nullptr, … }`（`engine.cpp`）。`L.gated=false`（Nemotron 非门控，`L.relu2=!gated`，`engine.cpp:729`）。
4. **后果**：比较器全等 ⇒ `stable_sort` 保序 ⇒ `by=0..n-1`；`:196` 仅 `i==0` 立组 ⇒ `run=[0]`，`:198` push `n` ⇒ `run=[0,n]` ⇒ **`n_run=1`**；`e=experts[by[0]]=experts[0]`。
   ⇒ **该 call 内所有 CPU 专家 use 全用 `experts[0]`（token0 的 top-1 host 专家的）up/down 权重**，只是激活各用各的。
5. **静默错误，无崩溃、无护栏**：`gated` 分支 `:210/221` 明确写了非门控 relu2 路径 ⇒ 代码**有意支持**非门控，却漏改分组键。**无任何断言/守卫**阻止该路径。

**与 t1 对照 ⇒ 一致。** 差异仅：t1 写的构造点 `engine.cpp:1925`，**实为 `:1926`**（`:1925` 是 `host_k[n_host]=k;`）；消费点 `:209` / `:249` **正确**。

### t1 之外我补的（供 builder 用）
- **根因是「键选错」，不是「没分组」**：`CpuExpert`（`cpu_experts.hpp:51–57`）只有 `gate/up/down/weight/row`，**没有专家 id 字段**；而调用方其实**已经知道 id**（`engine.cpp:1910/1924` 的 `host_e[]`，甚至 probe 用的 `Cached.e` 在 `:1906/:1921`）。⇒ 最小修法 = **按每专家的 `up` 指针（或显式 id）分组**，把 id 传进 `CpuExpert`。这是**结构性**的：门控模型有 `gate` 指针当天然 id，非门控没有。
- **只在 `n_host ≥ 2 且专家不唯一` 时发作**：`n_host==1` 时 `run=[0,1]`、`e=experts[0]` 恰好正确 ⇒ 单专家 call 不受影响。
- **影响面**：`engine.cpp:2017`（少 token `moe()`）与 `:2382`（`moe_rows()` 批路径）**两个调用点都中**（同一函数）。GPU 缓存路径不中（不经此函数）。
- 附注（D，非结论）：`:193` 用 `<` 比较不同对象的指针，属 C++ 未指明行为（实践可行）；换 id 分组可一并消除。

## §3-② 独立复核 — 共享专家读 `xq_`（A + 保留）

**我自己的链**：
1. `layer()`（`engine.cpp:2718–2730`）：`:2720 layer_head()` → `:2726 moe_shared(L,il,n)` → `:2727 moe()`。
2. `layer_head` 的 kMoe 分支调 `moe_router`（`nemotronhmoe.cpp:342`）→ `Engine::moe_router`（`engine.cpp:1866`）：`:1870 if(L.latent_down.p)` → `:1872 lin(latent_down, xn_, moe_in_, n, xq_)` → **`:1873 native_quantize_q8_1(moe_in_, xq_, in_w /*=1024 latent*/, n)`** ⇒ **`xq_` 被改写成 1024 宽**（Nemotron MoE 层 `latent_down` 必在，`nemotronhmoe.cpp:175`）。
3. `moe_shared`（`nemotronhmoe.cpp:423`）`lin(L.sh_up, xn_, g_, n, xq_)`；`sh_up` 宽 `n_embd_=4096`。`lin`（`engine.cpp:1849–1858`）用 `xq` 时按 `native_q8_1_bytes(w.n_in=4096)` 取 stride ⇒ **把 1024 宽的量化缓冲当 4096 宽读**。
4. `sh_up` 是**量化类型**（U43 记 blk.88 `ffn_up_shexp.weight` = 12,386,304 B；{4096,5376} ⇒ 4.5 bit/elem = **Q4_K**）⇒ 走 `lin` 的量化分支、**确实读 `xq_`**（非 F32 绕过）。

⇒ **t1 §3-② 代码级成立：`moe_shared` 的共享专家输入用的是一根被改写成 1024 宽的 `xq_`。**

### ★ 保留（实验反证张力，须对照，不能只靠读码定死）

### ★ 我补的第二处（t1 未提，A，建议 builder 一并看）
`moe_rows()`（**批路径**）里 `host_` 的构造 `engine.cpp:2257`：
```
host_.push_back({L.exp_gate + e * L.gu_stride, …});   // ← 无 L.gated 守卫
```
对着 `moe()` 的 `:1926`（`L.gated ? L.exp_gate + e*L.gu_stride : nullptr`）——**两处不一致**：
- 非门控 `L.exp_gate = nullptr`（`:761`）⇒ `nullptr + e*L.gu_stride`（`e>0`）= **非法指针算术（UB）**，得到一个**非空垃圾 gate**。
- 后果：`cpu_experts` 里 `:210 gated = e.gate != nullptr` 会**误判为门控**，进而 `:213/:219` 解引用该垃圾地址 → **越界/崩溃**可能。
- **当前不触发**：Nemotron `L.mmq=false`（`engine.cpp:1613`）⇒ `batched()` 恒 false（`:1863`）⇒ **批路径从不进入**（`READING-P3-status.md §8` 记"prompt 批暂也走 moe()"）。⇒ 这是**潜伏缺陷**，一旦按 B3 打开批路径就会现形。
- ⇒ **修 §3-① 时务必两处一起改**（批路径 + 少 token 路径），否则提速开批时会崩。
