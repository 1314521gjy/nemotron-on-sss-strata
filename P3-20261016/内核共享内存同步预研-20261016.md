## §2 逐处核覆盖（"A 写、B 读"是否有 barrier 夹在中间）

**#10 多列内核（`native_mmvq_multi_kernel`，`native_mmvq.cu:1289-1382`）逐行核**：
- 写：`:1345-1350`（`if (ty>0)` ⇒ `partial[ty-1][j][i][tx] = tmp[j][i]`）；读：`:1361`（TS 路）/`:1377`（普通路）。
- **索引一一对应**：写者以 `(ty-1,j,i,tx)` 定位、读者以 `(l,j,i,tx)` 读、`l` 遍历 `0..NW-2` ⇒ **每个读位置恰有一个写者** ⇒ **一个 barrier 足够** ✅。
- `if (threadIdx.y > 0) return;`（`:1352`）在 **barrier 之后** ⇒ **不是 divergent barrier** ✅。
- `tmp[NCOLS][ROWS] = {}`（寄存器）：**零初始化，且是各线程私有的** ⇒ 无需 barrier ✅。

**#11 `native_mmvq_slots_kernel`（`:1479-1513`）**：同形（写 `:1502` → `:1504` → 读 `:1509`），`ROWS=2`/`1` 两条实例都同构 ⇒ ✅。`slots`（`MmvqSlots`）**按值传入** ⇒ 落在**内核参数空间（只读）** ⇒ 无需同步 ✅。

**#12/#13（`partial[2][...]` + 循环内 barrier）**：**这是唯一"一个 barrier 可能不够"的结构** —— `partial[2]` 是**双缓冲**，迭代 `k` 读 `partial[k%2]`、写 `partial[(k+1)%2]`；**要同时隔开"读本缓冲"与"写下缓冲"，通常需要两个 barrier（或一个位置正确的）**。⇒ **候选点 ①（结构上）**。
- ⚠️ **但它不在本线的可达路径上**：这两处属 **`q8_packed_launch` / `q6_packed_launch`**（`:1910` 注释 "Persistent workgroups"），即 **`STRATA_Q8_PACKED=1` / `STRATA_Q6_PACKED=1`** 的 opt-in 路径；且本席早前核过 **Q8-packed 的 registry 在本 build 里为空、路径未链入** ⇒ **标记"不可达（同类缺陷，非本次事故）"**。

**⇒ §2 结论（本席）**：**可达的两个内核（#10/#11）的 barrier 覆盖完整，找不到"缺同步"的地方。** ⇒ **我不支持"内核内部缺 barrier"这一归因。**

# §6 收口（2026-10-16 追加；队长派的两件）

## 6.1 ★ `pdl_scope()` 默认值 = **false** ⇒ **候选② PDL 排除（A 级，不再是推断）**

```cpp

bool& pdl_scope() {
    static thread_local bool on = false;   // ← 默认 false
    return on;
}
```
- 它是 **`thread_local` 开关**，只由 `src/core/verify.cpp:899-900` 的 RAII `PdlScope` 置位/复位（即"**verify window's recorder**"，`pdl.hpp:12`）⇒ **poly 本线无 verify recorder ⇒ 恒 false** ⇒ `launch_pdl` 走**普通 `<<<>>>`**（`pdl.hpp:95`，属性只在 `pdl.hpp:80` 为真时加）⇒ **无 `ProgrammaticStreamSerialization` 属性**。

⇒ **PDL 在本线"主机不加属性 + 设备不编入" ⇒ 双重排除。** 候选②**关闭**（可写死："本线不存在 PDL"）。

## 6.2 ★ 跨流写者全表 + R1/R2/R3 覆盖矩阵

引擎只建 **4 条流**（A 级）：`st_`（`:1416` 计算）· `swap_st_`（`:1095-1096` 换入）· `up_`（`:1678-1679` staging）· `rs_`（`:1689-1690` read/跨卡）。使用计数：`cs(st_)=50 · cs(rs_)=9 · cs(swap_st_)=7 · cs(up_)=4`。

| 写者（哪个流） | 写什么 | 使用点 | 配对/同步 | **被哪个开关关掉** |
|---|---|---|---|---|
| **`swap_st_`**（换入流） | **expert slot 的设备内存**（`s->slot`）；`L.slot[e]` 的发布在 **host 侧**（`follow()`） | `cs(swap_st_)` 共 7 处（含 `:1278-1279` 的 `memcpyAsync` + `evRecord(s->done)`） | 消费者靠**主机 `cudaEventQuery(s.done)`**（`:1306`）而非流上等待 | ✅ **R1：`--expert-swaps 0`**（`start_swaps` 直接 return，`:1093`）⇒ **整条流不建** |
| **`up_`**（staging 流） | **只写 `stage_`**（`:2189-2191` 的 wait+`stage(...,up_)`+record；另 2 处是同步/销毁） | `cs(up_)` 共 4 处：`:382` 同步 · `:400` 销毁 · **`:2189-2191` 写** · `:1679` 赋值 | **`ev_free_`(st_→up_) / `ev_ahead_`(up_→st_)** 双向配对（4 行一组，见总纲 §7） | ✅ **R2：`--stage-ahead 0`**（`ahead` 恒 false） |
| `rs_`（read/跨卡） | read 路径的行传递（`ev_in_/ev_out_`） | `:2902/:2925` 等 | event 配对 | — **单卡不涉及**（且不在 decode/长负载路径） |
| `st_`（计算） | **其余一切**（`xq_ / q8_ / g_ / h_ / d_ / stage_ 的 MMQ 读、`moe_out_`、`dx_`…） | 50 处 | 同流有序 | 关不掉（也不该关） |

**★ R1/R2/R3 覆盖矩阵**：
| 开关 | 关掉的写者 | 关不掉的 |
|---|---|---|
| **R1** `--expert-swaps 0` | `swap_st_`（换入） | `up_` · **`st_` 上的跨线程投递** |
| **R2** `--stage-ahead 0` | `up_`（staging） | `swap_st_` · **`st_` 上的跨线程投递** |
| **R3 = R1+R2** | **两跨流写者全停**（`rs_` 单卡不用）⇒ **剩下的写者只有 `st_` 自己** | ★ **`st_` 上的跨线程投递**（下条） |

**⇒ 候选①（"输入其实不同"）在 R3 下剩下的生存空间 = 「从不同主机线程向同一条 `st_` 投递」**（**没有任何旗标能关掉它**）：
1. **`moe()` 的 `launch` 由 Worker 线程执行**（`:2033` 把 `&launch` 作为 `meanwhile` 传进 `cpu_experts`；`cpu_experts.cpp:213` 在**任务 0** 里执行）⇒ **该线程向 `st_` 投递**，而**主线程同时在跑 CPU 专家任务**；
2. **`Behind` 线程跑 `card()`**（`:2399`；`Behind::go` 起 `std::thread`，`:247-248`）⇒ 与主线程的 `cpu_experts` 并发。
- 本席**静态**读到**缓冲不重叠**（`launch`/`card` 用 `g_/h_/q8_/d_/stage_/dx_`；CPU 专家用 thread_local + 读 `h_x_` + 写 `h_cpu_`），**且每个时刻只有一个线程向 `st_` 投递** ⇒ **静态上仍无 hazard**；但**它无法用旗标排除** ⇒ **R3 之后要找"输入不同"只能查这里**。
- ⇒ 探针建议（零 GPU 设计）：**打印每次 `launch`/`card` 的线程 id + 轮次**，看是否出现"两线程交替向 `st_` 投递 / 同缓冲被两线程触碰"。

## 6.3 与"探针假象"的一致性（★ 三条独立路径收敛到同一结论）

队长发现 **builder 的 REPEAT 探针缺 `cudaStreamSynchronize(cs(st_))`**（`st_` 是 `cudaStreamNonBlocking`，`:1416`）⇒ 它报的"同输入两次不同"**可能是读回竞争造成的假象**（形态证据：`≠0` 时的差值是 **21504 的 98%** ⇒ 是"整块无关数据"，非 ULP 级）。
⇒ **三条独立路径现在指向同一结论**：
1. 本席 §2 的**静态 barrier 覆盖完整**（无缺同步）；
2. 本席 §6.1 的 **PDL 双重排除**；
3. 队长的**探针缺陷**（"内核内 race"的**形态证据也不像**竞争）。
⇒ **"内核内 race"这条线基本清了**（不写进 KB 卡，按 §6 的"不写清单"处理）。

**★ 修正后的探针（"内核内部"的唯一真判据）**：**同一次运行内、同一条流（`st_`）、同一输入，连续调用两次，且两次之间 `cudaStreamSynchronize(cs(st_))`**，再逐位比输出。⇒ **缺了那个同步，比的就不是"两次算得一样不一样"，而是"有没有读回竞争"**（两件事都被它混在一起了）。

## 7.1 ★ CPU 专家路径的累加顺序 = **确定**（A 级逐处核）

`cpu_experts.cpp`（sha `4faa619c…`，未变）：

| 段 | 并行粒度 | 写什么 | **并发写同一地址？** |
|---|---|---|---|
| **up 段**（`:205-236`） | `workers.run(first + n_run*gu_tasks, …)`（按 **group × 行块**） | `hp[j*n_ff + r]`（`j=byp[i]`） | ❌ **无**：(j,r) 唯一确定地址 |
| **hq 段**（`:237-239`） | `workers.run(n, …)`（按**条目**） | `hqp[j*h_bytes]`（每线程自己的行） | ❌ 无 |
| **down 段**（`:241-261`） | `workers.run(d_tasks, …)`，`d_tasks = ceil(out_w / 16)`（`kRowsPerDownTask=16`） | **`out[row*out_w + r]`**，任务 `t` 只管 `r ∈ [t*16, …)` | ❌ **无**：**输出行区间互不相交**（每线程只写自己的 16 行） |

**★ 关键：行内求和的次序**（`:254-259`）
```cpp
int j = 0;
for (int row = 0; row < rows; ++row) {
    float acc = 0.f;
    for (; j < n && experts[j].row == row; ++j) acc += experts[j].weight * s[j];   // ← j 跨行单调递增
    out[(size_t) row * out_w + r] = acc;
}
```
- `j` 是**跨行单调递增的单游标**，`acc +=` 的次序 = **`experts[]` 的给定次序** ⇒ **与线程数、与线程完成次序无关** ⇒ **确定** ✅。
- `s` = `static thread_local std::vector<float> one` ⇒ **线程私有** ✅（不会两线程共用累加器）。
- ⇒ **结论：CPU 专家路径是"各线程写自己的槽 + 行内按固定次序单线程求和"⇒ 不随完成次序漂。**（**前提**：`experts[]` 的**内容与次序**确定 —— 而它取决于 `L.slot[e]`（驻留集合）⇒ **驻留集漂 ⇒ 项集与次序都漂**，那是已知的"谁算"问题，**不是累加本身**。）
⇒ **队长这条候选（多线程并发写同一行 ⇒ 末位漂）在静态上排除。**

## 7.2 GPU 侧累加顺序（A 级读码）

| 内核 | 结构 | 判定 |
|---|---|---|
