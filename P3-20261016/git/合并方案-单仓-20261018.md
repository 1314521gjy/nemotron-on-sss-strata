## §6 回滚（分三种；**禁止 `reset --hard`**）

1. **a/b/c 阶段出错（未 commit）**：
   - `git reset`（清 index，工作树不动）→ `git checkout -- .gitignore` 或从 `%TEMP%\gitignore-before-merge.txt` 还原；
   - `Move-Item PolyStrata\.git-upstream PolyStrata\.git`（改回）→ `git -C PolyStrata status` 应空、`HEAD` = `1bdcddea`；
   - 若 rename 造成损坏：从 `E:\视频\_backups\20261018-git-merge\PolyStrata-dotgit\` 整体 copy 回 `PolyStrata\.git`。
2. **已 commit 但判定不对**：
   - `git reset --soft HEAD~1`（撤销合并提交、**保留工作树与 index**）→ `git reset`（清 index）→ 还原 `.gitignore` → `Move-Item .git-upstream .git`；
   - ⚠ **绝对不要 `git reset --hard HEAD~1`**：PolyStrata 源文件只存在于合并提交里，hard reset 会删工作树源码。
3. **全量还原**：备份目录 `E:\视频\_backups\20261018-git-merge\` 里保留 `.git` 原样；恢复上游仓 = `Move-Item PolyStrata\.git-upstream PolyStrata\.git`。
   - 台账必须写死的一句：**"恢复上游独立仓 = 把 `PolyStrata\.git-upstream` 改回 `PolyStrata\.git`"**。

## §7 已知副作用与风险（合并前须知）

1. **`PolyStrata/.claude/worktrees/desktop-main-aa73018d` 会断链**：其 `.git` 文件指向 `PolyStrata/.git/worktrees/...`，rename 后路径失效；该目录 **3,294 文件**必须排除（`.gitignore` 已排）、**不删**。恢复 A 仓（rename 回来）后若不再需要它，可经 lead 批准用 `git worktree prune/remove` 清理。
2. **合并后无 remote**：B 仓本身无 remote；上游 remote 只存在于 `PolyStrata/.git-upstream/config` 里 ⇒ 合并仓不可能误 push。
3. **`.git-upstream` 是大坑**：若被误 add 会暴露内部对象/remote URL；`.gitignore` 已显式排除 + §5 有扫描项。
4. **A 的跟踪历史**（`1bdcddea` 等）只在 `.git-upstream` 里；合并仓看不到该 commit——台账记录 A 旧 HEAD/tree，恢复方法见 §6-3。
5. **规则优先级**：父级 `!PolyStrata/**` 放行 + 子级 `PolyStrata/.gitignore` 拦截构建物；若发现某构建物没被拦（§5 扫描非空）⇒ 停、报 lead，不自行 `-f` 绕过。
