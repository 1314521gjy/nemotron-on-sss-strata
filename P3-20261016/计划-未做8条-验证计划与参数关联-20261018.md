## 2. 每条的验证计划（预注册）

### 1.6 RouterLookahead（先导：准确率）
- **打点**：在 `route()` 后 dump `layer, token, ids[22]`（二进制，≤30 行；env `STRATA_DUMP_ROUTE=0|1` 默认 0）
- **离线**：用 dump 算两种预测器的 top-22 重合率
  - (a) `h_l × W_router(l+1)`（老师的做法；需 dump h 或让引擎直接算预测命中）
  - (b) 用 l 层的 top-22 ids 做 n-gram 预测（零成本代理）
- **判据**：**(a) 的重合率 ≥40% ⇒ 立项**；(b) 若 ≥40% 也可先试（零成本）
- 预算：1 编译 + 1 跑（dump，max-new 32）+ 零 GPU 离线

### 1.7 ForesightSwap（依赖 1.6）
- 预取缓冲：**优先用闲置 staging/ring（3GB=968 槽）**，不动 cache（避免与 borrow 抢）
- **淘汰策略**：预取槽是循环覆盖（每层重写）⇒ 不参与 cache 的 LRU
- 判据：**decode 配对 ≥+10%**（p=40% ⇒ 理论 +15~20%）；峰值 **不增**（用闲置内存）；ids class-E
- 预算：1 编译 + 4 跑（alt + p6792 各 2）

### 1.8 CPU 帮搬
- 前置：1.7 的 prefetch 用 DMA 引擎（不占 CPU）⇒ 若已经不吃 CPU，则本项无意义 ⇒ **只在"prefetch 拖慢 CPU 腿"时才做**
- 判据：CPU 腿 `cpu_us/miss` 不升（≤+2%）

### 1.9 Coverage Curve 分配
- **零 GPU 先模拟**：用 `p_decode2`（20,911 行计数）+ 6,746 槽，比较：
  - 现状（全局 top-N）· 按曲线贪心（每层按边际收益分）· 老师等分
- 判据：**模拟 hit 提升 ≥2pp ⇒ 1 编译 + 1 跑**；否则判否（已有等分 +0.10pp 的先例）
- **耦合注意**：与 B1 表叠加（B1 已到 75.3%，剩余空间小）⇒ 必须在 **B1 表**上模拟

### 1.11 Prefill head alias
- 读码确认：prefill 期输出头 440.4MB 是否闲置（它只在最后 head gemv 用）⇒ 是则可借
- 借给 staging ⇒ staging 变大 ⇒ prefill 收益（R54：staging 减半 −11% ⇒ 加 142 槽 ≈ +3~5%？）
- 判据：prefill ≥+2%；峰值不增（借用而非新增）
- **耦合**：与 1.10 borrow 抢同一块"借来借去"的显存 ⇒ 先算总账

### 1.12 KV 预取重叠 / 1.13 Batched DMA
- 1.12：只有 8 attn 层 ⇒ 预估 <1% ⇒ **暂缓**
- 1.13：判据 host/launch ≥−20%（R49 实测 4.9ms/轮）⇒ 若 host/launch 本身只占 7% 且已判"不在关键路径"（Phase 5 结论）⇒ **判否**

### 6.3 1.6/1.7 RouterLookahead + ForesightSwap → **值得做，但必须先打点**
**老师的形态（file:line）**
- RouterLookahead（`expert_source.hpp:241-245`）：**layer l+1 的 router（BF16 host copy）作用在 layer l 的 MoE input** → 每 token top-k（k 默认 10）→ 去掉已驻留 → **只 `warm()` 预热页**；depth 1–4
- ForesightSwap（`STRATA_FS_SLOTS=N`）：每层 N 个 VRAM 槽，copy stream 填「刚 miss + 下一层预测」；**槽从 expert cache 的 VRAM 扣**
- ★★ **老师自己的 FS 是负结果**：4/16 槽实测 decode **0.91–0.98**（3060/P100/5070）⇒ **left off**（`docs/DETAILS.md:1736-1744`）
  ⇒ **原因**：槽从 cache 扣 ⇒ 直接减少常驻。**所以我们必须走"用闲置 staging/ring 的 3GB（968 槽）"，不碰 cache** —— 这是新用法、无先例

**准确率先验（C 级）**：老师 5070Ti **recall 27–34%、precision ~8%**；64GB 全驻留时 lookahead 无可测效果（我们全 RAM 驻留 ⇒ 不能照抄 warm，只能做 FS 换腿）

**收益公式（本机 alt 交付口径）**：wall 53.9ms、cpu pool **37.1ms（68.8%）**、miss 340.9/token、u≈108.8µs
`增益 ≈ f × 68.8% × (1 − g/u)`（f=转换比例，g=GPU 路成本）
- recall 30% ⇒ 上限 **+14~20%**，现实 **+8~15%**（D）
- recall 10% ⇒ +3~7%（边缘）

**Go 门（先打点）**：`STRATA_DUMP_ROUTE=1`（22–25 行、1 编译、2 跑 ~84MB/条）→ 离线算 recall/precision + **预测 miss/层 ≤24 槽**（968 槽≈24/层）
**判据**：**recall ≥30% ⇒ 1.7 立项；<25% ⇒ 1.6+1.7 一并判否**

## 8. 16:15 最终判决：**1.6 + 1.7 = 判否（结构性原因）**

### 8.1 实测（R74）
- dump：265,348 行 / 25.15 MB / 14,684 tokens / 5,614 个相邻层对
- **相邻层 top-22 重合率 = 4.20%**（每层 3.4–5.3%）
- 负控（左层换随机 22 专家）= **4.32%**，随机基线 22/512 = **4.30%**
⇒ **真实值 ≈ 负控 ≈ 随机 ⇒ 相邻层路由无预测力**

### 8.2 为什么老师能我们不能（**结构差异，不可修**）
| | 老师 | 我们 |
|---|---|---|
| MoE 层排布 | **48 层连续 MoE** | 40 MoE 层**被 40 mamba + 8 attn 隔开** |
| 相邻 MoE 层之间残差流 | 变化小（老师假设成立） | **变化大**（中间夹了 mamba/attn） |
⇒ 老师的 `RouterLookahead`（"residual stream changes little"）**前提在我们的模型结构上不成立**。

### 8.3 并发带宽窗口也不支持
- v1（pinned memcpy 读）：比值 1.358
- **v2（引擎同款读法）：C 32.29 / P 23.46 / 并发 39.99 ⇒ 比值 1.239 = 微弱区**
- 老师自己的 FS 是负结果（4/16 槽 decode **0.91–0.98**，`docs/DETAILS.md:1736-1744`）
⇒ **FS 完整版不立项**。

### 8.4 口径订正
**41.3 GB/s 是"多流交织+硬件预取+读写交错"的合流读数；单流上限 32.29 GB/s** —— 以后不许拿 41.3 当单流上限。
