## §0 一句话

> **`--resident-budget-gib N` = 给"RAM 常驻副本"一个**上限**：先放下"GPU cache 不持有的全部专家"（complement），再按 profile 从**缓存尾部**补上"会被 prompt 借走的那些槽"的专家；**剩下的不常驻，读文件**。**
> **GPU 与 RAM 不重复存**（RAM 存的是 GPU 的补集 + 借出尾部）；**钉的是同一份 RAM 副本**（`--resident-cpu-experts` 页可换出，`--resident-experts`/budget 页锁定）。

## §1 六条逐条

### 1. 它管什么

`docs/DETAILS.md:262-266` 原文：
> "**A RAM budget (engine 0.1.31, `--resident-budget-gib N`):** the resident variant for a model whose experts do not all fit: **the N GiB of experts the GPU cache does not hold that the expert profile ranks hottest are copied into RAM at start (locked; page-locked when the driver allows the whole budget), and the rest are read from the files.** It implies `--mmap-experts` and leaves 4 GiB of headroom."

- 单位是 **GiB**；只算 **GPU cache 不持有的专家**（补集）；按 **profile 热度**取前 N GiB。
- 超出预算的：**读文件**（mmap / pack），不是流式到 VRAM。
- 参数解析：`generate.cpp:2219-2227`（`o.resident_budget = gib*2^30`；同时置 `mmap_experts = resident_cpu_experts = resident_pin = true`；headroom 由 `STRATA_RESIDENT_HEADROOM_GIB`（默认 4）覆盖；装不下时把 `resident_pin` 关掉）。
- 预算被 clamp：`clamp_resident_budget(requested, physical, commit, headroom)`（`expert_source.hpp:88-90`：RAM 与 commit 取小、减 headroom、再留 256 MiB）；**装不下至少是 WARNING**（`generate.cpp:7155`）。

### 2. 三集怎么划

| 集 | 选谁 | 出处 |
|---|---|---|
| **GPU cache** | profile 热度前 N（按槽大小归一）；启动填满，decode 期按 `recent_` 自适应换 | `program` 侧：`--expert-cache`；我们 poly 侧：`fill_expert_cache()`（`engine.cpp:1086`） |
| **RAM resident** | ★ **补集优先**：`base_bytes`（所有 GPU 槽都不持有的专家）**必须**先装进 budget；然后**从缓存尾部往前**把"可能被借出的槽"的专家也放进去（`lend_from = slots - k`，k = prompt 可能借的槽数）| `choose_resident_keep_from(slot_bytes, base_bytes, budget, lend_from)`（`expert_source.hpp:127-134`）；调用 `generate.cpp:7014-7018`、`:7086` |
| **按需搬运** | prompt 借出的槽 + 未常驻的专家：从 RAM（若在）或文件读，DMA 进借来的槽；prompt 后把借出的槽**从 RAM 拷回** | `expert_source.hpp:127-131`；`AMD_HIP.md:228-230` |

★ **是否互斥**：**主存上是互斥的**（RAM 副本 = GPU 的补集）；**唯一重叠 = 缓存尾部"会被借出"的那 k 个槽**——它们同时在 GPU cache 和 RAM 里，为的是借出时不必读文件。
- 交换时 `exchange_cache_complement(in, out)`（`expert_source.hpp:136-138`）：GPU 换进 `in`、换出 `out`，则 `out` 占 `in` 在 RAM 副本里的位置 ⇒ **RAM 始终等于"GPU 不持有的那批"**。
- ⇒ **给我们的数**：40 层 × 512 = 20,480；GPU 7,388 ⇒ **补集 13,092 专家 = 37.76 GiB**（3.0966 MB/专家）。**不是 39.2**（39.2 = 用 41 层/60.5 GiB 的总额减 21.3）；若再算上"借出尾部"（pb=6912 需借 ~3,748 槽 ⇒ +11.06 GiB），**RAM 副本 ≈ 48.8 GiB**。

### 3. RAM 那层怎么钉

| 模式 | 机制 | 出处 |
|---|---|---|
| `--resident-cpu-experts` | **普通页**（pageable）的匿名 RAM 副本 | help `_help-v0.1.43.txt:238-240`；`AMD_HIP_PERFORMANCE.md:36-38` |
| `--resident-experts` | `= --mmap-experts --resident-cpu-experts`，**整份尽量页锁**（`cudaHostRegister`），**4 GiB headroom**，装不下退回普通 mmap | `generate.cpp:2210-2216`；help `:241-243` |
| `--resident-budget-gib N` | 同 resident，**锁定**；"page-locked when the driver allows the **whole budget**" | `generate.cpp:2223-2227`；`DETAILS.md:263-264` |
| 日志证据（3.8-Flash 实跑） | `expert arena: cudaHostRegister PORTABLE ok; large pages refused … using 4 KB pages` + `loaded 46.84 GiB` | `_staging/dec-pool2.txt:26-30` |

- 页锁失败的兜底是**响亮的**（`note()` / WARNING），且可退回 pageable（`resident_soft`，`generate.cpp:7089`）。
- `STRATA_RESIDENT_HEADROOM_GIB`（默认 4）是"给系统留多少"，与我们的 `+8 GiB` 硬线不是同一个东西（我们是拒绝阈值，它是预算扣减）。

### 4. "边搬边算"的结构

`src/prefill/prefill.cpp:133-136` 原文：
> "Step 3: from this chunk size on, **every non-resident expert of every layer streams in a fixed order through a `ring_slots()`-slot ring** (nearly all 512 are routed at such a chunk), **so the copy engine keeps working through the attention halves instead of waiting for each layer's routing.**"

- **缓冲**：一个 **N 槽的 ring**，每槽一个完整专家 blob。N 默认：**384**（几乎全部从 pinned RAM DMA 时；Q2_0 8192-chunk：96→1153、384→1294 tok/s）或 **96**（大量走 host 拷贝时；IQ3_S 64 GB：96→1216、256→1070）。**按字节预算反推槽数**（`ring_budget_slots()`，`prefill.cpp:285-300`）；`STRATA_PREFILL_RING` 覆盖。
- **顺序**：不再按"本层路由"逐个等，而是**固定顺序把下一层/后面的专家预先灌进 ring**，拷贝引擎在 **attention 段**继续工作。
- **依赖**：`fetch(n)` 启动 n 个槽的 DMA，落地后**信号** GPU（`expert_source.hpp:327-329`）；计算侧按槽等待。`note_async_read(blob, stream)`（`:172-178`）保证 DMA 读完前不回收源。
- **开关**：`STRATA_PREFILL_STREAM_AHEAD`（默认开，`prefill.cpp:125-131`）；`STRATA_STAGER_SLEEP` 控制等待方式（`:145-150`）。
- ★ 与我们的对照：**我们是单 `stage_`、逐轮串行**（`round_` + `stage()` + `ev_copy_/ev_krn_`）；**它是 ring，允许多个未来轮在飞**。

### 5. `--resident-cpu-experts` 与 budget 的关系

- `--resident-cpu-experts` **没有上限**：把"GPU cache 不持有的全部专家"放进普通 RAM（pageable）。
- `--resident-budget-gib N` = **给同一份东西加上限 N GiB**（只留最热的 N GiB，其余读文件），并顺带把 `mmap/resident/pin` 一起打开。
- `--resident-experts` = setup 给"低内存 PC"选的组合（`mmap + resident-cpu + page-lock 尽量 + 4 GiB headroom`）。
- 源码：`generate.cpp:2208-2227`；help `:238-243`。

### 6. ★ 能不能只搬实现、不改语义地接到 `moe_rows()`

**能，但要分三块搬，且语义有一处必须预先接受：**

| 块 | 现状（poly `moe_rows`） | 照搬后 | 语义影响 |
|---|---|---|---|
| **A. RAM 常驻副本** | 无（专家直接 mmap；`STRATA_PIN_ARENA_GIB` 只是**按层前缀**钉页，不是补集） | 建 **complement + 借出尾部** 的副本（37.8 + 11.1 = **48.8 GiB**）；可先 pageable，再尝试整份 `cudaHostRegisterReadOnly` | **不改**（同一批字节） |
| **B. 借槽** | `stage_` 是**独立 scratch**（`fbuf`），pb 一大就吃驻留 | **借 VRAM cache 的尾部槽**当 staging，prompt 后从 RAM 回填（~200 ms/2,387 槽比例） | **改驻留集合**（prompt 期间少 2–3.7k 槽）⇒ **top-probs 允许末位漂移，ids 必须逐位**（见 borrow 判据 V2b） |
| **C. 流水（边搬边算）** | `round_` 串行 + 单 `stage_`；只有 ahead 预取走 `up_` | **ring（N 槽）+ 固定顺序预灌**，拷贝在 attention/上一轮 kernel 之下 | **不改数值**（只改时序） |

- **不需要动**：`group_/round_` 的**行映射**（`bounds/rel/d_place`）、MMQ 的 `cb[tile_class]`、`moe_sum`、latent 几何——这些与"专家从哪来"无关。
- **必须新增的接口**（照搬 `ExpertSource` 的最小面）：`pinned(layer,expert)`（能否直接 DMA）、`blob/copy_blob`（RAM 副本）、`prefetch/warm`（ring 预灌）、`note_async_read`（异步安全）。`expert_source.hpp:166-230`。
- **建议顺序**（与 builder 现在的方向一致）：
  1. **A（RAM 副本，pageable）**：把"层前缀 pin"换成"补集 + 尾部"；先不 pin，验"读文件次数 → 0"。
  2. **B（借槽）**：去掉 `stage_` 的独立分配，借 cache 尾部；按 `borrow验收判据`（ids 逐位、decode 逐位、冲突响亮）。
  3. **C（ring）**：单 `stage_` → N 槽 ring，固定顺序预灌；这是"边搬边算"的实质。
- **不改语义的边界**：A/C 完全不动数值；**B 会动驻留集合**，所以 **ids/decode 是硬判据，top-probs 走 V2b 容差**（已在前件预注册）。

## §3 未验 / 边界

1. **【未验】** 我们 48.8 GiB 的副本 + 8 GiB 硬线是否稳（当前 76.2 GiB free；`cudaHostRegisterReadOnly` 对文件映射页的整份注册可能失败——上游就出现过 "cudaHostRegister on 31.64 GiB fails"，`generate.cpp:4727-4737`）。
2. **【未核】** `--resident-budget-gib` 在 **poly 引擎**里不存在（这是 `src/program` 的旗标）；polymer 只实现了 `STRATA_PIN_ARENA_GIB`。所以"照搬"= 把 `src/program` 的 **语义** 搬到 poly，而不是加一个同名旗标。
3. **【未核】** ring 的槽字节预算（`ring_bytes()`）在我们的 pack（3.0966 MB/blob）下会解析成多少槽——按 384 槽同字节预算折算会远小于 384（上游在 Q8_0 上就被迫降槽）。
4. **【口径】** "39.2 GiB" = 41 层总额 − GPU；我们的实际补集是 **37.8 GiB**，差在 MTP 第 41 层。
5. 本件**只读、零 GPU、未改码、未碰 `E:\strata`**。
