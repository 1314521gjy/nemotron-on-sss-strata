## 结论（三选一）：**成立** —— 但**附一条对"形态证据"的更正**

**代码级成立**（A）：探针两次读回**都没有同期**，且它偏离了引擎自身的读回惯例 ⇒
**探针的"同输入两次不同"不能排除"读回竞争"** ⇒ **「内核内 race」的归因应降为【待判】**。

**但"形态已排除 ULP 级"这半句，由我实测**是**过度断言** —— 详见 §3。

## §1 代码级证据（A，逐行读过）
探针全文在 `engine.cpp:1990-2005`：
```cpp
1990  if (getenv("STRATA_PROBE_REPEAT") && il == 1) {
1991      const size_t pn = (size_t) m * gu_w;
1993      cudaMemcpy(p1.data(), g_, pn*sizeof(float), cudaMemcpyDeviceToHost);   // ← 读回①，无同步
1994      one2 = ... native_mmvq_slots(..., st_);                                  // 第二次同输入 mmvq
1995-96   for (j...) native_mmvq(..., st_);
1997      cudaMemcpy(p2.data(), g_, pn*sizeof(float), cudaMemcpyDeviceToHost);   // ← 读回②，无同步
1998-99   diff = count(p1[q] != p2[q]);
2000      p1[0] = nextafterf(p1[0], 1e30f);                                        // 扰动【自己】一个元素
2001-02   ctl  = count(p1[q] != p2[q]);
```
1. **`:1993` / `:1997` 是 `cudaMemcpy`（非 Async、无 stream 参数）** ⇒ 走 **legacy 默认流**。
2. **`st_` 是 `cudaStreamNonBlocking`**（`:1416` `cudaStreamCreateWithFlags(&st, cudaStreamNonBlocking)`）；
   `up_` 也是（`:1095`）、`rs_` 也是（`:1689`）。
3. ★ **机制比"漏了一句同步"更锋**：**非阻塞流与 legacy 默认流之间【没有隐式同步】**（这正是 `NonBlocking` 的定义）
   ⇒ **两次读回与 `st_` 上排队的 mmvq 内核之间【没有任何顺序保证】** ⇒ 读回可能在内核完成前发生 ⇒ **p1/p2 可能读到"上一代/半成品"的数据**。
4. **引擎自身惯例确实是"先同步再读回"**（A）：
   `:1827 ck(cudaStreamSynchronize(cs(st_)), "dump")`（`dbg()` 的读回）· `:2855 ck(..., "read")`；
   且 `cudaStreamSynchronize(cs(st_))` 在 `:1827` 与 `:2421` 之间**再无出现** ⇒ **探针这一段确实漏了**。
⇒ **§1 = 断言成立。**

## §2 比较器的"正控"**不构成正控**（A，代码 + 实测一致）
`:2000` 的"正控"是 **`p1[0] = nextafterf(p1[0], 1e30f)`** —— **扰动自己（p1）的一个元素**，再重数差异。
它证明的只是「**比较器能看见我人为放进 p1 的那 1 个元素**」，**证明不了「p1 与 p2 是否因数据本身而不同」**。
实测（`loc_base.log`，A）：
- `repeat_diff != 0` 的 977 行里，**`|control_diff − repeat_diff| ≤ 1` 占 100%**、`== ` 占 68.1%
  ⇒ **正控与主线几乎恒等，从不提供独立信息**。
- `repeat_diff == 0` 的 479 行里，`control_diff` **恒为 1** ⇒ 它只是那条被人为扰动的元素在响。
⇒ **§2 = 断言成立**：**正控必须是「已知不同的输入」，不能是「扰动自己一个元素」。**

## §3 ★ 形态证据的更正（**我实测，与队长给的数字有出入**）
队长给的形态证据：「`≠0` 的差值是 **21232~21504**（= 8×2688 的 55%~100%）⇒ 整块无关数据而非 ULP 级」。
**我按 `loc_base.log` 全量复算（1456 行 `ndrep`）：**
| 项 | 我的实测 |
|---|---|
| `ndrep` 行数 | **1456** |
| `repeat_diff == 0` | **479 行（32.9%）** ✓ 与队长一致 |
| `repeat_diff != 0` | **977 行（67.1%）** ✓ 与队长一致 |
| `pn`(=n) 取值 | **8 种**：2688 / 5376 / … / 21504（= `m×2688`，m=1…8） |
| **`repeat_diff` 全量范围** | **6 ~ 21504** ← ★ **不是 21232~21504** |
| **`n=21504` 子集范围** | **6 ~ 21504** ← ★ 也**不是** 21232~21504 |
| 按 n 分组 | n=2688：327~2688（12.2%~100%）；n=8064：4766~8064（59%~100%）；n=10752：2741~10752（26%~100%）；… **各 n 组都同时含"接近全块"与"远小于全块"** |

**⇒ 更正**：**"整块无关数据"只解释了多数行**；**存在 `diff` 极小的行**（最小 **6 / 21504 = 0.03%**）。
⇒ **形态【不能】单独排除"kernel 级小差异"** —— 小 diff 的那批行，**既可能是读回竞争，也可能真是 kernel 差**，**现有数据分不开**。

**⇒ 对结论的影响**：**不推翻** §1（"缺同期"是代码级事实，独立成立）；**但削弱了"形态已排除 ULP 级"这半句** ⇒ 该半句应**降为"多数行形态支持'整块不同'，少数行未解释"**。
