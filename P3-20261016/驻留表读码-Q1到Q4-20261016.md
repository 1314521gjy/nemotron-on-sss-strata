## Q1 ★ 常驻表怎么设定：`fill_expert_cache()` 的排序键与取谁

### 1.1 三个步骤（全部 A 级读码）

| 步 | 做什么 | `file:line` |
|---|---|---|
| **建候选** | 对**每个 MoE 层 × 每个专家**建 `Cand{il, e, bytes, value}`，`bytes` = 该层槽字节（`(slot_down + d_bytes + kTail)` 向 `unit` 对齐） | 构造 `:1014-1036`；`bytes` = `:1025`；`unit` = `:1022-1024` |
| **排序键** | `value = used / (double) bytes`，`used = (prior_.empty() ? 0 : prior_[i]) + use_[i]`（`i = il*n_expert + e`） | `:1032-1033` |
| **取谁** | `std::stable_sort` **降序**；**平票只按 `e`**（`a.e < b.e`）；然后**按序取，直到 `room`(=arena) 用尽**（装不下的**跳过继续**） | 比较器 `:1037-1038`；取循环 `:1061-1067` |

**★ 两处容易读错、必须写清**：
1. **平票比较器是 `a.e < b.e`（只比 `e`，不比 `il`）**（`:1038`）。⇒ 当 `value` 全相等时，**两个"同 e 不同 il"的候选互不序**（返回 false 双向）⇒ **`stable_sort` 保持构造顺序** ⇒ **构造顺序 = `for il{ for e{…} }` = 层主序**。**⚠️ 不是"跨层按 e 排"。**
2. **选取序 ≠ 摆放序**：取完之后还有一次 `std::sort(taken, il→e)`（`:1068-1069`），那只是把槽**按层排好摆放**（"a layer's side by side"，`:1060` 注释），**不影响"取谁"**。

### 1.2 ★★ 两个分支（这是 Q1 的答案）

| 情形 | `value` | 排序结果 | **取到的是** |
|---|---|---|---|
| **① 有 counts**（喂了 profile 和/或本次已跑出 `use_`） | `(prior_ + use_) / bytes` | 按**每字节使用量**降序；平票按 `e` | **热度优先**：每字节被用得最多的专家先上卡（同层内等价于"使用次数高的先上"） |
| **② 无 counts**（既不喂 profile、`use_` 也全 0） | 全 **0** | **全平票** ⇒ `stable_sort` ⇒ **构造顺序** | ★ **层主序前缀：从 `il=0` 起整层整层地装，直到容量满** ⇒ 实测 8010 对 ÷ 512 = **前 ~15.6 个 MoE 层**（第 16 层装一部分） |

### 1.3 ★ 对 KB 草稿那条的核实结论（按队规：核实后改机制、保留数字）

KB 草稿（卡 5 证据④）原文：「无 profile ⇒ 退化成"按专家 id 升序" ⇒ **驻留集 = 每层 id 前缀**（预测命中 ≈204/512=39.8%），与实测 40.6% 吻合」。

**核实结果**：
- **机制描述错**：不是"每层 id 前缀"，而是 **"按层序的前缀"（前 15.6 个整层）**（§1.1 第 1 点：平票比较器不构成跨层全序 ⇒ `stable_sort` 保层主序）。
- **数字是对的**：实测 **40.6%**（t16，`--dump` ⇒ `rows_=1` ⇒ 全非批路径）≈ 容量比 **39.1%**（8010/20480）—— **两种取法的命中期望都在 39–42%**（层前缀：16 层全中 + 第 16 层部分 ⇒ ~41.6%；每层 id 前缀：22×(204/512)×40/880 ⇒ ~39.8%）。
- **⚠️ 关键限定（必须写进卡）**：**该 40.6% 的观测不足以区分这两种机制** ⇒ 不能拿它当"层前缀"的证据；"层前缀"的证据是**读码（B）**。
- **要 A 级实证的最小钩子**（零 GPU 设计）：在 `:1063-1067` 的取循环里，env 门控打印 **`taken` 按层的计数**（一行 40 个数）⇒ 一眼看出是"整层"还是"每层前缀"。**不建议现在为它开窗口**（不是阻塞项）。

## Q2 ★ "默认"是什么（不喂任何 profile / 不给其它旗标）

**要读死的三件事**：

1. **候选值与排序**：`opt_.profile` 空 ⇒ `read_profile` 直接 return（`:176-179`）⇒ `prior_` 空；`use_` 在 `alloc()` 里 `assign(...,0)`（`:1692`），而 **`alloc()` 在 `fill_expert_cache()` 之前**（`:1487` → `:1489`）⇒ **`use_` 恒为 0** ⇒ **§1.2 的 ② 分支**。
   ⇒ **默认驻留集合 = 按层序从头装的整层前缀**（本机实测容量 8010 对 ⇒ **前 ~15.6 个 MoE 层**）。
2. **装多少由 arena 定**：`arena = min({all, free_b − reserve, …})`（`:1043`），而 **`reserve` 默认由卡的大小定**：`default_reserve_mib(total_b, ram_tight)` = `clamp(total_b>>25, 256, 768)`（非 tight）/ `clamp(total_b>>24, 512, 1024)`（RAM tight）（`:330-333`，调用 `:1001-1002`）。⇒ **32 GB 卡默认 reserve = 768 MiB（非 tight）/ 1024 MiB（tight）**。
3. **观测口（零猜测，跑一次就能读死）**：
   - 加载行：`… N of 20480 routed experts in VRAM (x.x GiB)`（`engine.cpp:897`）；
   - `--serve` 的 `INFO` 行：`INFO context=… expert_slots=… expert_cache_mib=…`（`main.cpp:540-545`）；改 reserve 后还有 `VRAM reserve_mib=… expert_slots=… expert_cache_mib=…`（`main.cpp:584-588`）。

**⇒ 结论（可直接回答）**：**"默认"就是把卡上装得下的容量，按"从第 0 层往上、每层 0→511"的顺序填满**；本机默认（`--vram-reserve-mib 2500` 那一档）实测 = **8010 / 20480 对（39.1%），23.1 GiB** —— 即 **前 15 整层 + 第 16 层的一部分**。**没有任何"按层重要性/按热度"的默认智能**：热度只有喂了 counts 才有。

## Q3 ★ "随工作自动拟合曲线" = `--expert-profile` 的累积计数（确认等价 + 当前开关状态 + 两阶段用法）

### 3.1 等价关系（确认，A）
- **学习载体**：`save_profile()` 把 **`prior_`（上次的计数）+ 本次跑累计的 `use_`** 相加后写回：`all = last->prior_; … all[i] += e->use_[i]`（`:1702-1706`），逐行输出 `"层 专家 计数"`，**只写 `n > 0` 的行**（`:1710-1714`）。
- **下次生效**：那次写回的文件，下次被 `read_profile` 读成 `prior_`（`:181-189`），**直接进 §1.2 ① 的排序键** ⇒ **使用次数多的专家下次先上卡**。
⇒ **这就是本引擎"随工作自动拟合"的唯一对应物**（没有别的自适应机制：`grep` 无 resident/group/curve/learn）。

### 3.2 ★ 当前开关状态：**默认关闭（只读）**，要 `--expert-profile-write` 才开
- **写侧**：`save_profile()` 第二行 **`if (!opt_.profile_write) return;`**（`:1697`，注释原文 "DEFAULT READ-ONLY"）；`profile_write` 默认 **false**（`engine.hpp:45`），只有 `--expert-profile-write` 置真（`main.cpp:835`）。
- **→ 附加一条**：`if (opt_.profile.empty()) return;`（`:1696`）⇒ **不喂 profile ⇒ 连"写"都不会发生**，没有默认落盘位置。
- **读侧**：只要给了 `--expert-profile FILE` 就**一定**读（`:834`）。
⇒ **"自动拟合"现在的默认 = 完全关闭**（既不读也不写）；我们今天的修法（t17）把读写**双向自证**（`:177-179` 失败告警 + `:191` 成功打印 `loaded N entries`）。

### 3.3 ★ 代价 / 收益 + **两阶段用法（操作定义）**

| | 内容 |
|---|---|
| **收益** | profile 是**唯一已知能抬"命中质量"的量级手段**（机制层；Cyber 线曾见 +31.7%）。它抬的不是"容量"而是"**在 39% 容量里装谁**"（`KP-UNI-0228`「收益在选受害者」） |
| **代价（已判为正确性缺陷）** | **开了回写 ⇒ 跨运行漂**：每跑把本次计数累加上去 ⇒ 起始驻留集合逐跑变 ⇒ 数值逐跑变（**`KP-UNI-0244` 的判决**） |
| **⇒ 纪律** | **只在"受控学习窗口"里开写，学完冻结**；**生产/对照跑一律只读** |

**两阶段操作定义（照敲级）**：
```
【阶段一 · 学习】（只此阶段开 write；负载 = 生产同分布）
  run … --expert-profile p_learn.txt --expert-profile-write      # 可重复多轮；p_learn.txt 逐轮累积
  # 结束判据（任选，须先定）：① 跑够 N 轮；② p_learn.txt 的 top-K 集合连续两轮不变

【阶段二 · 冻结】（之后所有跑：只读，绝不加 -write）
  cp p_learn.txt p_run.txt          # 母本 = p_learn.txt（此后只读）
  run … --expert-profile p_run.txt  # 每跑前再 cp 一次（防误写；母本不动）
```
- **红臂**：阶段二里若某跑误加 `--expert-profile-write` ⇒ `p_run.txt` 被回写 ⇒ 下一跑起始集合变 ⇒ **判该跑不合格**（不是"结果变了"）。
- **★ 一条硬约束**：`--expert-swaps N>0`（默认 64）会在**运行中**改驻留（`follow()` 发布换入的槽）⇒ **想"集合 = profile 定的那一份、运行中不动"，必须 `--expert-swaps 0`**（`start_swaps()` 在 `opt_.expert_swaps == 0` 时直接 return，`:1092`）。

## Q4 ★ 能不能指定"手工常驻集合"？

**结论：没有直接口子 —— 只能通过"喂 profile 的计数"间接指定。**（A）

| 问 | 答 | `file:line` |
|---|---|---|
| 有"给一张常驻清单"的旗标吗？ | **没有**。全部与专家相关的 CLI 只有：`--expert-profile`（计数文件）· `--expert-profile-write` · `--expert-swaps` · `--stage-mib` · `--stage-ahead` · `--cpu-share` · `--tail-skip` · `--vram-reserve-mib` · `--no-gpu-experts` · `--layer-split` · `--any-node` | `main.cpp:733-793` · `:833-851` |
| `Options` 里有"清单/白名单"字段吗？ | **没有**（只有 `profile` / `profile_write` / `gpu_experts` / `expert_swaps` / `tail_skip` / `stage_*` / `cpu_share` / `vram_reserve_mib` / `layer_split`） | `engine.hpp:39-81` |
| `fill_expert_cache()` 的输入是什么？ | **只有** `prior_[i] + use_[i]` 与 `bytes`（`:1032-1033`）⇒ **唯一的"指定"通道 = 计数** | `:1032-1033` |

**⇒ "手工常驻集合"的可行编码（精确做法，含两个坑）**：
1. **原理**：排序键是 `used / bytes`，**同层同 `bytes`** ⇒ 给目标专家的计数设成**远大于其它**，它们就排在最前 ⇒ **在被取的那一段里**（取到 `room` 用尽为止，`:1063-1067`）。
2. **坑 A（只准这些 ≠ 只取这些）**：容量有余时，**低计数的专家照样会被取**（只是排在后面）⇒ 要"只有这份清单"，必须**把 `--vram-reserve-mib` 调到 arena 恰好装下这 N 个**（或用 `--no-gpu-experts` 走另一极端）。
3. **坑 B（运行中会被改）**：默认 `--expert-swaps 64` 会在解码中把"用得多的"换进来 ⇒ 手工集合被稀释 ⇒ **要它保持原样须 `--expert-swaps 0`**（`:1092`）。
4. **口径提醒**：`read_profile` **只保留 `n > 0` 的行**（`:186`），且 `out` 预先置 0（`:181`）⇒ **省略某行 = 计数 0**（不是"排除"）。
