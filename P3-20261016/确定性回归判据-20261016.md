# 确定性回归判据（race 修好后用它验收）— verifier

> ## ⚠️ ★★ 取证工具有效性横幅（verifier 独立复核后加 · 2026-10-16 · 保留原文，见总纲 §7）
> ### **取证工具自身必须同期**：
> 1. **读回（D2H）前必须先 `cudaStreamSynchronize` 那个流** —— 否则读回与内核**无序**；
> 2. **比较器的"正控"必须是「已知不同的输入」**，**不能是「扰动自己一个元素」** —— 后者只证明"比较器能看见差异"，**证明不了"数据真的不同"**。
>
> ### ⇒ 据此，**2026-10-16 的「内核内 race」归因降为【待判】**。
> 依据（**独立复核 = 成立**，详见 `P3-20261016/B3探针读回同期-复核-20261016.md`）：
> `STRATA_PROBE_REPEAT` 探针（`engine.cpp:1990-2005`）在两次读回 `:1993`/`:1997` 之前**都没有 `cudaStreamSynchronize(cs(st_))`**，
> 而 `st_` 是 `cudaStreamNonBlocking`（`:1416`）⇒ **两次 `cudaMemcpy`（走 legacy 默认流）与 `st_` 上排队的 mmvq 内核【无顺序保证】**
> ⇒ 探针的"同输入两次不同"**不能排除"读回竞争"**；
> 而引擎**自身惯例是先同步**（`:1827` "dump"、`:2855` "read"）⇒ 探针偏离了既有惯例。
> **（本判据件正文不变；本条只给"上游取证证据的效力"降级，不改变判据本身。）**

> ## ⚠️ ★★ 更正横幅（2026-10-16：**`--expert-swaps 0` 不能当"零成本确定性兜底"** · 保留下方原文）
> **旧口径（本件 §1③ 与 §3 的 `fb` 档用的）**：把 **`--expert-swaps 0`** 当**"确定性已有零成本兜底"**。

> ⇒ **它不是零成本，是在【decode】上砍掉一多半** ⇒ **旧口径【作废】**。
> ### ⇒ **真正的零成本确定性兜底 = 【冻结 profile】**（即本件 §7.1 的操作定义，也正是 §10 的修法）。
> ### ⇒ 本件改法与保留：
> - **§1③ 的比较基线**：**由 `--expert-swaps 0` 改为【冻结 profile 档】**；**判据的含义不变**（"**修了却更慢的确定性没有意义**"，且**不得靠关 swaps 换确定性**）。
> - **§3 的 `fb=`（swaps 0）档**：**保留可跑，但【改用途】 = "换入关闭"的机制读数臂**，**不再作兜底基线**（**实测依据**见 `配方组-判据` 修订 17.2/17.3）。

> **（依据：`配方组-判据-20261016.md` 修订 17.2/17.3。本横幅不改 §1/§3 的原文，只在其上追加更正。）**

> 用途：**race（长负载非确定性）修好之后**，用它**一次判定"修好了"**。

## §1 三条判据（**缺一不可**）
| # | 判据 | 为什么需要它 |
|---|---|---|
| **①** | **3 跑 `token ids` 逐位相同** | 直接测"同输入同输出"。按总纲口径 = 比**共同前缀**；**长度/停止点漂 = timing 依赖，不计违反**（这条是我们自己的裁定，写死在此，避免把 timing 漂当失败） |
| **②** | **`--top-probs` 逐位相同（浮点级）** | ★ **只比 id 会漏「末位漂但未翻 id」**：浮点已经变了、argmax 还没翻 —— 那是"还差点翻"的亚稳态，正是 race 的指纹 |
| **③** | **比兜底快**：本档 decode tok/s **> `--expert-swaps 0`** | ★ **确定性已有零成本兜底**（冻结驻留）⇒ **修了却更慢的"确定性"没有意义**。这一条防"用性能换确定性"冒充成功 |

> ★ **更正（2026-10-16，见件首横幅）**：**③ 的比较基线改为【冻结 profile 档】**（`--expert-swaps 0` **不再是兜底**：decode −2.6×）⇒ **要点不变**：**确定性不得靠"关 swaps / 强制冻结驻留"换来**。

**总判定**：三条全过 ⇒ **PASS**；任一不过 ⇒ **FAIL（列出未过项）**。

## §2 负控（**必须能变红**，否则判据是废的）
> **用【修好前的 exe】跑同一配置** ⇒ 判据**必须报红**。

**★ 注意形态**：负控是 **「旧 exe vs 修好后」跨档比**，**不是** "NEG 自己 3 跑互比"——
- 自己互比比的是"NEG 稳不稳"；负控要问的是"**判据能不能分辨旧 exe**"。
- **（这一处我实现时一开始写错了，是 mock 试验抓出来的：当时负控对旧 exe 报"没变"，看起来"判据失效"，其实是把比较对象搞错了。）**

**若负控没报红 ⇒ 判「判据失效 / 或旧 exe 其实也确定」⇒ 本轮结论作废。**

## §3 跑法（一条命令，三个档同跑；脚本已内建）
```
python perf_baseline.py --model <gguf> --tokens <长prompt, ≥700 token> \
  --max-new 8 --runs 3 --allow-batch-1024 \
  --presets "fix=--prompt-batch 8 --no-draft --lookup 0,\
fb=--prompt-batch 8 --no-draft --lookup 0 --expert-swaps 0" \
  --det-fix fix --det-fb fb \
  --neg-exe <修好前的 exe> \
  --out det_regression.md
```
- **`fix`** = 被测（修好后的 exe，默认 `--exe`）；**`fb`** = 兜底（`--expert-swaps 0`）；**`NEG`** = 由 `--neg-exe` **自动加档**（同配置、旧 exe）。
- ★ **更正（2026-10-16，见件首横幅）**：**`fb` 档不再作兜底基线**（`--expert-swaps 0` decode −2.6×）⇒ 改用途为**"换入关闭"的机制读数臂**；**③ 的基线档改为【冻结 profile】**（即与 `fix` 同配、只换 profile 母本的跑法）。
- ★★ **更正 2（2026-10-16 晚 · 与 `配方组-判据` 对齐）**：上面命令里的 **`--prompt-batch 8` 是【旧 canonical】**，**新 canonical = `--prompt-batch 1024 --stage-ahead 128`**。
  **理由（A）**：`rows_ = min(prompt_batch, max_context)`（`engine.cpp:1591`），而 **`Layer::mmq` 要求 `rows_ >= kStageRows(32)`**（`:1622`）⇒ **`--prompt-batch 8` 时 `batched()` 恒 false**（`:1877`）⇒ **批路径 + 预取重叠链【整条不存在】**。
  ⇒ **两套口径的读数【禁止混引】**；本件 §3 的命令**保留原文（作旧口径记录）**，**新跑一律用新 canonical**。
  ⇒ **同口径更正**：**主读数取 `prefill tok/s`**（`配方组-判据` 修订 7）· **噪声地板用 `s_round = 1.4826·MAD/median`、n≥5、弃预热**（修订 11；**`±29%` 那条地板【作废】**）。
- **不带 `--dump-layers`**（观测掩盖律 §1：带 dump 会把竞态掩盖 ⇒ 用它验确定性是错的）。
- `--top-probs N`（默认 5）由脚本自动附加 —— **判据② 靠它**。
- 输出：**三条判据表 + 总判定 + 负控行**，另附横向对比（**id 级 / 浮点级 双列**）。

## §7 ★ 确定性跑法的**操作定义** + 本跑法的**正控**（2026-10-16 补 · 保留原文）

### §7.1 操作定义（**跑确定性判据时必须这样做**）
> **每跑前，用同一份 `--expert-profile` 母本、覆盖/重置成该跑的输入；跑后【不写回】。**
> 实现二选一：**(a)** `--expert-profile` 指向一份**每跑重置**的副本（`cp 母本 → p_run.txt`）；
> **(b)** **不给 `--expert-profile`**（见 §9：默认路径根本不读写）。
> ★★ **补一句（2026-10-16 更正）：★ 不要用【关 swaps（`--expert-swaps 0`）】当兜底** —— 那是 **decode −2.6×** 的代价，**不是零成本**（见件首横幅 / `配方组-判据` 修订 17.3）。**零成本兜底只有一条 = 【冻结 profile】**。
**为什么必须这样**（机制已判成立，见 `驻留集合变是否改数值-判读-20261016.md`）：
- **起始驻留集合由 profile 的【计数】决定**（`engine.cpp:977` 注释：*by use per byte when there are counts, **the profile's** and this run's*）；
- **每跑改写 profile ⇒ 下一跑计数变 ⇒ 起始集合变**；
- 而**驻留集合变必然改数值**：① **两侧激活量化格式不同**（CPU=ggml `vec_dot_type`=**Q8_K**，`cpu_experts.cpp:174/187`；GPU=引擎 **Q8_1**，`engine.cpp:1889/1913`）；② **累加分组不同**（CPU 按 token 的专家次序逐项加，`cpu_experts.cpp:253-259`；GPU 按 kSlots 批量加 + `moe_add` 再加一次）。

### §7.2 本跑法的**正控**（已实测，构成"跑法有效"的证据）
| 臂 | 做法 | 实测（builder `pc_*.log`，exe `c144b8a8…`） | 判读 |
|---|---|---|---|
| **冻结（正控）** | 每跑前 `cp` 同一母本 ⇒ 同一输入 | **ids 3 跑相同** + **`--top-probs` 逐位相同** | ✅ **跑法有效**（冻结 ⇒ 逐位同） |
| **不冻结（负控）** | 不刷新 | **ids 相同，但 `--top-probs` 全不同**（`0.412098` vs `0.412439` …） | ✅ **判据能变红**（不冻结 ⇒ top-probs 漂） |
⇒ **两条合起来**：**该跑法是有效的**（冻结逐位同 / 不冻结必漂）—— **这正是"判据能变红"的兑现**；
⇒ 且它**顺带证明"只比 ids 不够"**（负控 D 的 ids 相同、**只有浮点级抓到**）⇒ **§1 判据② 的存在理由得到实证**。

## §8 ★ 「3 跑够不够」—— 独立判读：**不够，且不是"稍微不够"**

### §8.1 硬依据
把"某一跑输出与基准不同"看成**每次独立的 Bernoulli(q)**。N 跑全同 ⇒ 观测到 **0 次分歧**：
- **q 的 95% 上界（rule of three）≈ 3/N**：
  | N | 3/ N | 能说什么 |
  |---|---|---|
  | **3** | **3/3 = 100%** | ★ **等于什么都没说** —— **3 跑全同【不能】把 q 压到 100% 以下** |
  | 5 | 60% | 弱 |
  | **10** | **30%** | 工程可用 |
  | 20 | 15% | 较好 |
  | 30 | 10% | 好 |
- **反过来看检出能力（power = 1−(1−q)^N）**：
  | 真实 q | N=3 | N=10 | N=30 |
  |---|---|---|---|
  | **1/3**（≈ R0 的"2 同 1 异"） | **70%**（漏 30%） | 98% | ~100% |
  | 0.10 | **27%**（漏 73%） | 65% | 96% |
  | 0.05 | 14% | 40% | 79% |
⇒ **R0 的"2 同 1 异"完全可以用 q≈1/3 + N=3 解释**（70% 概率正好抓到 1 次）⇒ **3 跑既不能证真也不能证伪**。

### §8.2 建议口径（**工程口径，非统计保证**）
- **最低**：**N ≥ 10 跑全同**（q 上界 ≤30%；对 q=0.1 有 65% 检出）—— **并写明这是工程口径**；
- **若要与"不许动清单"同级的结论**：**N ≥ 30**（q ≤10%）；
- ★ **更重要**：**这条缺陷已有确定性解释（profile 耦合，已升因果）** ⇒
  **正解是"消除已知来源 + 用跑数覆盖剩余来源"，不是"靠加跑数证明没有随机"**。
  **跑数不能替代根因消除。**

### §8.3 ★ 红规则（写死）
> **N 跑全同才判过；任何一次不同 ⇒ 判据降级**（并把该跑**作为新反例入册**）。
> **结论的有效期 = 到下一次反例为止**（**不是**"永久确定"）。

### §8.4 与"±29% 噪声地板"的关系（★ 别混）
- **±29% 是【性能】口径**（tok/s 的散布地板）⇒ 用于**性能判据**（"3 次取中位"）；
- **确定性是二值的（逐位）** ⇒ **噪声地板不适用**，用上面的**计数口径**；
- 但"档内是否一致"仍按**总纲的「共同前缀」口径**（**长度/停止点漂 = timing 依赖，不算违反**）。

## §9 顺带（只读独立核）：**默认路径会不会读写 profile？**
**结论：不会。**（A，file:line）
- `save_profile()`（`engine.cpp:1695-1696`）：**首行就是 `if (opt_.profile.empty()) return;`** ⇒ **默认不写**；
- `read_profile` 的唯一调用（`engine.cpp:1488`）：**`if (!opt_.profile.empty()) read_profile(...)`** ⇒ **默认不读**；
- `Options::profile` 默认空串（`engine.hpp:44`），**只有 `--expert-profile` 才赋值**（`main.cpp:833`）。
⇒ **默认用法下起始驻留集合是固定的** ⇒ **该耦合只在用户显式给 `--expert-profile` 时出现**。
⇒ **因此这不是"默认用法下的正确性缺陷"**；**但**：`--expert-profile` 恰恰是**提速候选（H profile）的推荐用法**，且**我们自己的 canonical 跑法一直在用它**（`run_cg.cmd:22`）⇒
**"用了 `--expert-profile` 就可能同输入不同输出"是真实的正确性风险，应写进文档并上报**（级别：**非默认路径**）。

## §10 ★ 修法验收判据：`--expert-profile` **默认只读** + `--expert-profile-write` opt-in（2026-10-16 队长批的修法）

> **修法**（builder 执行）：**默认不写回** profile；要写回须显式给 `--expert-profile-write`。
> **验收 = 三条**（每条都能单独变红）：

| # | 判据 | 怎么算 | 变红条件 |
|---|---|---|---|
| **①** | **默认【不写】** | **不给** `--expert-profile-write` 跑一次 ⇒ **profile 文件的 md5 与跑前相同** | **md5 变了 ⇒ 判红**（"默认只读"没生效） |
| **②** | **旗标下【要写】** | **给** `--expert-profile-write` 跑一次 ⇒ **md5 与跑前不同** | **md5 没变 ⇒ 判红**（写功能被误删/失效） |
| **③** | **默认下【2 跑 top-probs 逐位同】** | 同一母本、默认（只读）跑 **2** 次 ⇒ **`--top-probs` 逐位相同（浮点级）** | **有分歧 ⇒ 判红**（泄漏未除） |

### ★★ ① 与 ② 是**互相制约**的一对（别只做一半）
- **只做①** ⇒ 有人可以"**把写功能整个删掉**"来通过 ⇒ **假绿**；
- **只做②** ⇒ 无法证明"默认不写" ⇒ 泄漏仍在；
- ⇒ **①②必须成对**：**①证明默认不写、②证明功能还在**。**这正是"正控必须是已知不同的输入"那条的又一落点。**

### 验收时另要核的两件事（便宜、易漏）
- **旗标名以实际 `--help` 为准**（本判据按队长给的 `--expert-profile-write` 写；**若实际名字不同，以 `--help` 为权威并留痕更正**）。
- **母本自身 md5 也不能变**（跑完核一次）—— 防"只读的是副本、母本被别的路径改了"。
- **exe sha / prompt sha** 照 §0 纪律写进 log 头。
