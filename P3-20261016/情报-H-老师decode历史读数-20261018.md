## §1 ★ 从 dec-pool2 的 verify 表反推（D 级，换算假设写死）

**输入（`E:\strata\_staging\dec-pool2.txt`，全部 A 日志）**：
- `:66` `position 6963, 171 tokens, 64 rounds`；`:67` `speculation 76 rounds of 6, drafts accepted 124 of 175 (0.709), **2.63 tokens per round**`。
- `:71` `verify window  **wait for rings 12.378**  **pool 7.269**  host 0.101  commit 0.037 ms/round; CPU experts 0.93 distinct / 1.14 routed per layer`。
- `:79` `decode **200 tokens in 1847.9 ms -> 108.23 tok/s**`；`:81` `per token 9.240 ms/token (WALL CLOCK)`。

**换算**：
1. **每 round 产出 token 数** = `(accepted 124 + 基础 1×76 rounds) / 76 rounds = (124+76)/76 = **2.63**`（与日志 `:67` 的 2.63 逐位对上 ⇒ 假设自证）。
2. **组件和** = 12.378 + 7.269 + 0.101 + 0.037 = **19.785 ms/round**。
3. **若这些组件就是整个 round** ⇒ `19.785 / 2.63 = 7.5228 ms/token` ⇒ **132.9 tok/s**（**D，上界**）。
4. **实际 round 墙** = 1847.9 / 76 = **24.314 ms/round** ⇒ `24.314 / 2.63 = 9.246 ms/token` ⇒ **108.2 tok/s**（与 `:79/:81` 的 108.23 一致 ✓）。
5. ⇒ **组件覆盖率 = 19.785 / 24.314 = 81.4%**；**残差 4.53 ms/round（18.6%）= GPU verify/内核与提交开销**（未在 `:71` 的四个字段里，别硬凑）。
6. **结论**：**反推值 132.9 只能当上界；采用值取直读 108.23**。若只有 `:71` 而没有 `:79`，公式为 `2.63 / (12.378+7.269+0.101+0.037) × 1000 ≈ 132.9 tok/s`（D）。

**1/2/3/4/6-token 窗口**：`:55` 写明 `window up to 6 tokens`；`:56-65` 逐窗口捕获（1/4/2/3/6 各一条）；`:68` 直方图 `T1:10 T2:10 T3:5 T4:50 T5:0 T6:1`；`:67` 76 rounds of 6。**这些是投机验证窗的组成，不直接给 tok/s**；唯一 decode 总量读数是 `:79` 的 108.23。

## §2 结论：量级与对比（B3/B0 为 lead 给定口径）

- **老师 3.8-Flash 在本机（4080S）的稳态 decode ≈ 105–125 tok/s**：
  - 最权威单条：**108.23**（200 tokens，dec-pool2，A）；
  - 全库 221 条同机日志：**中位 122.58**（300-token 组中位 123.11，200-token 组中位 108.23）；**最坏有效值 92.78、最好 141.80**；64-token 短跑 84.37；
  - 同机指纹社区报告：**91–122**（pool4 98.33；auto cache 102.1/122.3；262k ctx 91.3）。
- **对 B3 = 25.23 tok/s（256 口径、无损交付）**：`108.23/25.23 = **4.29×**`；`122.58/25.23 = **4.86×**`；区间 **4.3–4.9×**（最好 141.8 ⇒ 5.62×）。
- **对 B0 = 14.25 tok/s**：`108.23/14.25 = **7.59×**`；`122.58/14.25 = **8.60×**`；区间 **7.6–8.6×**（最好 141.8 ⇒ 9.95×）。
- **我们复跑原厂 0.1.43.1 的那条（q38_perf，45 tokens）= 61.91** ⇒ 对 B3 **2.45×**；但它投机只兑现 1.12 tokens/round（40 rounds of 2、accept 5/5），且 45-token 短跑含 ramp ⇒ **不能当"老师引擎在我们这的实现水平"，也不能当我们的目标**。
- **短跑 8-token 的 25.18 ≈ B3 25.23 是巧合，不可当"打平"**：8 tokens 被首 token/图捕获主导（同文件 spec 3 rounds、q38_4096 同口径掉到 4.12 即反例）。

## §3 口径警告（读这张表之前先读）

1. **老师的历史 decode 全部带投机**：dec-pool2 是 `--spec 6`（76 rounds of 6、2.63 tok/round）；社区 5090/4080S 是 `--spec 4 --spec-min-p 0.70`（draft accepted 115–155/256）。**我方 B3/B0 是 `--no-draft --lookup 0`** ⇒ 两者是"有投机 vs 无投机"的 decode，不可 1:1 当同口径。
2. **短 token 数（8/45/64）不可比**：首 token、CUDA graph 捕获（`verify: capturing the N-token window`）、专家换入 ramp 都在里面；**只有 200/300/1000-token 平均的读数能比**。
3. **跨卡不混**：5090 的 140–178 不能当 4080S 的数；本机 4080S 的 91–141 才是同卡参照。
4. **跨版本不混**：0.1.40.2（dec-pool2）与 0.1.43.1（q38）不同 exe；好在本机的 221 条聚合里两代都有，且中位一致（122–123）。
5. **显存悬崖**：同机指纹报告 `explicit 8900 → 13.7/14.7 tok/s`（0 MiB free）⇒ 任何"decode 掉了 7×"的读数先查是否踩了这个坑（`README:301-309`）。
