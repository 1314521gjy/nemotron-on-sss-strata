## §0 建议（一句话）

> **先做 A（只换执行流，不改依赖），它是 10 行级、可旗标关、数值必然不变；若 A 只回收一部分速率，再做 B（乒乓双缓冲，真重叠）。**
> ★ **关键前提**：`stage_` 目前是**单缓冲**（`engine.cpp:1673` + 每轮覆盖），所以"换流"**不会**让第 r+1 轮的拷贝早于第 r 轮的 kernel —— **A 只赌"同一条流里 kernel/拷贝交替"是 9 GB/s 的成因**；trace 的天然正控（同尺寸两流差 2.2×）支持这个赌，但**尚未证明因果**。

## §2 为什么"只换流"不一定够（必须先想清楚）

`stage_` 是单缓冲 ⇒ **第 r+1 轮的拷贝在物理上不能早于第 r 轮 kernel 完成**（否则会覆盖它们正在读的数据）。所以：

- **A** 把拷贝放到 `cp_`，依赖不变（`cp_` 等 `st_` 的"上一轮 kernel 完成"事件；`st_` 等 `cp_` 的"本轮拷贝完成"事件）⇒ **拷贝与 kernel 仍然串行**，但**拷贝不再与 kernel 在同一条流的队列里交替**。
  - 收益来源假设：9 GB/s 是"同流交替（小 kernel→大拷贝→小 kernel）"造成的（trace 里同尺寸在 `up_` 上是 22.1）。**A 直接检验这个假设**。
  - 若 A 后仍是 ~9 GB/s ⇒ 假设错，**必须做 B**。
- **B** 乒乓双缓冲 ⇒ 第 r+1 轮的拷贝可以**与第 r 轮的 kernel 真重叠**（不同半区）。

## §3 方案 A：轮内拷贝走 `cp_`（最小改动）

### 3.1 新对象（`engine.hpp` 成员，`alloc()` 里建）
- `void* cp_`：**新建** `cudaStreamCreateWithFlags(..., cudaStreamNonBlocking)`（**不复用 `up_`**：`up_` 每层只用一次、有自己的 `ev_ahead_` 语义，混用会把 17 轮拷贝串到早拷贝后面，且让 red line ① 的"早拷贝独占一条流"失效）。
- `void* ev_krn_`：`cudaEventCreateWithFlags(cudaEventDisableTiming)`，**记在 `st_`**。
- `void* ev_copy_`：同上，**记在 `cp_`**。
- 旗标：`STRATA_MOE_ROWS_CP_STREAM`（默认 **0=旧行为**，便于负控；A/B 通过后再谈默认 1）。

### 3.2 逐轮事件契约（**这是全方案的核心**）

| 事件 | 记在哪 | 谁等它 | 为什么 |
|---|---|---|---|
| `ev_krn_` | `st_`，**每轮 kernel 全部入队之后**（第二轮 `mul` + 该轮 `relu/quantize` 之后） | `cp_` 的下一轮拷贝：`cudaStreamWaitEvent(cp_, ev_krn_)` | 保证不覆盖上一轮 kernel 正在读的 `stage_` |
| `ev_copy_` | `cp_`，**本轮两次 `cudaMemcpyAsync` 之后** | `st_` 的本轮 kernel：`cudaStreamWaitEvent(st_, ev_copy_)` | 保证 kernel 读到完整数据 |
| `ev_stage_[turn]` | `cp_`（`stage()` 内部已有，改传 `cp_` 即自动） | CPU（填 pinned 前） | 仍然表示"这块 pinned 的上一次拷贝已完成" |
| `ev_free_` | `st_`（`card()` 末尾，**不动**） | 下一次 `up_` 的早拷贝（**不动**） | kernel 都跑完 ⇒ 所有拷贝（被 `st_` 等过）也必然完成 |

### 3.3 伪代码（只列变化）

```cpp
for (int turn = 0; turn < n_round; ++turn) {
    const int r = ...;                      // 现有轮序（kept/early 逻辑不动）
    bool copied = false;
    if (r == kept) {
        // 缓冲里有：不拷
    } else if (r == 0 && early) {
        cudaStreamWaitEvent(st_, ev_ahead_, 0);        // 现有，不动
    } else if (rows > 0) {
        cudaStreamWaitEvent(cp_, ev_krn_, 0);          // ★ 新增：等上一轮 kernel
        stage(L, group_.data() + g0, m, cp_, n_cpu > 0); // ★ st_ → cp_
        cudaEventRecord(ev_copy_, cp_);                // ★ 新增
        copied = true;
    }
    if (rows == 0) continue;
    if (copied) cudaStreamWaitEvent(st_, ev_copy_, 0); // ★ 新增（只在真的拷过时等）
    ... 两处 mmq_->mul / relu / quantize（不动）...
    cudaEventRecord(ev_krn_, st_);                     // ★ 新增：本轮 kernel 全部入队后
}
```

**注意**：`stage()` 内部的 `cudaEventRecord(left, cs(stream))` 会跟着变成 `cp_`（因为传的是 `cp_`）—— 这正是我们要的（`ev_stage_` 表示"该 pinned 块的最后一次拷贝"）。

### 3.4 `stage()` 之外的调用点
- 早拷贝 `stage(..., up_)`：**不动**（red line ①）。
- `spare`/`n_cpu>0` 路径：`stage(..., cp_, alone=true)`，`alone` 线程池选择不变。
- `ev_free_` 的 record/ wait：**不动**。

## §4 方案 B：乒乓双缓冲（真重叠，A 无效时上）

- `stage_` 划成两半：`half = stage_bytes_/2`；第 r 轮用 `stage_ + (r&1)*half`。
- `per_round = (stage_bytes_/2)/(gu2+d_bytes)` ⇒ **轮数翻倍**（本靶 17 → ~34 轮/层）；`plan_ahead` 的 cap（`:1249` 的 `stage_bytes_/(2*gu_bytes+d_bytes)`）也要按半区算 ⇒ **`n_ahead` 减半**。
- 依赖：`cp_` 的第 r 轮拷贝只需等 **第 r-2 轮**的 kernel（同一半区），**不与第 r-1 轮冲突** ⇒ 真重叠。
- 代价：launch 数 ×2（每轮两个 `mul`），而当前 kernel 总时长只有 470 ms ⇒ 可接受；但**每轮变大变小会改 MMQ 的 tile 宽度**（`most` 不变，`m` 变）⇒ **数值可能与 A 有末位差**（不是错误，需用 `--top-probs` 判）。
- 改动面：`stage()` 加 `uint8_t* base` 参数（或用 `stage_ + (r&1)*half` 传进去）+ 分配/分轮各几行 ⇒ **~20 行**。

## §7 风险表

| 风险 | 后果 | 防法 |
|---|---|---|
| **`ev_krn_` 记早了**（在本轮 kernel 之前/中途记） | 下一轮拷贝覆盖 `stage_` ⇒ **静默错值**（不崩） | 只在**本轮最后一处读 `stage_` 的 `mul`** 之后记；A 用"轮体末尾"最稳 |
| **`ev_copy_` 记早了**（在两次 `cudaMemcpyAsync` 只记了一次之后） | kernel 读到半份数据 ⇒ 错值 | 记在 `stage()` 返回之后（两次拷贝都已入队） |
| **没拷也等 `ev_copy_`** | 等到**上一次**的旧记录 ⇒ 顺序错乱/不必要 stall | 用 `copied` 布尔门控（伪代码已写） |
| **事件复用** | 同一事件每轮重记：`cudaStreamWaitEvent` 只捕获**调用时**的最新记录 ⇒ 必须"先 record、后 wait"，顺序不能反 | 按 §3.2 的次序（record at end of round r；wait at start of round r+1） |
| **CUDA graph** | `cp_` 若在 capture 里被用 ⇒ `cudaStreamBeginCapture` 会失败/跨流非法 | `moe_rows` 不进 graph（`whole` 只在 `n<32`，见 `:2691/2707`）⇒ 天然安全；代码留注释即可 |
| **"拷贝跑太快饿死 kernel"** | 不会：拷贝不占 SM；只占 PCIe 与显存写带宽（22 GB/s vs ~700 GB/s） | —— |
| **B 的半区导致 `most`/tile 变化** | 末位数值差 | 用 `--top-probs` 判，**ids 必须逐位同** |
| **`--pcie-frac` 之类限速** | 不存在（grep 0 命中） | —— |

## §8 验收判据（三件，缺一不可）

1. **速率**：nsys 同一 profile 口径下，`cp_` 上的 H2D 速率 **≈22 GB/s**（A）、或 **H2D 墙钟被 kernel 覆盖**（B）；总 prefill **必须变快**。
2. **数值**：`pb=32` 与 `pb=8` 的 **45 个 ids 逐位不变**（搬运的先后不改变任何算术）；`--top-probs` 在 A 下应**逐位同**（B 可能末位漂移，需单列）。
3. **负控**：`STRATA_MOE_ROWS_CP_STREAM=0` ⇒ 计时回到旧值、ids 仍逐位同（证明开关真的旁路，而不是"改了也没差"）。

## §9 未验 / 边界

1. **【未验】** "同流交替导致 9 GB/s"这个因果 —— **A 就是它的判决实验**；builder 的 B1–B4 小基准可先给方向（见 `回执\H2D带宽-读码与剖面-20261017.md` §3）。
2. **【未核】** `cp_` 与 `up_` 是否被驱动放到不同的 copy engine 上（若只有一条引擎，A 的收益可能只是"队列形态"）。
3. **【未核】** B 的轮数翻倍对 `most`/launch 数的影响量级（**未跑**）。
4. 本件**只出方案：未改码、零 GPU、未碰 `E:\strata`**。
