# 方案（只方案、未改码）· prompt 缓冲借专家缓存槽（borrow）移植 — 2026-10-17

- **授权**：队长「只移植 borrow，其余不移植」。
- **上游语义**（`PolyStrata\docs\DETAILS.md:166-167`）：*"the prompt path borrows room in the GPU's expert cache for its buffers and puts those experts back after the prompt"*；`:332-334`：`--prefill auto` 取"缓冲能放进所借槽"的最大块（≤8192），**只借 prompt 需要的量**。
- **本机实测标尺**：3.8 @ 6792、`dec-pool2` 配置 = **2805.87 tok/s**（`prompt path borrows 1903 cache slots (3.62 GiB)`、resident 10109）；我们单 chunk = 290.0（resident 3640）、pb1024 = 383.6（resident 6892）。

---

## ★ 0. 先报一条"诚实前提"（不写清会白改）
- **"借"本身不减少占用**：借出的槽在 prompt 期**仍然不能放专家** ⇒ **驻留照样少"借出的字节数"**。
- **3.8 的借出量只有 3.62 GiB、我们的是 ~10.8 GiB**（2.4–3×）。
- ⇒ **只移植 borrow、【不缩 scratch】，驻留仍会从 6892 掉到 ≈3640，单 chunk 大概率仍然负。**
- ⇒ **本方案把"缩 scratch"列为 borrow 的【必要伴随项】**（见 §6），否则这一刀没有兑现路径。**若你坚持"只动 borrow"，我照做，但验收第 1 条（驻留不掉）预期不达标。**

## 1. 我们自己代码里的落点（A 级 `file:line`）
- **scratch 在 `shared_scratch()`（`engine.cpp:1561`）注册、`alloc()`（`:1591`）里两次 pass 后落地**：
  - `gu_ = fbuf(rr*2*n_ff_exp_)`（`:1584`）· `hx_ = fbuf(rr*n_ff_exp_)`（`:1585`）· `dx_ = fbuf(rr*n_embd_)`（`:1586`），`rr = rows_*n_used_`
  - `scratch_ = dmalloc(scratch_at_*4)`（`:1641`，`cudaMalloc` 单独）· `mq_/mq2_/mqx_`（`:1661-1663`）
- **arena 在 `fill_expert_cache()`（`:995`）**：`arena = min({all, free_b - reserve, most})`（`:1044`），`exp_` = `vmm_map` 的基址（`:1054-1059`）；`L.slot[e]` 指向其中。
- **顺序问题**：`fill_expert_cache()` 在 `scratch_`/`mq_` 之后（`:1141/:1498` 的调用都晚于 `alloc()` 的 `:1641`）⇒ **scratch 占多少，arena 就少多少（1:1）** —— 这就是现在单 chunk 驻留腰斩的机制（实测 21.3→10.5 GiB）。
- **另有 `mmq_` 的 `d_ids_/d_wts_/iota_/tab_`（`:1664-1668`）也是 ∝ rr**，同样在借的候选里。

## 2. 借哪些槽
- **从 arena 顶端借**（物理连续，最省实现）：`fill_expert_cache()` 里把 `arena` 的末尾 `borrow_bytes` 划为"借区"，**专家填充只用 `arena - borrow_bytes`**。
- 或**按 profile 最低优先级借**（`E:\strata` 的上游做法，profile 有排名）：本靶 profile 在 `C:\sp3\expert-profile.bin`（24576 ranked pairs）；**按排名最末的槽借**，语义更贴上游，但实现更复杂。
- **推荐先"顶端借"**：实现简单、等价性最好证；profile 优先级留第二版。
- **借出量** = prompt 期才需要的 scratch 合计（按 `rows_` 算；`--prefill auto` 未移植前由 `--prompt-batch` 决定）。

## 3. ★ 冲突保证（绝不能静默重叠）
1. **借出的槽【不放进专家填充序列】**：`fill_expert_cache()` 的 `chan_`/`L.slot` 候选集只覆盖 `[0, arena - borrow_bytes)`；**借区不出现在任何 `L.slot[e]` 里**。
2. **take 序列一致**：借区首地址与长度记在 `arena_` 的元数据里；**每次 `moe_rows`/`stage()` 用之前校验**"借区与专家区不交叠 + 借区仍在 arena 内" ⇒ **不满足就 `std::runtime_error("prompt buffers do not fit the expert cache")`**（**响亮、绝不静默叠放**；§5 静默退化禁令）。
3. **归还后的专家必须可验证**：还回时按 `L.slot` 重填；**decode 首 token 前做一次 `cudaStreamSynchronize(st_)`**（或事件）确保归还落地；**不靠 sleep**。

## 4. 归还时机与谁等谁
- **归还 = prompt 的最后一个 chunk 之后、decode 之前**（`n < kStageRows` 的第一个调用之前，或 `prefill` 循环结束时）。
- **谁等谁**：**归还的拷贝在 `st_`（或一个专用 `up_`）上；归还完成事件 `ev_borrow_done_`；decode 第一次读专家前 `cudaStreamWaitEvent(st_, ev_borrow_done_)`**。
- **★ 不碰 §7**（见 §5）：归还**不走** `stage_`↔`ev_free_/ev_ahead_` 那套，**另起一个"归还"事件/路径**，避免搅动 per-layer 流水。

## 5. ★★ §7 四条红线（逐条；当前行号 = 我改动后的实测行号）

## 6. ★ 缩 scratch（borrow 的必要伴随项；建议同批或紧接）
| 项 | 现在 | 改法 | 省 |
|---|---|---|---|
| `dx_`（`:1586`） | `rr * n_embd_`（2.49 GB @pb6912） | **`rr * out_w`（latent 的 1024）** | **~1.87 GB** |
| `gu_`/`hx_`（`:1584-1585`） | `rr * (2*n_ff_exp_)` / `rr * n_ff_exp_` | **按 `kSumRows` 分块算专家**（别一次开 `rr` 行） | ~4.5 GB → ~0.6 GB |
| `mq_/mq2_`（`:1661-1662`） | `q8_bytes(rr, …)` | 同上分块 | ~2 GB |
- **⇒ scratch 10.8 GB → ~2–3 GB**（接近 3.8 的 3.62 GiB）⇒ **借出量降到 3 GB 级 ⇒ 驻留 ~6892→~6200–6500（而不是 3640）**。
- **数值影响**：分块只改"每块算多少行"，**算术顺序不变 ⇒ ids 应逐位同**（与 `sm` 改法同类）。
- **⚠️ 这是"第二个变量"**：若你要求严格一次一变量，**先只做 borrow（预期驻留仍掉、单 chunk 仍负），再单独做缩 scratch**。**我建议合并**，否则 borrow 单做看不到收益。

## 7. 旗标与默认
- **`STRATA_PROMPT_BORROW`（默认 `0` = 旧行为；`1` = 借）**。**负控 = 不设或设 0**。
- 缩 scratch 若要单独开关：`STRATA_PROMPT_SCRATCH_TILE`（默认 0）。

## 8. 改动面与风险
- **borrow 主体**：`alloc()`（借区预留）· `fill_expert_cache()`（排除借区 + 校验）· `moe_rows`/`fill_expert_cache` 的归还点 · 一个归还事件。**≈60–100 行**。
- **缩 scratch**：`shared_scratch()`/`alloc()` 的尺寸 + `moe_rows` 的分块循环。**≈40–80 行**。
- **风险表**：
  1. **静默重叠**（专家覆盖借区）⇒ §3 的"take 序列 + 响亮失败"。
  2. **归还后专家坏**（拷贝没完成 decode 就读）⇒ §4 的事件等待 + 验收第 5 条。
  3. **借出量 > arena**（大 pb + 小 arena）⇒ 响亮 `do not fit`，**不静默退化**。
  4. **碰 §7**（若归还借道预取流水）⇒ 默认不碰；碰了整组改 + 重跑确定性。
  5. **数值**：borrow 只改布局 ⇒ **应逐位同**；缩 scratch 的 tile 也应逐位同（同一算术顺序）。

## 9. 验收预案（实施后照跑）
1. **驻留**：单 chunk（pb=6912）下 `N of 20480` 应 ≈ **6892**（未借档），**不是 3640**。
2. **★ prefill**：6792 token 单 chunk 应 **明显快于 383.6**（目标往 3.8 的 2806 靠）。
3. **★ ids 逐位不变** + `--top-probs` 逐位同（同 prompt 的 pb=1024 参照 `10041,1278,4206,1636,9956,1317,6347,1261`）。
4. **负控**：`STRATA_PROMPT_BORROW=0` ⇒ 回 290 / 383.6 旧行为。
5. **静默退化**：查 `N of 20480`；**借-还之后再跑一次 decode 正常**（防还回去的专家是坏的）。
