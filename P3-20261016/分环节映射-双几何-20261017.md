## §2 双几何并排（**D3 的判读底稿**）

### 2.1 Qwen3.8-Flash-Next（原厂 `strata` 的设计点；**C，设计件 §2 `:175-185` 逐字**）
> 「Parameters ~176B: 125B main, 51B n-gram table, ~4B MTP. **~6B active per token.**」「Layers **48: 36 GDN and 12 QSA**. Layers 3,7,…,47 are attention; PLE sits in GDN layer 1.」「Hidden width **H = 2560**」「Hyper-connection residual **4 streams (10,240 wide)**. Two HC mixers per layer, each with rank 320.」「QSA **24 Q heads, 2 KV heads, head dimension 256**.」「MoE **512 routed experts, top-10, width 640**, plus a **gated** shared expert of width 640」「PLE one injection before block 1: **16 rows of 160 values per token**, from a 320,001,536-row table」「Vocabulary **248,320**」

### 2.2 Nemotron-3.5-Super-VL-120B-A12B（本靶；**A，我们实测过的 GGUF/代码**）
> 88 层 = **40 mamba + 8 attn + 40 MoE**；**H = 4096**；MoE **512 路由专家 / top-22 / latent 1024 / 非门控 relu2** + shared（5376 宽）；每专家 **3,096,576 B（2.95 MiB）**；vocab **131,072**；MTP **1** 块。

### 2.3 ★ 并排（**只列"决定性能"的量**）
| 量 | **Nemotron（本靶）** | **Qwen3.8-Flash-Next** | 差 |
|---|---|---|---|
| 层数 / 层型 | **88 = 40 mamba + 8 attn + 40 MoE** | **48 = 36 GDN + 12 QSA**（**无独立 MoE 层**；MoE 与 GDN/QSA 同层） | ★ **结构不同族** |
| hidden | **4096** | **2560**（+ **4 条 HC 流 = 10,240 宽**） | ★ **残差结构不同族** |
| 路由专家 | **512 / top-22** | **512 / top-10** | **激活数 2.2×** |
| 专家宽 | **latent 1024**（up+down）· **非门控 relu2** | **640**（gate+up+down）· **门控 SwiGLU** | ★ **非门控 vs 门控** |
| 每专家字节 | **3,096,576 B** | **2,764,800 B** | 1.12× |
| **★ 每 token 专家触碰字节** | **40 × 22 × 2.95 MiB ≈ 2.53 GB** | **48 × 10 × 2.64 MiB ≈ 1.24 GB** | ★★ **≈2.05×** |
| 全部专家 | 20,480 对 ⇒ **59.06 GiB** | 48×512 + MTP 512 ⇒ **67.9 + 2.5 GB** | 同量级 |
| **KV / token** | **8 KiB**（8 attn 层, 2 KV 头, D128, f16） | **14.6 KB**（int8；13 attn 层, 2 KV 头, **D256**） | 1.8× |
| 递归状态 | Mamba state **165 MiB** | **GDN state 113 MB**（FP32） | 1.5× |
| 额外常驻 | —— | ★ **n-gram/PLE 表 51.2 GB（必须放 NVMe）** | ★ **Qwen 独有** |
| 每 token 激活参数 | ~12B（A12B） | **~6B** | **2×** |

### 2.4 ★★ 三条**机制必然**的推论（可直接给 D3 用）
1. **★★ 每 token 的专家字节：我们 ≈2.53 GB vs 它 ≈1.24 GB（2.05×）** ⇒ **同引擎同卡下，我们的 prefill 必然更受"搬运/DRAM/PCIe"限制** ⇒ ★ **这解释了为什么"重叠/预取"对我们的净贡献高达 9.26×**（`KP-UNI-0250`）—— **它不是巧合，是几何决定的**。
2. **★ 我们多一倍层（88 vs 48）且每层一个模块** ⇒ **层边界/发射次数 ≈1.8×** ⇒ **"发射固定开销"这类杠杆（CUDA graph / 图合并）对我们也更值钱**。
3. **★ 它多一整套 PLE（51.2 GB on NVMe，每 token 16×160 值）** ⇒ **它的 prefill 有一块我们完全没有的成本**（PLE gather/IO）；**反过来我们没有任何"表"要读** ⇒ **⇒ 在 C3 的份额表里，"I/O 段"这一项两边不可直接比**（我们应≈0）。

## §3 判"机制必然" vs "实现可改"（**给 C3/D3 的初步分栏**）
| 环节 | 预期差的性质 | 依据 |
|---|---|---|
| **6 专家装载/换入** | ★ **机制必然（我们的字节量 2×）**；但**"同样字节下谁搬得更快"= 实现可比** | §2.3 每 token 专家字节 |
| **7 up+激活+down** | **部分可比**：**非门控 relu2 vs 门控 SwiGLU** ⇒ 算术量不同族；但**MMQ/A4 GEMM 的"每字节效率"可比** | §1 #7 |
| **9 跨流等待** | ★ **实现可比**（同为"预取藏进计算"）⇒ **差 = 我们的工程缺陷或几何劣势** | §1 #6/#9 |
| **2 mamba/GDN** | **不同族**（Mamba-2 vs Gated Delta Net）⇒ **只能比"每 token 时间"，不能比"每算子效率"** | §2.3 |
| **3 attention** | **不同族**（8 层 f16 KV 2:1 GQA D128 vs 12 层 int8 2:1 GQA **D256** + indexer） | §2.3 |
| **11 输出/采样** | ★ **实现可比**（都只有一个输出头）——但**头的大小不同**（他们 417 MiB Q5_K） | `PREFILL_HEAD_ALIAS.md:3` |
| **（Qwen 独有）PLE / n-gram** | **不存在于我们侧** ⇒ **份额表里要给它们单列，且注明"我们侧为 0"** | §2.4-3 |
