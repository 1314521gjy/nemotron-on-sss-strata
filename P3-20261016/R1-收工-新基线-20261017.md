## 4. 根因（一句话，带 file:line）
conversation-cache 的 checkpoint 每 2048 token 把 prompt 的 `read()` 切成 **4 个 call**（`conversations.hpp:31` → `main.cpp:376-389` → `engine.cpp:3139-3147`，多 call 路径 `:3160` / `:3242-3288`）；每层 `moe_rows()` 跑 4 次、**每个 call 把 ≤341 专家的 `L.ahead` 整表重搬**（cap `:1314`、无条件并入 `group_` `:2450`、早拷 `:2380-2389`）⇒ **68% 的 DMA 字节是纯重复**。
老师（3.8-Flash）= **零重复**：resident 10,109 + streamed 14,467 = **24,576 = 其唯一专家数**。

## 5. 已否掉的（别再试，都带机制）
- **CP_STREAM 第二流、单 buffer = 零效果**（−0.46%，两版 exe、12 跑一致）：只有一张 `stage_`（`engine.cpp:1768`），`up_` 等 `ev_free_`（`:2407`）、`st_` 等 `ev_ahead_`（`:2737`）⇒ 93–95% 字节本来就在 `up_` 上，第二流没有可重叠对象。**要重叠必须 N≥2 槽 + 整组改那四处配对。**
- **`--stage-ahead` / `--stage-mib` 单 call 下已到平台**：64 / 256 / 4096 全在基线区间内。代码原因：`--stage-ahead` 只是门槛（`:2347`，6791 ≥ 所有扫值 ⇒ ahead 恒开），ahead **量**由 `plan_ahead` cap `:1317` = 341 定；`--stage-mib` 被 512 专家封顶（`:1769`：min(stage_mib, 512×3,096,576 B = 1512 MiB) ⇒ 2048 ≡ 4096）。
- **A 项（mq_ + dx_ 回收）降级**：字面上限只 **+404 槽**，到 6,900 需 +1,010 槽；且"按 `rows_` 缩放的 token 缓冲分块"语义不成立（装的是整段激活，缩它只能降 pb）。
- **借槽（borrow）不在 prefill 最短路上**：6912-token 时每层 512 专家全被路由 ⇒ 借槽不造显存、arena 无 spare ⇒ prefill 收益 ≈0，只动 decode。

### 8.5.1 墙的归因（2026-10-18 00:40，nsys 对账后**修正版**）
**真 prefill 窗口 3.631 s** = **compute 2.941 s（77.5%）+ 层边界气泡 0.400 s（40 个 × 7.2–12.2 ms，恰好一 mamba 层一个）+ 未藏副本 0.289 s**。

- **真实 DMA：45.23 GB / 1.952 s = 23.2 GB/s**（≈ PCIe Gen4 x16 实用上限），**与 compute 重叠 85.2%**，未藏仅 0.289 s ⇒ **DMA 已经不是瓶颈**（起点时 DMA 占 91%，现在反过来）。
- ⚠️ **撤销**："H2D 74.50 GB vs 引擎自印 45.10 GB = 1.54× 隐藏重复"是**假绿（窗口伪影）**：74.50 − 45.23 = 29.27 GB **全在 prefill 窗口外**（load 填充 17.65 + load 权重上传 4.89 + decode swap 6.73）；prefill 窗口内 45.23 GB 与引擎自印 45.10 GB 差 **0.3%**。⇒ **重复不存在，不做"去重修复"。**
- ⚠️ **撤销**：R10 报的"nsys 让墙 +21.3%"作废；真窗口 3.631 s vs 无 nsys 3.825 s，差在单跑噪声内（±5%）。
- **compute 2.941 s ≈ 55 TFLOPS 有效算力**（163 TFLOP / 2.94 s）⇒ 接近 4080 SUPER 稠密 fp16 峰值 ⇒ **compute 已接近打满，别指望这里大砍**。
  ⚠️ **更正（2026-10-18 01:00，情报D）**：**这条口径是错的**。4080 SUPER 厂商规格 = 稠密 FP16 ≈ **165 TFLOPS**、INT8 ≈ 330 TOPS（本机未测，C 级）⇒ 55 只到 **1/6 ~ 1/3** ⇒ **不能用它关闭 compute 优化**。
  上游有一条我们没走的 compute 路径：**FP16/BF16 prompt 计算**（`src/prefill/gemm.hpp:1-8` + DQ=2 反量化 ring `prefill.cpp:315/1307`；`QUANTS.md:37`：Q4_K 在 CUDA 上 prompt 默认走 FP16），而我们 `engine.cpp:2031-2033` 走 **int8 MMQ** ⇒ **这是 compute 侧唯一真候选**（要移植 + 编译 + 数值门）。
  另：`PF_FUSED` 对 Q4_K_M / sm_89 **不适用**（`QUANTS.md:37-38`：K-quant fused 仅 gfx11；3.8 靶实测仅 +5%）；`mmq_kq` **不用抄**（`src/poly/mmq.cu:1-2` 用的就是同一批 llama.cpp MMQ K-quant 内核）。
- **prefill 剩下的现实上限**：去掉 0.400 s 气泡 + 0.289 s 未藏 ⇒ **约 2.94 s ≈ 2310 tok/s**（现在是 1775.7）。
