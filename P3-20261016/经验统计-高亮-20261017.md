## ★★★ 三、根因（A 级，三方互证：代码 diff + 几何 + 字节账）
> **`moe_rows()` 从没接 MoE 的 latent 几何。**
- 靶：`embedding_length=4096`、`moe_latent_size=1024` ⇒ `L.exp_in = L.exp_out = 1024`（`nemotronhmoe.cpp:174-177` / `engine.cpp:735-740`）
- `moe()`（n<32，正常）用 `in_w/out_w` + `latent_down` 投影 + 写 `moe_out_`
- `moe_rows()`（n≥32，坏）**全用 `n_embd_=4096`**：量化 `:2378` · cached up `:2419` · cached down `:2428` · staged up/down `:2456/2461` · cpu `:2479` · `moe_sum→fo_` `:2492`；门 `:1623` 也按 `n_embd_`
- ⇒ up 按 4096 列读 1024 宽矩阵 ⇒ 每专家读 4×、跨 slot ⇒ arena 尾专家越界读 `0xFF` ⇒ **NaN**
- **修复**：11 处对齐 `moe()`（开关 `STRATA_MOE_ROWS_LATENT`，默认开）
- **★ 这是第一天就记下的移植债**（"`moe_rows()/stage()/moe_card()` 硬编码 `n_embd_`"）—— **pb≤8 时进不了 `moe_rows()` 所以从不发作；t13 解锁时只验"14-token 跑通"，没验"算对"**

## ★★★★★★★ 六b、正确路径 prefill 的时间账（A 级，nsys `ln_correct`，窗口 5158.3 ms）
| 项 | 量 | 占比 |
|---|---|---|
| **H2D memcpy** | **1511 次 · 3831.6 ms · 34.87 GB ⇒ 9.10 GB/s** | **74.3%** |
| GPU kernel（全部） | 17231 次 · 470.8 ms | 9.1% |
| GPU 空闲/等（缺口） | 873.9 ms | 16.9% |
| D2H / memset | 3.0 / 1.1 ms | ~0 |

- **★ GPU 只有 9% 忙** ⇒ **继续优化 GPU kernel 的天花板 = 9%**（`mul_mat_q` 占 kernel 的 58%，就算全免也只省 prefill 的 5.7%）。
- **★ 真瓶颈 = H2D**，且 **9.10 GB/s 只到 PCIe 4.0 x16 实用带宽（≈25）的 ~1/3**。**若到 25 ⇒ 拷贝 3.83 s → ~1.4 s ⇒ prefill ~5.16 → ~2.7 s ≈ 2.7×**。
- **候选三因（待判，别混）**：① 源是 **pageable** 而非 pinned ② **每次拷贝间有同步/事件等待** ③ **单流串行**。
- **★ 实测排除**：**`h_stage_` 本来就是 pinned**（`engine.cpp:1673` `cudaMallocHost`）⇒ ①**否**；`--pcie-frac` 我们引擎**没有**这个旗标。
- **★ 硬件上限实测（`C:\sp3\pcibench.exe`，24.1 MB × 200 次）**：**pinned 23.50–23.87 GB/s** · pageable 11.36–11.81 ⇒ **25 是理论、23.5 是本机实际**。
- **⇒ 9.10 甚至低于 pageable 的 11.4 ⇒ 瓶颈在 `stage()` 循环本身，不在硬件、不在 pinning。**
- **★ host gather 实测（`gatherbench.exe`，读同一份模型 shard）**：**冷 4.98 / 热 5.66 GB/s**（只差 14%）⇒ **页缓存几乎没兜住**（若是内存速应 20–50）。
- **`stage()` 的源 = 模型文件的 mmap 页**（`home(t).data(t)`，`engine.cpp:763/771/777/789`、`:904-906`）⇒ **命中页缓存=内存速；未命中=读盘**。
- **★ 待判（一条实验）**：先顺序读满两个 shard 再跑 ⇒ H2D 若上去 ⇒ 缓存被挤（可修）；若不动 ⇒ SSD ~5.7 限死（**重叠救不了，只能降体积或常驻 RAM**）。

- **decode 份额**：`native_q4_k_mmvq` 38.6% · `native_mmvq_slots` 23.8% · `mamba2_scan` 12.1%（decode 是 MMVQ 主导）。
