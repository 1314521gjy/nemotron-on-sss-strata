## §1 根因（一句话 + 证据链）

> **`moe_rows()` 从没接 MoE 的 latent 几何**：本靶 `embedding_length=4096`、`moe_latent_size=1024`，但 `moe_rows()` 把**专家输入/输出宽度**一律写成 `n_embd_=4096`（`exp_in/exp_out/latent_*` 在该函数里出现 0 次），且输入未做 `latent_down` 投影、结果未落 `moe_out_` ⇒ 每个专家的 up 被按 4096 列读（实际 1024）、down 被按 4096 行算 ⇒ **每专家读 4× 字节、跨过相邻 slot**，arena 尾专家读过界（0xFF → NaN）。

**A 级证据链**（详件 `回执\moe-vs-moe_rows宽度diff-20261017.md`）：
1. GGUF 头：`embedding_length=4096` · `moe_latent_size=1024` · `expert_feed_forward_length=2688` · 512 专家 / top-22。
2. 加载器：`nemotronhmoe.cpp:174-177` ⇒ `L.exp_in = L.exp_out = 1024`（`engine.cpp:735-740`）。
3. 字节账互证：up+down ≈ **2.953 MiB/专家**（1024×2688×0.5625×2）＝ 日志 `23.1 GiB / 8010` ✓。
4. 对照：`moe()`（n<32）用 `in_w/out_w` + `latent_down` + `moe_out_`（`:1883-1909`）；修复前 `moe_rows()` 全用 `n_embd_`（量化 `:2394`、cached up/down `:2435/2444`、staged up/down `:2472/2477`、cpu `:2495`、`moe_sum` `:2508`）。
5. 边界：`batched()` 要求 `n ≥ kStageRows=32`（`:1878`）⇒ **n<32 走好的 `moe()`、n≥32 走坏的 `moe_rows()`** ⇒ pb 阈值恰在 32。
