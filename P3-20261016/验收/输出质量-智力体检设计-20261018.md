## §0 一句话结论

1. **基线 45 ids 解码出来是语义连贯的英文**，而且**正好接上 prompt 的最后一句话**（`...and it will happily` → ` delete the check you wrote to catch a bug, because the bug it would catch is, by the rules of the language, impossible.`）⇒ **基线本身不是胡言乱语**（A 级，同一 GGUF 的 token 表解码）。
2. "胡言乱语"可以变成 **4 条可测判据**（退化循环 / 概率塌缩 / NaN·Inf / 长生成重复率），每条都有历史真红例与阈值（§2）。
3. **独立参考可行**：`E:\llama-cpp-upstream\` 有官方预编译 **b11696**（llama-completion / llama-tokenize + CUDA），同 GGUF 同 prompt 可跑；本席已用 `llama-tokenize` 证明 **decode→再 tokenize 逐位可复原**（首 64/64、中段 300/300 全等）。按 R21 需把 `--n-cpu-moe` 提到 **25–26**（预计 VRAM 30.6/29.1 GB），耗时约 **6–7 min/跑**（§3 有命令草案）。
4. ★ 最容易被假绿骗过的一条：**"ids 45/45 对基线"本身**——它只证明"和过去一样"，不证明"和语言模型该有的一样"；必须叠加 §2 的独立质量门与 §3 的独立参考。

- **解码文本**（原样，含开头空格与换行）：
  ```
   delete the check you wrote to catch a bug, because the bug it would catch is, by the rules of the language, impossible.

  And yet the tower works. Millions of people use it every day without knowing that the
  ```
- **prompt 语境**（`C:\sp3\p6792.txt` 同法解码，6792 ids）：
  - 开头：`The history of computing is a history of layered abstractions, each one built to hide the accidents of the layer beneath it. A program that adds two numbers does not know whether the addition happens in a register, in a cache line, or…`

## §2 "胡言乱语"四条可测判据（每条写"怎么变红"）

### 2.1 退化循环（历史事故：`1278,2879,1044` 周期）

- **算法**：对 45 个 ids（或长生成窗口）算三个数：
  1) `D1ratio = 去重 token 数 / N`；
  2) `D2ratio = 去重 2-gram 数 / (N−1)`；
  3) `Period = 最小 p∈[2,12]，使 ≥80% 位置满足 ids[i]=ids[i−p]`（无则 0）。
- **标定（本席实算，A 级）**：基线 `pair_D`：D1=34/45=**0.756**、D2=44/44=**1.000**、Period=**0**；历史坏跑 `tile_pb1024.log`：D1=3/45=0.067、D2=4/44=0.091、**Period=3**；`pair_B_pb1024.log`：D1=0.111、D2=0.136、**Period=6**。
- **RED（任一）**：`Period ∈ [2,12]`（周期性覆盖 ≥80%）· 或 `D2ratio < 0.5` · 或 `D1ratio < 0.4`。
- **负控**：把历史坏跑 ids 喂进来必须红（上面两例必红）；基线必须绿。

### 2.2 概率塌缩（用现有 top-probs 日志抽 pos0–7）

- **数据源**：`--top-probs 8` 日志的 `top id:prob …` 行（每 token 一行）。本席已抽 7 份日志的 pos0–7（A0p/A0p2/A1p/R6-OFFtop/R6-ONtop/R9-RS3000-top/R13-TOP）：
  - **正常带**：pos0 top1 **0.9897–0.9911**；pos1–7 top1 **0.9996–0.999992**；top1−top2 margin **0.982–1.000**；top8 质量 **≥0.999023**；4 组独立跑（旧/新 exe、A0/A1/R13）pos0 top1 互差 **≤0.03% 相对**。
- **判据**：每个 pos0–7 取 top1、top2、top8_mass、entropy。
- **RED（任一，pos0–7 内）**：① `top1 < 0.20`（近均匀=模型不确定/受损）；② `top1−top2 < 0.01 且 top1 < 0.90`（分不开）；③ `top8_mass < 0.98`（质量漏到长尾）；④ **连续 8 个位置 top1 全 > 0.999999 且生成 id 相同**（塌缩到常数）。
- **YELLOW**：同一配置的 pos0–7 top1 与基线带相对偏差 **> 5%** ⇒ 先复跑再判。
- **怎么变红（历史真例）**：本机 23 份旧日志的 top 行出现过 `top 3:nan 4:nan …` ⇒ 概率数组出现 NaN ⇒ 必须 RED（见 2.3）。当前 R1a/R1c/R6/R7/R8/R9/R10/R13/R14 日志 **0 命中**。

### 2.3 NaN / Inf

- **命令**（零 GPU，全量）：
  ```powershell
  Get-ChildItem -LiteralPath 'C:\sp3' -Filter '*.log' | Select-String -Pattern '(?i)\b(nan|inf)\b' | Select-Object Path,LineNumber,Line
  ```
- **本席实跑结果**：**23 份日志命中**，全部是旧 config/修复前时代的 `top …:nan`（`card_*`/`corr_*`/`cs_*`/`Gb_*`/`lat_pb32_off`/`mr_*`/`nan_*`/`sa8_pb32`/`thr_*`）；**当前候选跑（R1a/R1c/R6/R7/R8/R9/R10/R13/R14）0 命中** ⇒ 该门当前绿、且历史有真红例（能变红）。
- **RED**：任一新跑日志命中 `nan|inf`（含 `top …:nan`）；或 ids 行出现非整数/负数/≥vocab(131,072)。

### 2.4 长生成重复率 / 自洽代理（128–256 token，需 GPU）

- **跑法**：同 prompt、`--max-new 256`、greedy、冻结 profile（其余 flags 同 A3 基线）；对 256 个 ids：
  - `Period`（p∈[2,16]，覆盖 ≥50%）· `D2ratio`（<0.5 红）· **最长重复子串**：后缀-前缀重复长度 ≥12 且出现 ≥3 次 ⇒ 红；
  - 解码成文本：**必须成句、主题不跑偏**（人工/另一模型判读，标 B/C 级）。
- **标定**：45-token 基线 D2=1.0 是"短窗口下界"；256-token 正常英文 D2 预计 >0.85（**未测，需首批跑标定**——明写未验）。
- **RED**：period/D2/最长重复任一越界，或解码文本不是通顺英文/明显跑题。

### 3.2 同 prompt 可行性（本席已证，A 级）

- 本席用 **同一 GGUF + `llama-tokenize.exe`** 做往返：`detok` 解码 → `llama-tokenize --ids --no-bos` 重编码：
  - 首 64 ids：**64/64 全等**；
  - 中段 300 ids（含 4 个换行）：**300/300 全等**；
  ⇒ 把 `p6792.txt` 解码成文本后喂 llama.cpp，**能复原成同一 6792-token prompt**。
- ★ 两个硬约束（实测）：① 文本 **33,606 chars > Windows argv 32,767** ⇒ **必须用 `-f` 文件**；② **llama.cpp 打不开中文路径**（本席实测 `-f ...\验收\ref-prompt-p6792.txt` 失败）⇒ **执行人先把 `...\验收\ref-prompt-p6792.txt` 复制到 ASCII 路径** `C:\sp3\ref_prompt_p6792.txt`。
- **开跑前零 GPU 门（执行人 30 秒可做）**：`llama-tokenize.exe -m <GGUF> -f C:\sp3\ref_prompt_p6792.txt --ids --no-bos` 的输出必须与 `C:\sp3\p6792.txt` **逐位相同**；不等 ⇒ 该对照作废。

- 输出对比：llama 的 45-token 文本 vs 基线 45 ids 的解码文本（§1 那串）——**逐字对照**；若不一致，再用 `llama-tokenize -p "<llama 输出>" --ids` 转成 ids 做逐位对照（并注明"文本→ids 转写"的限制）。

### 3.4 耗时 / VRAM 预算（由既有 A 级实测外推，D 级）

- 既有实测（`P3_llm_comp_run1.log`，N=24，700-token prompt）：**load 41.9 s**；prompt eval **26.45 t/s**；gen **6.61 t/s**（44 runs）；峰值 VRAM **32,156 MiB**（采样件 `P3_llm_vram_sampler*.txt`）。
- 本靶 6792-token prompt 外推：
  | `--n-cpu-moe` | 预计峰值 VRAM | R21（≤31,700） | prefill（估） | 总时（含 load+gen） |
  |---|---|---|---|---|
  | 24（历史实测口径） | 32,156 MiB | **不过**（超 456） | 6792/26.45 ≈ 257 s | ≈ **5.1 min** |
  | 25 | ≈30,644 MiB（−1,512/层） | **过**（余量≈2,116 MiB） | ≈283 s（−10%） | ≈ **5.6 min** |
  | **26（建议）** | **≈29,132 MiB** | **过**（余量≈3,628 MiB） | ≈303 s（−15%） | **≈6.0 min** |
  - 说明：每 +1 层 MoE 上 CPU ⇒ 省 512×3,096,576 B = **1,512 MiB** VRAM；速度按 N=27 vs N=24 的 bench 差（36.31 vs 43.95，−17%）线性估。**峰值必须实测**（R21：1 Hz 采样、临界带复核）。
- 预算（供 lead 上报）：**主对照 1 跑 ≈6 min**；加"短命题 sanity 探针"3 条（`The capital of France is` 等，n=8–16）每条 ≈1 min（load 42 s + 秒级）⇒ **合计约 9–10 min / 一轮**。

### 3.5 备选（弱）：CPU-only `llama-simple.exe`

- `E:\llama-cpp-pin\build-cpu-eval\bin\llama-simple.exe -m model.gguf [-n 45] [-ngl 0] [prompt]`：**纯 CPU ⇒ VRAM≈0，天然过 R21**；
- **但 prompt 走 argv**（33,606 chars 超限）⇒ **喂不进同一条 6792 prompt** ⇒ **不能做逐位/逐字对照**，只能拿短 prompt 做质量 sanity（弱证据）。
- 如需 CPU 全量对照：只能另编 CPU 版 llama-completion（**要编译，本轮禁**）⇒ 列为"未验/不推荐"。
