## §0 口径与流程（先读；违反其中任一条 ⇒ 该批读数作废）

1. **速度只认"同配置 3 个非-probs 跑的中位"**；报 **中位 + (min,max)**。单跑/两跑数字**不许**写成结论。
2. **decode 收益必须在异构 prompt 口径上报**：`C:\sp3\bench\{qa,code,zh}_ids.txt`（+`alt` 快检）；**p6792 只作历史对照，禁止对外报**（它的 22–25 tok/s 是模板红利，见 `多样prompt台-设计-20261018.md` §2）。
3. **每跑前报预算**（几臂/几分钟/显存与内存），得到批准才跑；**一次一跑**、GPU 独占；峰值 VRAM 必须过 R21（≤31,700 MiB）。
4. **两列同报**：速度（decode tok/s、tokens/round、兑现率）+ 质量（ids/文本/概率）；缺任一项 ⇒ 该结论降级为"未验"。
5. **参照系** = 同日同 exe 同 config 同 prompt 的多跑中位；跨 sha 读数一律作废。
6. 档位标签（新老）：**类 E = 计算路径变化**（`--pcie-frac>0`、任何 CPU↔GPU 换算法位置）——沿用 2026-10-18 交接件的类 E 门，见 D7。

## §4 这批判据**不能证明**什么（必须与结论同写）

1. **单/少 prompt ≠ 语言能力**：qa/code/zh 只是"多样性探针"，不能证明模型"聪明"；答案对错要人工/独立模型判（B/C 级）。
2. **ids/文本逐位同 ≠ 无损**：p6792 上三档有损 decode 与基线逐 token 同，但那是模板红利；D6 已把该案例列为负控。
3. **tok/s 提速 ≠ 正确性**：速度结论与质量结论必须分开报，互相不能替代。
4. **同引擎对照不能证明引擎正确**：所有 ids/Δp 门都是"与自己基线比"；"模型没被弄傻"仍需独立实现（`task-17` llama.cpp 45-token 对照）。
5. **3 跑中位 ≠ 统计显著**：只给量级与范围，不排除窗口漂移；跨批比较一律作废。
6. **类 E 的 ids 逐位只在 ≥2 prompt 上成立**：单 prompt 的逐位同不能外推。

## §V3-A 「只解释、不验收」清单（★ 新增，强制）

| 指标 | 为什么只能解释 | 反例（盘上读数，带源） |
|---|---|---|
| **GPU util% / SM occupancy** | GPU 大部分时间在等 CPU/handoff，util 是"在哪等"不是"等多久" | 老师 A770 实测 decode 期 ccs 多为 0–20%（`A770_SPEED_SPEC.md:696-700`）；本机 nsys decode 段 3–4% busy（同上）⇒ util 低是**常态**，不是引擎差 |

| **threads/并行度、occupancy 代理** | 超订/混合核下"并行单元更多"反而更慢 | **threads 16→24：16.23–16.40 → 12.65 tok/s（−22%）**，`cpu_us/miss` 96.3–100.1→127.9–156.6（`情报-Y:112`） |

**规则（硬）**：
1. 上述指标**只能用来解释**（在报告里说明"为什么快/慢"），**不得作为采纳判据**（不得写进"达成/不达成"的判定条件）。
2. **采纳只看**：`ms/token`（**3 次非-probs 跑的中位**，D1）+ **ids 逐位 / 文本逐字 / 全位置 Δp**（D2/D3/D5）质量门；两者都绿才可采纳。
3. 报告里出现代理指标 ⇒ 必须同时给出对应 `ms/token` 中位；给不出 ⇒ 该结论**只能当解释，不能当交付依据**。

**怎么变红**：若有人用上述任一指标直接下"采纳/不采纳/达成"结论 ⇒ **该结论判红（无效）**，必须退回 `ms/token` 中位 + 质量门重判。

## §V3-B 「honest profiler」前置（打点自检清单，★ 新增）

1. **每个计时字段必须注明来源**：
   - **实测**＝CUDA event 或墙钟（`steady_clock`）直接量的；
   - **导出**＝残差 / 相减 / 由别的量推算的。
2. **导出项不得作为主判据**：只能辅助解释；任何"分段分解/占比"结论的主项必须是实测。
3. **R49 现状（先补真计时，再谈分解）**：
   - `commit = wall − (router + cpu_pool + host)` ⇒ **残差**（`PolyStrata\src\poly\main.cpp:849`）；
   - `host/launch = (cpu_ms − cpu_busy_ms) − pool` ⇒ **导出**（`main.cpp:843`）；
   - ⇒ 现有 ledger 的"四段"里 **`commit` 与 `host/launch` 两段不是实测**；**先补 CUDA event/墙钟真计时，才允许下"四段分解"结论**；在此之前 ledger 只用于总量/比例解释。
4. **自检门（账要闭合）**：`gate/up + quant + down` 之和 vs `cpu_pool` 差 **> 2% ⇒ 标"账不闭合"**，分相值不得下结论：
   - `R49-L1-20261018.log`：gate/up 3210.9 + quant 22.2 + down 3415.6 = **6648.7 ms** vs `cpu_pool=6238.0 ms` ⇒ **+6.6%**；
   - `R49-L2-20261018.log`：4430.6+64.8+4707.3 = **9202.7** vs 8508.9 ⇒ **+8.2%**；
   - 两跑都 **>2% ⇒ 当前 ledger 账不闭合**（可能分相边界/重叠不同，待施工核）。
5. **怎么变红**：报告写"实测"但实际是残差/相减/推算 ⇒ **红**；四段和与总量差 >2% 仍引用分相下结论 ⇒ **红**。

## §V3-C 同批 CTRL 配对（强制项，★ 新增；G2 正式化）

1. **任何 decode 实验必须带同批 CTRL 首尾配对**：同 prompt、同 config、同 exe，实验块**前/后各至少 1 跑 CTRL**。
2. **首尾 CTRL 差 > 5% ⇒ 整批作废**（环境漂移；不做任何归因）。
3. **采纳门** = 同批**配对差**的中位（按实验类型：性能门 ≥15% 或 D1 的 +5% 噪声门）+ D1–D5 质量门；**单跑 / 无 CTRL 一律不采纳**。
4. 依据（本机读数）：p6792 无窗同配置单跑 12.57 / 14.10 / 14.53（±8%）；R5 实测 CTRL 首尾漂移 **−10.3%**（`回执\R5-ring2-v2-ABAB配对-20261017.md`）。
5. **怎么变红**：缺 CTRL、或首尾差 >5% 仍给归因/采纳结论 ⇒ **红**。

## §V3-D 追加"不能证明什么"（与 v2 §4 并列）

7. **util 低 ≠ 引擎差**：Strata 自己的 A770 文档就说 decode 时 GPU mostly IDLE（`A770_SPEED_SPEC.md:688-700`）；本机 nsys decode 3–4% busy 同型 ⇒ util 低是这类引擎的**已知形态**，不是失败证据。
8. **util 高 ≠ 有效**：自旋等待/忙等也算 busy；occupancy/占用回答的是"**在哪等**"，不是"**等多久/值不值**"。
9. **命中率 / tokens-per-round / 单跑 tok/s 不能证明"更快"或"更对"**：只有 ms/token 中位 + ids/Δp 质量门能。
