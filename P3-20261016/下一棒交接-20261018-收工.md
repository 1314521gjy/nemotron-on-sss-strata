## 2. 今天判否的（**别再试**，附判据）

| 机制 | 声称 | 判否证据（A 级） |
|---|---|---|
| `--lookup 3` 作 decode 主杠杆 | p6792 +57% | **alt prompt −10%**（12.03 vs 13.36）；p6792 是重复模板，续写≈抄 prompt ⇒ n-gram 天然命中 |
| MTP draft（原状） | 官方卖点 | p6792 +51% 但 **alt prompt −32%**；acceptance **0–4%** |
| `--tail-skip` 7/11/15 | 老师默认 7 | 有损，决策记录：**只存档不启用**；T11 有 3 处 >0.05 Δp 跳变 |
| PCIe 分流 v1（`--pcie-frac`） | 老师 1.300× | p6792 +11%；**alt prompt +3.1%（噪声内）+ near-tie(margin 3.15%) 处翻 token** ⇒ 不采纳为默认；代码保留 opt-in（默认 0） |
| `--host-core last` / `--aux-cpus auto` | 老师 aux +11% | 我们 **−11.5%**（24 线程已占满 24 逻辑，host 自己是第 24 个 worker）⇒ 默认 `off` |
| `--expert-swaps 32/128` | 换入粒度 | 32 → −5.1%；128 非法（合法域 1..64） |
| `--vram-reserve-mib 2600` | 涨驻留 | +1.0%，峰值 31,439 贴门（余 261 MiB）⇒ 不采纳 |
| profile 累积写回 | 涨命中 | 机制成立（+63 行写回），命中 51.7→**53.1%**，decode +0.7% ⇒ 收益太小 |
| `--threads 48` | — | **−55%**（CPU 过订阅） |

**关键认知**：命中率 51.7% vs 老师 96.5% 的差距**主因不是 tier**，而是 **top-22 vs top-10 + 驻留比例 28.8% vs 36.8%** ⇒ 漏专家/层/token ≈10.4 vs 0.35（30×）。**是模型几何差异，别拿 96.5% 当我们的目标。**

## 3. 今天修好但**不划算**的（重要资产）

**MTP 块（blk.88）原本只移植了一半**：`kind_of()` 把它判成纯 MoE（运行证据：开 draft 载入 `of 20992`=41×512，关 draft `of 20480`=40×512），**attention 子层与 `post_attention_norm` 从未加载**，`block_attend/block_rows` 是空实现 ⇒ draft 输出近似随机 ⇒ acceptance 0–4%。

**R30 已补齐**（`kAttnMoe` + 双载 + 块 KV + `block_attend/block_rows` + `post_attention_norm→L.ffn_norm` + `check_draft_block` 硬校验 + `--draft-dump`）：
- **acceptance 84.6–94.9%**（dump 逐轮 `base→guess→picked` 全对）⇒ **MTP 能力达标**
- **但 decode 只 +2.2%**（11.45 vs 11.20，门 5%）：D2 每轮 203ms×2.07 token（98.2ms/token）vs D3 75ms×1（89.3ms/token）⇒ **投机只抬 tokens/round，不降每 token 成本**
- **ids 门不过**：draft 机制自身占 VRAM（`state_` +113MB、`r_` 3×2 缓冲 +454MB、块权重/KV）⇒ **驻留 5721→5509（−212 专家）** ⇒ prompt 端 hidden 变 ⇒ pos0 分布偏移 `max|Δp|=6.2e-2`、top1 互换。**注意：这不是"末位漂"，是"谁算 GPU/CPU"变了。**
- ⇒ **结论：MTP 能力保留为 opt-in，交付仍 `--no-draft`**
- 未做的隔离实验：`STRATA_DRAFT_LOAD_ONLY=1`（接线但空转）+ reserve 补偿 −212 专家，再判 ids 门。**这是下一棒接手的第一个候选。**

## 4. 新判据 / 新纪律（今天踩出来的，必须继承）

1. **类 E「计算路径变化」档**（`--pcie-frac>0`、任何 CPU↔GPU 换算法位置）：不要求逐位，但须 ①**ids 逐位（≥2 条不同 prompt）** ②**文本逐字同** ③**确定性**（同配置重复跑概率逐位同） ④`max|Δp|` 记录且**无 >0.05 跳**，near-flip(margin<0.05) 单列 ⑤默认值仍关。
2. **确定性对照必须 `--expert-swaps 0`**：交付配置在冷缓存 prompt 上**同配置重复跑都不逐位**（换入 2,700+ 专家、A0 vs A0b 也翻 1 个 id）。要逐位判就先关 swaps。
3. **probs 对比一律静默窗口**：挂 VRAM 采样器的跑会从 pos97/65 起漂（max|Δp| 0.11，ids 不变）⇒ 采样器扰动时序。
4. **`--draft-dump` 只作语义检查**：它的 stderr 打印会经时序影响计时型 `guesses` 决策（D1 vs D2 仅差 dump 也 ids 不同）。
5. **tokens/round / 兑现率有盘上来源**：`main.cpp:660-668` 的 `DONE` 行 = `generated/prompt/prompt_ms/decode_ms/finish/drafts_accepted/drafts_offered/reused` ⇒ `tokens/round=generated/reused`、兑现率=`accepted/offered`。
6. **基准代表性**：p6792 是重复模板（"delete the check"×8 / "The history"×10 / 53 段），续写=抄 prompt 子串 ⇒ **只能证"无乱码/无退化"，不能证语言能力、且严重高估 lookup/MTP**。异构 prompt 用 `C:\sp3\alt_prompt.txt`（293 tok，C++ 题+哈希表问答），ids `C:\sp3\alt_prompt_ids.txt`。

## 6. 下一棒建议（按杠杆排序）

1. **`STRATA_DRAFT_LOAD_ONLY=1` 隔离**：把 draft 机制自身 VRAM 代价与"block 计算"分离 + reserve 补偿，判 ids 门能不能救；若 ids 能干净 ⇒ 再看 MTP 是否值得（当前 +2.2%）
2. **CPU 侧成本**：decode 每 token 里 CPU experts 11.1ms + router wait 6.6ms（alt prompt），而总 75ms ⇒ **大头在 GPU 单 token 延迟**，方向是 kernel/批处理，不是换专家
3. **多样 prompt 质量/性能台**（问答/代码/中文/长文）—— 没有它，任何 decode 结论都可能再被 p6792 骗一次
4. adaptive tier 的旋钮化代码**已在**（`--adapt-min-gain/--swap-half/--swap-ratio`，默认=现值），但收益预期低（命中率约束在驻留槽数）
5. 判否清单（§2）与 §4 纪律**直接继承，别重测**
