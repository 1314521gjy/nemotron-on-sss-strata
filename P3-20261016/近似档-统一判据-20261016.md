## §1 三个开关的**定性**（A，逐条 file:line）—— 它们**不是同一类**
| 开关 | 默认 | 机制（原文/行号） | **改不改结果** |
|---|---|---|---|
| **`--tail-skip N`** | **0** | `engine.hpp:75`：*"a routed expert outside VRAM that every token of a call ranks this far down or later is **left out**"*；守卫 `engine.cpp:1946-1952`；计数 `tail_experts`（`engine.hpp:139`）⇒ 输出行的 **"N left out"**（`main.cpp:724`） | ★ **真的少算专家 ⇒ 改结果**（**这是"丢计算"型近似**） |
| **`--lookup N`** | **3** | suffix-drafter 猜后续（`main.cpp:439` `repeats.propose`）；`N=0 ⇒ look=false`（`:321`） | ★ **猜测【被验证】后才接受**（`main.cpp:478`：`t == w[right+1]` 才继续）⇒ **id 级可能【完全不变】**；**但整窗走 `engine.window(w, use.t)`（`:472`）批量前向 ⇒ 浮点级可能变** |
| **`--draft-model F`** | 无 | 从**另一个文件**取猜测块（`main.cpp:753-754`） | 同 `--lookup`（**猜测+验证**）+ **① 多载一个模型（VRAM/内存账要同报）② 猜测来源不同** |

★★ **⇒ 结论（本件最重要的一句）**：
> **`--tail-skip` 与 `--lookup`/`--draft-model` 不是同一类近似** ——
> **前者【丢计算】（改结果，肉眼可见）；后者【先猜后验】（id 级可能逐位同，但【浮点级】未必）。**
> ⇒ **判据必须【分层】：ids 逐位【不够】**（**`--lookup` 会从 id 级眼皮下溜过去**）。

## §2 ★★ 统一判据（三条，对三个开关一视同仁）

### R1 **单独成档**（**硬**）
- **绝不进 `all` / 基线 / 正确性档**（引用 `开关清单-预分类` 的分类口径）。
- ★ **一次只开一个近似开关** —— **同时开两个 ⇒ 分不清谁贡献**（与修订 12"反组必须先自证"同一条纪律）。
- 档名建议：`appx_tail6` / `appx_lookup3` / `appx_draft`（**可读、可 grep**）。

### R2 **正确性双判（两条都要，缺一不可）**
1. **ids 逐位相同**（同一 prompt、同一 `--max-new`、**greedy**）—— 比**共同前缀**（长度/停止点漂若发生，**单列**，见 R3）；
2. ★ **`--top-probs` 逐位相同（浮点级）**（`确定性回归判据 §1②`）。
> ★ **为什么②不可省**：`--lookup`/`--draft` 的猜测是**验证过**的（`main.cpp:478`）⇒ **id 可能逐位相同**；但它们把窗口**批量前向**（`:472`）⇒ **数值可能变** ⇒ **只比 id 的判据【会放过它】**。
> ⇒ **这条与本靶已确立的机制同族**：**批量/不同路径 ⇒ 累加序变 ⇒ 浮点位变**（`驻留集合变是否改数值-判读-20261016.md`）。

### R3 **怎么判"变了"**（★ **近似档允许变，判据是"变必须被量化并声明"，不是"必须不变"**）
| 情形 | 判定 | 处置 |
|---|---|---|
| **ids 逐位同 + top-probs 逐位同** | ★ **该档在本靶上等于"真·快"** | **报队长** ⇒ 可考虑**提级进 `all`**（**这是本判据最值钱的输出**） |
| **ids 同、top-probs 不同** | **等价但【非逐位】** | ★ **不得与逐位档混用**（同 `确定性回归判据` 的"亚稳态"口径）；**与"逐位档"比较须注明口径** |
| **ids 不同** | **非等价档** | **必须给：分叉位置 + 差异幅度 + 对任务指标的影响**；**标"非等价近似"** |

### §2.1 负控 / 正控（**能变红**）
- **负控**：**同一档【跑两次】**（弃预热）⇒ **必须逐位同**。**若该档自身两次不一致 ⇒ 它的任何比较都作废**（先治环境/查成因，别解释成"效应"）。
- **正控**：**关掉近似的档**（`--tail-skip 0` / `--lookup 0` / `--no-draft`）⇒ **必须回到与 canonical 逐位相同的基线**（不回 ⇒ 说明"关"没干净，同"关近似"分类的落点）。
- ★ **`--tail-skip` 的专有正控**：**输出行的 `left out` 必须 > 0**（`main.cpp:724`；`tail_experts`）—— **否则该档根本没裁掉任何东西 ⇒ "档"是空的**。（与 §3 的"接受率"并列：**每个近似开关都要有一个"它真的动过"的读数**。）

## §3 ★ 性能口径（近似档的"收益"怎么读）
- **主读数 = `prefill tok/s`**（修订 7）；**decode 作副读数**，**必带实际长度 + 停止原因（`finish`）**。
  ★ **近似档会让长度变**（`--tail-skip` 少算 ⇒ 输出可能不同；投机 ⇒ 停止点可能变）⇒ **长度不同时 tok/s 【不可比】**（同 `确定性回归判据` 口径）。
- **必报四项**：`prefill tok/s` · `decode tok/s` · **接受率 = `guessed_right / guessed`**（`main.cpp:481-482`，即输出行的 "X of Y guessed tokens right"）· **`left out`（tail_experts）**。
- ★★ **防伪（`KP-MOEDEP-0007` 同构：接受率升而 decode 降）**：
  > **接受率高【不能单独】当作"投机有用"的证据** —— 它可能同时把窗口拖大 ⇒ **墙钟 decode 反而降**。
  > ⇒ **判据：接受率与 `decode tok/s` 必须【同报】；两者方向相反 ⇒ 判"净亏"，不出"有用"结论**。
  > ⇒ 这与"**命中率不能单独当机制读数**"（修订 14.2/15.2）是**同一类错误** —— **比例类读数必须配一个绝对读数**。

## §4 ★ `--draft-model`（MTP/投机）专条：**同批交错 ON/OFF**
- **做法**：在**同一次批跑**里**交替 ON/OFF**（A,B,A,B,…），**每档 n ≥ 5 + 弃预热**，取**成对差**（配对设计）。
  ★ **理由**：我们吃过"**跨时间漂**"的亏（`t18` 的绝对数**不可复现**）⇒ **交错把 drifts 消掉**，比"两档前后各跑 5 次"强。
- **判据**：**配对差中位数 > `max(2·s_pair, 5%)`**（`s_pair` = 配对差的 MAD-σ）⇒ 才判"**有净收益**"；**否则判【无结论】**（**不许写成"没效果"** —— 见 V4：连续 3 轮不合格 ⇒ 转治环境）。
- **★ 必核（否则交错本身是错的）**：交错**不得改 `--prompt-batch` / `--stage-ahead`** —— decode 本来就进不了 `--stage-ahead` 的闸门（`engine.cpp:2197`），**一动批参数就换了被测对象**（修订 16.2）。
- **退化方案**：**若引擎做不到一次跑里 ON/OFF 交替** ⇒ 退回 **A/B 各 ≥5 跑 + 中位**，**并【必须】报 `s_round`**（修订 11）⇒ 并在结论里**注明"未配对"**。

## §6 ★★ 温度档（`--temperature/--top-p/--top-k/--min-p/--seed`）—— **投机/MTP 的判据必须带它**（2026-10-16 补）

> 依据（**转述，未自核 ⇒ 标 C**）：外部点评指出 **Strata 的重要加速来源之一是投机解码 / MTP**，而**同门实测"接受率是温度的函数"**：**温度 1.0 → 接受率 6%**；**温度 0.3 + `top_p 0.9` → 70%**，**decode 近翻倍**。
> ⇒ **"接受率低"可能只是"温度高"，不是"机制没用"** ⇒ 三条判据（下）。

### 6.1 读码定死（A，我核过）—— 温度为什么是**另一个族**
| 事实 | 出处 |
|---|---|
| **默认 = 贪心**：`Sampling.temperature = 0.f`，且 `if (s.temperature <= 0.f) return most_likely(logits, …)` ⇒ **argmax，且【不消耗 RNG】** | `main.cpp:73` · `:91` |
| **温度档才动 RNG**：`for (Cand& c : cand_) c.logit /= s.temperature;` + `discrete_distribution(…)(rng)` | `main.cpp:129-131` |
| **`--seed 0`（默认）⇒ 不可复现**：`if (s.seed != 0) rng.seed(s.seed)`，而 rng 初值是 `std::random_device{}()` | `main.cpp:357` · `:304` |
| **采样五元组 + 顺序**：`temperature/top_p/top_k(默认20)/min_p/penalties`，其后才是抽签 | `main.cpp:73-78` · `:81` |
| **serve 路径下采样参数走 `GEN` 键**（每请求可不同） | `main.cpp:515-521` |

### 6.2 ★ 三条判据（队长点名）
- **T1 测投机/MTP 必须带温度档**：**至少三档 { 贪心/`temperature 0`、`0.3`(+`top_p 0.9`)、`1.0` }**；**只报一档的接受率 ⇒ 退回**（否则"接受率低会被误读成机制没用"）。
- **T2 接受率必须与墙钟同报**（**防 `KP-MOEDEP-0007`**："接受率升而 decode 降"）：接受率 = `guessed_right / guessed`（`main.cpp:481-482`），**必须与 `decode tok/s` 同列**；**方向相反 ⇒ 判净亏**（同 §3）。
- **T3 温度本身是"改结果"的开关** ⇒ **温度档与近似档同样处理**：**单独成档 · 不进基线 · 必配 ids/`--top-probs` 判据**。
  ★★ **并且：`贪心档` 与 `温度档` 是两个【不可混引】的族** —— **任何"基线/基线对照"一律用贪心档**；温度档只用于**投机/MTP 的收益判据**。

### 6.3 ★ 我补的两条（**不补会直接判错**）
1. ★★ **温度档下"同档两次必须逐位同"【默认不成立】**：`--seed` 默认 **0** ⇒ 走 `random_device` ⇒ **每次运行不同**。
   ⇒ **负控/正控要改成"同 `--seed` 两次"**；**报温度档读数必须把 `seed` 写进 log 头**（否则**根本不可复现** ⇒ 该档读数**退回**）。
   ⇒ 这也意味着：**§2.1 的负控（同档两次逐位同）在温度档下必须先固定 seed 才有意义** —— **别拿它去判"引擎不确定"**。
2. ★★ **温度档下【禁止】用"ids 逐位相同"当"投机无害"的证据**：投机的验证逻辑（`main.cpp:478` `t == w[right+1]`）**只在贪心下等价**；温度 > 0 时，**接受几个猜测就多抽几次签** ⇒ **RNG 流的推进次数随窗口长度变** ⇒ **输出必然不同（且与投机的窗口耦合）**。
   ⇒ **判据**：温度档下**只能**用"**任务指标**（同 seed 下的输出质量/长度/接受率）"衡量，**不许**用"逐位相同/不同"论证等价性。

### 6.4 口径（写死，纳入 log 头）
> **温度档读数必须同报五元组**：`temperature` · `top_p` · `top_k` · `min_p` · **`seed`**。
> ⇒ **建议把"log 头四样"扩为【四样 + 采样五元组】**（旗标 / exe sha / prompt sha / `--prompt-batch`+命中 / **采样**）。**缺任一 ⇒ 该读数退回**。

## §8 ★★ 叠加档：**模型自带 MTP × 引擎自带 `--lookup`**（2026-10-16 新思路；只出判据、不执行）

### 8.1 ★★ 读码定死（A）—— **"叠加"在库里【算法已备、但没接线】**
- **两者本来就同时在场**：`most = (lookup > 0 || e.drafts()) ? min(max_window(), kMaxT) : 1`（`main.cpp:320`）⇒ **只要一个开着窗口就 >1**；MTP = `engine.drafts()`（`engine.hpp:239`，文件的 `nextn` 块），lookup = `repeats.propose()`（`main.cpp:439`）。
- ★★ **但每轮是【二选一】，不是叠加**：`DraftPolicy::choose(t_mtp, lookup_k, match)` → 一个 `Pick{t, lookup}`（`draft_policy.hpp:22-34`）；`main.cpp:452` 与 `:461` 把 **lookup 的 `k`** 与 **MTP 的 `1+n_d`** **分别**喂进去、**取其一** ⇒ **仲裁关系**。
  头文件首行原文：*"per verify round: the MTP's window, **or** a lookup (suffix) window?"*（`draft_policy.hpp:1`）。
- ★★ **真正的"叠加"（链式）已写好、但【零调用】**：`DraftPolicy::chain(t_mtp, p_mtp, k_avail, match)` —— 语义 = *"how many of `k_avail` lookup tokens to **append after an MTP window**"*，期望产量 `E(t_mtp) + p_mtp·(c + c² + …)`（`draft_policy.hpp:38-45`），配套 `observe_chain()` / `chain_rate()`。
  ⇒ **全仓 grep：`chain(` / `observe_chain` / `chain_rate` 在 `src/poly/` 下【零调用】；`--lookup-chain` 旗标不存在**（`main.cpp` usage 无）⇒ **此前设想的那个档 = 「算法已备、缺接线」**，**不是"没这功能"**。
- ★ **叠的方向**：`chain()` 是 **MTP 在前、lookup 接在后**（`E(t_mtp) + p_mtp·Σc^j`）—— **与"先 lookup 白抄、再用 MTP 补满"是【反的】**。⇒ **两条方向都值得试，但只有"MTP 在前"有现成算法。**
- ★ **两个窗口尺度不同（A）**：**MTP 最多猜 3 个**（`kBlockWindow = 4`，`main.cpp:66`），**lookup 可到 8**（`match ≥ kCopyMatch = 8` 时窗口取 `most`；`this->kMaxT = 8`，`main.cpp:70`/`:441`）⇒ **lookup 窗口更长 ⇒ 验证更贵** —— 这正是头注释"naive 做法掉 2–8%"的原因（原文 `draft_policy.hpp:3-5`：*"Taken whenever it proposes more than the MTP, it lost 2-8% on ordinary text"*；**这是 A 级原文，也是一条先验警告**）。

### 8.3 ★★ 主判据：**每轮产量**（`KP-ENGSPEED-0008`：投机提高"每轮产量"、**不改"每轮搬多少字节"**）
**三个读数必须同报**：① **接受率** `guessed_right/guessed`（`main.cpp:481-482`）· ② **墙钟 decode tok/s** · ③ ★ **平均每轮产出 token 数**。
★ **③ 现在【没有读数】** —— 我核过：**decode 循环里没有 rounds 计数器**（`main.cpp:435` 的 while 是裸的；`guesses.hpp:38` 的 `rounds` 是**策略自己**的计数，**不是**解码轮数）。
⇒ **判据**：**平均每轮产量 ≈ `produced / rounds`** ⇒ **`rounds` 必须进读数** ⇒ **归入 `O-1-钩子规格`**（在 `show()` 的 while 里 `++rounds`，env 门控、默认可 revert）。
⇒ **没有 ③ 就不许下"叠加有没有用"的结论**（同"比例读数必须配绝对读数"）。

### 8.4 ★★ 叠加档的专属反例（**能变红**）
| # | 观察 | 判定 |
|---|---|---|
| **S1** | E 或 D 的接受率 **≤ max(B, C) 中较高者** | ★ **判"不可叠加 ⇒ 二者抢同一窗口"**（**比"没效果"更有信息量**） |

### 8.8 ★ 执行监督（队长 2026-10-17 派：**builder 跑完后由本席判读**）
**交付口径 = 三量同报**（缺一 ⇒ 该组读数退回）：
1. **接受率** `guessed_right / guessed`（`main.cpp:481-482`）—— ★ **必须带温度档与 `seed`**（§6.3）；
2. **墙钟 decode tok/s**（**带长度 + `finish`**，近似档会让长度变）；
3. ★ **平均每轮产出 token 数 = `(produced − 1) / rounds`** —— **`rounds` 依赖 `O-1` 钩子**；**没这个数 ⇒ 不许下"叠加有没有用"的结论**。
**判读顺序**：先看 **D 档（双在场）** 是否落进 **S1**（接受率 ≤ max(B,C) ⇒ **判"不可叠加 / 抢占同一窗口"**）⇒ 若落进 S1，则 E 档（接线）**才成立为下一步**；若 D 已呈现 **S2**（每轮产量 > 两者单独最大且 decode 同向升）⇒ **先确认这不是温度档的功劳**（同 seed 复跑）。
**红臂**：同配置**同 seed 两次**若不逐位同 ⇒ 该组读数**作废**（温度档本就不保证逐位同 ⇒ 用**任务指标 + 分布**判，见 §6.3）。
