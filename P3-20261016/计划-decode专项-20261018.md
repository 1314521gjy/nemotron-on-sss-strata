# decode 专项计划（2026-10-18）— 分组/区组验证，不做单参数 OFAT
> 触发：prefill 已从 652.6 推到 **1906.7 tok/s**（+192%，对 3.8 差距 1.47×），`kernel busy 89.9%`；**decode 仍在 12–16 tok/s**，是下一阶段主战场（后期专项）。
> ★ 方法论要求：**decode 很可能是多参数共同影响 ⇒ 必须按参数分组、做区组/暗组验证（block/factorial），禁止单参数 OFAT。**

---

## 0. 已知（A 级，不重测）
- decode **不是 PCIe 带宽问题**：日志 `experts from VRAM 52.4%`（**该字段只在 decode 段计数**，`engine.cpp:2122-2123`）⇒ 每 token 只搬 ~0.59 GB ⇒ 12.3 tok/s 时 ≈ **7.2 GB/s**，离 23 GB/s 上限很远 ⇒ **瓶颈在延迟/小批量 GEMM/host 路径**。
- decode 用 CUDA graph replay（`engine.cpp:3007`，n ≤ window）；`route()` 在 host、单 token 开销小。
- 已知结论：`KP-UNI-0250` **stage-ahead 只救 prefill、expert-swaps 只救 decode（9.26×）**；`KP-UNI-0218` 借槽会伤 decode（−10~23%）；`KP-STRATA-0045` pcie-frac 属 decode 侧。
- 我们当前 decode 相关配置：`--expert-swaps 64` · `--cpu-share 0.55` · `--threads 24` · `--no-draft` · `--lookup 0` · `--tail-skip 0` · reserve 3000。

## 1. 方法论：分组打包 + 区组设计
**不做**"一次改一个参数"。**做法**：
1) 先把候选参数按**作用机制**分成 4 组（见 §3）；
2) **第一轮 = 组级筛选**：每组把"该组内推荐的改动"**打包成 bundle**，只测 bundle 的 **ON/OFF**（4 组 × 2 = **8 臂**）。这样测的是"这组机制值不值得动"，而不是单参数噪声。
3) **第二轮 = 组内细化 + 组间交互**：只进赢的组；并测 **两两交互**（例如 驻留×投机、投机×并行），因为多参数共同影响正是此前提到的风险点。
4) **抗漂移**：ABAB 交错 · **每 2 臂插 1 次 CTRL** · 每臂 **3 跑取中位** · 漂移 >5% 该 block 作废。
5) **机制自证**：每臂必须同时报 **每 token 搬运字节 + decode 命中率（口径 B）+ swap 次数**，防止"变快是因为没做事"。

## 3. 四组参数（组内打包，组间可交互）

**G1 驻留组**（决定每 token 搬多少字节）
- `--vram-reserve-mib`（3000 → 2500/2600，换取更多常驻槽；代价 prefill 略慢）
- `--expert-profile` 换成"累积写回版"（`--expert-profile-write` 跑一轮生成再读回）
- （待移植）per-layer 配额 · `--resident-cpu-experts`
- 预期：**每 token 搬运↓ ⇒ decode↑**；风险：prefill 退、显存门

**G2 投机组**（一次搬运算多个 token）
- `--draft`（当前 `--no-draft`）· `--lookup`（当前 0）· `strata_spec` 已链接的 suffix drafter
- （待移植）**MTP**（模型自带候选；`core/mtp.cpp` 不在链接面）
- 预期：**潜在最大单项**；风险：正确性/数值、模型是否有 MTP 头（D0 定）

**G3 并行组**（把延迟摊给 CPU/多线程）
- `--cpu-share`（0.55 → 0 / 0.7）· `--threads` · CPU pool worker 数 · （待评估）`--batch` 多序列
- 预期：decode latency-bound ⇒ 分担有用；风险：抢内存带宽、prefill 抢 CPU

**G4 布局组**（搬运粒度与顺序）
- `--expert-swaps`（64 → 32/128/全开；`KP-UNI-0250` 说它只救 decode）
- `--stage-ahead`（128，已知只救 prefill）· `--stage-mib` · `--tail-skip`
- 预期：PCIe 请求合并度与并发度；风险：驻留互斥（两列同报）

**第二轮交互（必测 2 项）**：G1×G2（驻留高时投机收益是否变小）、G2×G3（投机 + CPU 池）。

## 4. 判据（每臂都要过）
1) **decode = 3 跑中位**（单跑散 11.3–12.8，单跑不作数）；同窗 ABAB，CTRL 漂移 ≤5%。
2) **机制自证**：每 token 搬运字节 · decode 命中率（`experts from VRAM`，口径 B）· swap 次数 —— 三者必须一起报。
3) **质量门**：ids 45/45 + `pos0 Δp`（结构改动=0；涉及数值路径 ≤2e-3）+ 256-token 体检（Period/D2/解码文本）。
4) **显存门 R21**：峰值 ≤31,700 MiB（桌面留 ≥1 GB）。
5) **prefill 不许退 >3%**（当前 1906.7 / 墙 3.5622 s）。
6) 旗标可关；关掉必须逐字回旧读数。

## 5. 已知坑（写死，别踩）
- decode 单跑噪声 ±10%：**只认 3 跑中位 + ABAB**。
- **混臂禁令**：`--dump-layers` 会强制 rows_=1、`--no-gpu-experts` 绕过 moe_rows —— 不许当 decode 证据。
- 改 `engine.hpp` 后必须删 `build-p3\...\src\poly\*.cpp.obj` 再编（类布局错位会崩 `mamba2_scan: d_state outside 1..512`）。
- 开关自证行有 `: off` 后缀陷阱（`engine.cpp:1789-1791`）。
- 一律**先报预算**（几臂/几分钟/多少显存）再开跑。

## 6. ★ 2026-10-18 追加的两个必查机制（优先于 D4）

> 决策记录（2026-10-18）：CPU/GPU 同算与边搬运边计算均存疑；优先对拍老师机制，**先模仿再优化**。
> ⇒ **D3（老师对拍）提前到 D4 之前**，并在 D3 里专门做这两条；**先出"模仿清单"，再谈编译**。

### 6.1 CPU/GPU 同算（我们疑似没弄好）
- **老师有**：`--pool-workers N`（R2.2：默认每物理核一个，除 host 自旋核）、`--pool-tasks N`（每 GU/Down 阶段的批量 CPU 任务）、`--pool-affinity MODE`、`--host-core`、`--aux-cpus`、`--shared-late`（shared expert 在 CPU 池之后/重叠）——`C:\sp3\help.txt:81/203-226`
- **老师日志实据**：`2 pool workers on logical processors 2,4, the host thread on 0 (draining too)` · `CPU pool tasks/phase: 9 (automatic), participating threads: 3` · **`the CPU expert pool 7.159 ms/token over 48 layers (76 positions, 3648 dispatches)`** · `pool phases wait-park 0.000 drain 6.886 re-park 0.000 ms/token` · `R4 hit path ON - resident experts are computed on the GPU` · `R4 overlap 0 of 0 layers the hit work was DONE when the pool returned`（`dec-pool2.txt:31/32/41/83/84/40/86`）
- **我们**：`--cpu-share 0.55` + `--threads 24`，但日志里只有 **`CPU experts 0.4 ms/token`**；**没有** pool workers / pool tasks / affinity / host-core 概念。
- **必查**：我们的 0.4 ms/token 到底在算什么？为什么这么少？GPU 与 CPU 是**真并行**还是串行？expert 的"GPU 命中集 vs CPU 集"怎么切、结果在哪一侧 combine、有没有等对方？

### 6.2 边搬边算（decode 段疑似串行）
- **老师 prefill**：`m.cs`（计算流）+ `m.copy`（拷贝流）+ N 槽 ring（`prefill.cpp:1093/1119`）—— 我们已抄，实测 85.2% 重叠。
- **老师 decode**：verify 表 `wait for rings 12.378 / pool 7.269 / host 0.101 / commit 0.037 ms/round`（`dec-pool2.txt:71`）+ 逐层门铃（`generate.cpp:13935-13940`）⇒ 有明确的**层间流水/门铃**结构。
- **我们 decode**：**未画像**。要回答：每 token 是不是"路由完 → 等 PCIe 搬完 → 再算"？搬与算有没有重叠窗口？
- **判据**：decode 每 token 的 **PCIe 忙 / GPU 忙 / 二者重叠**三列；目标把 PCIe 藏进 compute。
