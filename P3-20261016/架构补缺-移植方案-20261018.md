## §0 结论速览

1. **① decode GPU/CPU 分流 = 老师最大的"缺架构"**：它的判据极简 —— **`m = (nmiss × pcie_num) >> 8`，把"路由序最后 m 个漏专家"交给 GPU 走 PCIe**，其余漏专家给 CPU 池（`expert_source.cpp:3770-3771`）；源必须 pinned（`:3806`）；目的地是 **staging 槽**（`:3832-3844`）；**plan 先发布（doorbell）、DMA 再在拷贝引擎上发**（`:3849-3853`），GPU 侧在 verify 窗口的 group kernel 里算（`verify.cpp:1652-1660`）。`pcie_num` 来自 `--pcie-frac`（`generate.cpp:2091`），自动版 `PcieAuto` 拟合 **`share = L/(L+1.85R)`**（`:1725-1770`）。我们 **`grep pcie src\poly` = 0 命中** ⇒ 完全没有。**移植 v1 不需要新 kernel**（直接复用我们已有的 `native_mmvq` 连 staging 指针算），需编译，~350–450 行。
2. **② 线程放置 = 最低风险、可先落地**：老师有 `--host-core first|last`、`--aux-cpus off|auto|LIST`、`--pool-workers/--pool-tasks/--pool-affinity/--no-host-worker`；实现是 `pool.cpp:74-96,401`（HostCore/`planned_host_core`/`pin_current_thread`）+ 头文件 `platform/aux_cpus.hpp`（`:235 note_owned_thread`、`:255 pin_current_thread`）+ `session.cpp:561-572`（host 线程自钉）。**只挪线程、绝不改结果**（help 原文）。我们只有 `--threads`，全工程无 Windows 亲和调用。**~120–160 行，零精度风险**。
3. **③ adaptive tier = 我们其实已经有骨架**：`Engine::follow()`（`engine.cpp:1369-1470`）就是"LFU-衰减 + 先验 tie-break + 收益门 + 异步到达检查"的自适应层；缺的只是**把写死的三个常数做成旗标**（`runtime.hpp:44-45`：`kSwapMin=2.0`、`kSwapHalf=128`，加上 `:1439` 的 `2×` 比例）。老师 0.1.44.1 之后的 `ADAPT_NOWAIT`/`res_patch`/resident-RAM-follow **在我们这里不适用**（我们没有"窗口重叠 + 槽表异步发布"的形态，且 poly 的槽表是**到达后才发布**，天然没那个 bug）。**per-layer 配额不建议**（我们 task-8 的 A 级结论：等配额命中率 −0.39 pt、全局贪心最优）。
4. **推荐顺序**：**Compile #1**（一次编）= ② 线程放置 + ③-a 三个旋钮 + ① 的 flag 骨架（全部默认 off，行为不变）；**Compile #2** = ① v1 固定 `--pcie-frac`（单独一编、单独一个变量）；**Compile #3** = ① auto-refine（PcieAuto）。

### §3.2 我们已有的东西（A 级）与差距

`Engine::follow()`（`engine.cpp:1369-1470`）= 一套完整的 adaptive tier：
- 衰减计数 `recent_`：`exp2(-written / kSwapHalf)`（`:1391`，常数 `runtime.hpp:45 kSwapHalf=128`）；
- 换入/换出候选：按 slot 尺寸分桶、`recent` 优先、`prior` tie-break（`:1394-1426`）；
- **收益门**：`in.recent >= 2 × out.recent + kSwapMin`（`:1439`，`runtime.hpp:44 kSwapMin=2.0`）——**这就是老师 `--adapt-min-gain` 的等价物，只是写死**；
- **异步到达检查**：`Swap::kSent` + `cudaEventQuery`，到达后才把 `L.slot[e]` 指向新槽（`:1376-1388`），随后 `card_moe` 发现槽表变了才重传 device 表（`:2287-2292`）；
- 上传路径：`s->pinned → s->slot` 的 `cudaMemcpyAsync` + event（`:1336-1338`，`swap_st_`）。

**差距只有三处**：
1. **旋钮写死**：`kSwapMin`/`kSwapHalf`/`2×` 比例 → 应做成 `--adapt-min-gain`/`--swap-half`/`--swap-ratio`（**默认 = 现值**），否则 decode 专项无法 A/B。**~40 行**。
2. **驱逐策略单一**（LFU-衰减）；老师 R4.1 测过 LFU-decay vs LRU 两种策略。**若 decode 命中率成为瓶颈再考虑**（~150 行 + 单独 A/B，属第二阶段）。
3. **窗口重叠**（NOWAIT）：**不需要**。poly 的换入是"发出→下次检查到达→到达后才发布槽"（`:1376-1388` + `:2287-2292`），不存在老师那个"表还是旧值就发布激活"的 bug 形态；除非以后做"swap 跨窗口重叠"，那时才需要 `res_patch`。**不建议现在做**。

### §3.3 per-layer 配额：**不建议移植**（有我们自己的 A 级反证）

- 老师 `--expert-cache-per-layer` 的动机是**修他们自己的坑**：help 原文 "the default policy fills in arrival order from one shared counter, so 256 slots went to ~26 layers of position 0 and measured **2.97%**；per-layer, the same routing gives **21.4% at 8 slots/layer and 70.4% at 64**"（`C:\sp3\help.txt:197-203`）——也就是**他们的默认是"到达序"而不是按计数**，才会被少数层首位专家吃光；**per-layer 是 bug 修复，不是通用最优**。
- 我们的填充是**全局按 `(prior+use)/slot_bytes` 降序**（`engine.cpp:1268-1272`、`:1286-1296`），本来就等价于全局计数贪心；`task-8` 已量化（A 级）：**等配额 147/层会把字节口径命中率从 68.2985% 掉到 67.9079%（−0.39 pt，= −210,773 次命中）**；floor=110 才几乎免费（−0.0091 pt）。⇒ **不要移植 per-layer 配额；若要"保底"，用 floor≈110 的混合方案**（也与 task-8 结论一致）。

### §3.4 与"命中率 51.7% vs 老师 96.5%"的关系（重要）

- 我们的 log：`experts from VRAM 52.7%`（`C:\sp3\pair_D_pb6912.log:87`；decode 45 token 的每 token 命中）；老师：`R4 expert-cache hits 115669 of 119845 = 0.9652`（`E:\strata\_staging\dec-pool2.txt:87`，同口径的 decode 命中）。
- **主因不是 tier，而是几何+口径**：老师 **top-10**（`src/prefill/kernels.cu:1511-1525` rank<10 硬编码）、驻留 **9041/24576 = 36.8%**；我们 **top-22**、驻留 **5890/20480 = 28.8%**。每 token 每层漏专家：老师 ≈ `10×(1−0.965)=0.35`，我们 ≈ `22×(1−0.527)=10.4` —— **差 30 倍**，其中 top-k 差 2.2×、命中率差给其余。⇒ **涨驻留（A 项 +1,010 槽 → 6,900）与 top-k 语义是命中率的直接杠杆；adaptive tier 是二阶**（它在 routing 漂移时才有用）。
- 因此 ③ 的产出建议：**只做 (1) 旋钮化**，供 decode 专项 A/B；per-layer 与 NOWAIT 都不进本轮。
