## §1 ★ 份额的定义与切口（**必须写进结论同一行**）
### 1.1 两条墙钟切口（**A，读码**）
| 切口 | 起 | 止 | 依据 | **含什么 / 不含什么** |
|---|---|---|---|---|
| **prefill 窗口** | `generate()` 入口（`main.cpp:350` `t0 = now`） | 读完 prompt（`:406` `r.prompt_ms = ms_since(t0)`） | `main.cpp:350/406` | ★ **含** `engine.images()`（`:351`，本靶文本 prompt ⇒ 空）**与 `kept.resume()`**（`:352`，**冻结 profile 下可能不便宜**）；**不含**模型装载（独立行 `loaded in X s`）· 进程启动/teardown · 输出打印 |
| **decode 窗口** | prompt 读完（`:409` `t0 = now`） | 生成结束（`:487` `r.decode_ms = ms_since(t0)`） | `main.cpp:409/487` | **不含**采样后的打印（`T`/`top` 行）· **不含** teardown |

⇒ ★★ **口径必写三件**：**① 哪个切口（prefill / decode）；② 分母是【kernel 时间之和】还是【该切口的墙钟】；③ memcpy/memset/空洞算不算。** 三件缺一 ⇒ **该份额退回**（沿用 `分步计时探针` §3.2 的闭合写法）。

### 1.2 ★ 剖面窗口与切口如何对齐（**代理切口 + 可判据化的校对**）
nsys 拿不到"`r.prompt_ms` 的起止"，只能用**时间线里的代理**（例：**首个 MoE 类 kernel → 最后一个**，或 `[read]` 段的首个/末个 kernel）。⇒ **必须**：
1. 在结论里**写明代理切口是什么**；
2. ★ **做一次闭合校对**：**`nsys 采到的该段总时长 / 该跑同一段的 `prompt_ms`（或 `decode_ms`）` ∈ [1.0, 1.1]`** ⇒ 认为**对齐**；**超出 ⇒ 口径错位，该剖面退回**。
   ★ **为什么是量级门而不是精确门**：`nsys` 本身有开销（观测改变被测对象）⇒ **门是"量级"**，不是等号。

## §2 哪些量可跨腿并排 / 不可
### 2.1 可并排
| 量 | 并排时**必须**满足 | 能否据此下结论 |
|---|---|---|
| `prefill tok/s` · `decode tok/s` | 同 prompt 长度档（**按各自 token 数**对齐，见 §2.3）· 都没开投机 · 同 `--max-new` | ★ **跨腿只作"量级"**（模型因子 ~2×：48 vs 88 层 · 10 vs 22 专家 · 640 vs 2688） |
| **命中率** | ★ 两侧都是**同一套打印口径**（见 §2.2 的**硬前提**）· 同报 `--prompt-batch` 与**是否 `--dump`** | ⛔ **更正（2026-10-17，见 `stdout口径对齐-20261017.md` §3）：跨腿【不可并列】** —— B 侧**无同名量**，且它只有 **prefill 段**的 `resident/streamed/CPU share`（与我方 **decode-only** 的口径**正好相反**）⇒ 只可"腿内"作机制结论 |
| **arena 对数 / 显存峰值** | 同写"含不含权重/KV/专家缓存/context" | ★ **更正（同上）：`arena` 跨腿【不可并列】**（B 侧 `--slots` **默认 0 = off**，**全流式 ⇒ 它没有 arena 这个量**）；**显存峰值仍可并列**（须写清构成） |
| ★ **内核类别份额** | ★ 同 §1 的两条切口 + 同一类别口径 | ★ **本次最有可比性的量**（引擎/模型无关的口径） |

### 2.2 ★★ 跨引擎腿（L-Q 用 **0.1.43.1 原厂**）的**硬前提**（我加，缺一即不可比）
1. ★ **原厂 0.1.43.1 的 stdout 行是否含同名字段**（`prefill/decode tok/s` · `experts from VRAM %` · `swapped` · `left out`）—— **我未核**（本席不跑）；**名字相同【不等于】定义相同** ⇒ **必须把两版的打印点对齐**（对我们这版是 `main.cpp:716-724`）。
   ⇒ **若字段缺失或定义不同 ⇒ 该量【不可并列】**，只能用两个引擎各自都有的量（tok/s）。
2. ★ **`0.1.43.1` 默认值可能不同**（例：`--stage-mib` 默认、`--stage-ahead` 默认、`--prompt-batch` 默认）⇒ **"原厂默认"与"我们 canonical"不是一个配置** ⇒ **必须把两侧【实际生效】的旗标全列出来**（不是只列命令行给的）。
3. ★ **CUDA graph**：两侧都必须**开着**（nsys 口径不许关 graph；若原厂默认关，则**L-Q 也要显式开着**，否则跨腿比的是两种发射结构）。

### 2.3 ★ prompt 长度的"对齐"（我加）
**两种模型的 tokenizer 不同**（Nemotron vs Qwen3.8）⇒ ★ **"同一份 prompt 文件、sha 相同"只能保证【文本】相同，不能保证【token 数】相同**。
⇒ **长度档必须按"各自的 token 数"对齐**，且**两侧都要报实际 token 数**（允许 ±3% 偏差，**超出 ⇒ 该对不并列**）。

### 2.4 **不可并列**（写死）
- **任何"单位算力效率"类派生量**（tok/s per FLOP / per parameter / per expert-activation）；
- ★ **任何旋钮的跨腿比较**：`--stage-mib` / `--stage-ahead` **在 3.8 侧【根本没有这个旋钮】**（`sm越小越快-机制与上游对应物-20261017.md`）⇒ **跨腿比旋钮 = 比不存在的东西**；
- **任何"档内数字"跨版本比**（同名旗标在两版**语义可能不同**，见 §2.2-2）。

## §3 ★★ 负控（**先于正控**；能变红）
| # | 负控 | 预期 | 判 |
|---|---|---|---|
| **N1（已知应当出现差异的一对）** | **同模型 · 同引擎 · 同 prompt**：`--stage-mib 48` vs `--stage-mib 2048` 的**内核类别份额** | ★ **份额必须不同**（已知 prefill 126→378 = **+200%**） | **若两档份额相同 ⇒ 判"探针/剖面无鉴别力"，本轮剖面作废** |
| **N2（散布门）** | **同一档跑两次**的份额 | 份额的 **MAD ≤ 3 点**（沿用 `§7` 的 nsys 两档门限） | **>3 点 ⇒ 先查口径（见 §4），不得拿它比两档** |
| **N3（可分辨门）** | 两档份额**中位差** | **≥ 10 点**才算"两档可分辨"（3 点的 3× 余量） | **< 10 点 ⇒ 判"差不可分辨"**，不许写"某步变快了" |
| **N4（正控）** | 已知**必须基本相同**的两次跑（同档同参、同窗口） | 份额**基本相同** | 若反而不一致 ⇒ **环境/窗口有问题** |

★ **负控先于正控**：**N1 不成立 ⇒ 后面所有"某步占比下降"的结论一律不得出**。

## §4 nsys 口径（沿用 `分步计时探针` §7，**不许松**）+ 一条新坑
1. ★ **`graphs=true` 保持开**（`engine.hpp:65`）；**"关 graph"不作允许手段**（关 = 改被测对象）；
2. 对照只用 **`--cuda-graph-trace` 两档**，且 **★ 两档必须同一种"展开语义"**（都展开 / 都只记节点）；**一档展开一档不展开 ⇒ 份额不同是预期的**，不构成"漏 kernel"；
3. **只报份额，不报 profiler 下的绝对时间**（profiler 改时序 ⇒ 其 tok/s 与墙钟不作性能结论）；
4. **两档份额中位差 ≤ 3 点 ⇒ 通过**；**> 3 点先查口径**（§4-2），确认同语义**才**判"漏 kernel"；
5. ★ **新增（来自本队已踩的坑）**：`nsys -o` 的**输出路径必须纯 ASCII**（旧坑：中文路径 ⇒ `std::range_error: bad conversion`，**两次失败**）；
6. ★ 交叉印证（沿用）：nsys 份额须与引擎机制计数**能对上故事**；**方向相反或量级差 >2× ⇒ 报"两者不可互证"**，不许单方面采信 nsys。

## §5 ★ ncu 采样的代表性（top-N 的**已知残差**必须写出来）
- **只采 top-N（N≤8）** ⇒ ★ **结论同一行必须给两个数字**：**① top-N 覆盖的份额和**（例：`top-8 覆盖 78%`）**② 未覆盖的份额 = 100% − ①，记为【已知残差】**；
- ★★ **不许**把"我采到的这些 kernel 里 X 最慢"写成"**全部时间都在这些 kernel 里**"（**抽样 ≠ 全量**）；
- ★★ **ncu 的时间不做份额**：ncu 会**重放/串行化 kernel**（改变时序）⇒ **份额一律取 nsys**；**ncu 只用于【单个 kernel 内部】的计数器**（SM 占用率 / 显存带宽利用率 / 是否 launch-bound）。

## §6 观测掩盖律（**不变**）
- **一切剖面不得新增同步点**（`dbg()` 的 `cudaStreamSynchronize` 就是前车之鉴，`engine.cpp:1814`）；
- ★ **若某手段【必须】改时序（例：ncu 的 kernel replay）⇒ 该手段在本靶【只可用于"单 kernel 内部计数器"，不可用于时间份额】；若要它出时间 ⇒ 作废**；
- **不许用"带观测的跑"证明"不带观测的跑"的行为**。

## §7 定级（★ 我建议**分两个标签写**，避免自相矛盾）
| 标签 | 含义 | 本次取值 |
|---|---|---|
| **读数等级** | 这个**数**是怎么来的 | **A**（本机实测，同一台机同一 exe） |
| **比较等级** | 这个**比较**可靠到什么程度 | **跨腿（L-N / L-Q / L-X）一律 `C`**（**不同模型 + 不同引擎版本** `eb5ef118` vs `a0116b27`）· **腿内同引擎重跑 = `B`** |
★ **为什么要分两个**：**等级是"数"的属性，推论可靠性是"比较"的属性** —— 不分就会写出"这个 A 级读数说明我们比它慢"这种越级结论（**结论强度不能超过证据**，总纲 §2）。
★ ★ **与本席 `回执\对拍判据-改口径-20261017.md` 的表述统一**：那里本席的口径"**读数 = A**"与本件一致；本件把**跨腿比较**单列为 **C** ⇒ **两件合起来 = 「读数 A / 比较 C」**（同一套口径）。
