# `moe_rows()` latent 几何 —— **完整性独立复核**（找"漏掉的"）

> 根因：`moe_rows()` 从未接 MoE 的 latent 几何（`exp_in/exp_out`=1024 vs `n_embd_`=4096）⇒ 越界读 `0xFF` ⇒ NaN。builder 已落 10+1 处。
> **本件只做【独立完整性复核】：不看那 11 条修了什么，而是把 `moe_rows()` 整个函数 + 它调到的辅助函数 + `moe()` 反向对扫一遍。**
> **只读 + 零 GPU + 未改码**。**AI：deepseek-flash[1m]** ⇒ **自验，不构成独立验收**。证据 **A** = 本机读源码。

---
## §0 ★ 判决一句话
> **对【当前两个模型】（Nemotron：latent + 非门控；Qwen3.8：非 latent + 门控）——`moe_rows()` 内【没有会出错的漏】。**
> 但复核出 **3 处"不是当前 bug、却是定时炸弹/该收口"的地方**：**① `moe_card()` 仍用 `n_embd_`**（对 latent+门控 会错，今天不可达）· **② `h_x_` 的步长约定在 `moe()` 与 `moe_rows()` 之间【不一致】**（今天靠 `in_w==out_w` 兜住）· **③ `:2394` 的 memset 是 over-broad**（合法，可不动）。

## §4 ★★ 反向扫描 `moe()` → `moe_rows()`：**发现一处"跨函数约定不一致"**
| 项 | `moe()`（非批路径） | `moe_rows()`（批路径） | 判 |
|---|---|---|---|
| 专家输入宽 | `in_w`（`:1902`） | `in_w`（`:2218`） | ✓ |
| 专家输出宽 | `out_w`（`:1903`） | `out_w`（`:2219`） | ✓ |
| `moe_out_` 清零 | `n * e_row`，`e_row = out_w`（`:1904/:1910`） | `n * out_w`（`:2226`） | ✓ 等价 |
| **`h_x_` 的行步长** | ★ **`e_row = out_w`**（`:1904`），取 `h_x_ + at*e_row`（`:2085`）；**但填充是 `copy2(..., n*in_w)`（`:1895`）⇒ 步长 in_w** | ★ **按 `in_w` 连续填/整块传**（`:2232/:2234/:2496`） | ★★ **只有 `in_w == out_w` 时两函数都自洽**；Nemotron 1024/1024 ✓、Qwen 2560/2560 ✓ ⇒ **今天无 bug**。**但这是隐式耦合**：若某模型 `exp_in ≠ exp_out`，**至少一个函数会读错行**。⇒ **报队长**（要么 `moe()` 改 `in_w` 步长，要么两处都写明"需 in_w==out_w"的断言） |
| `acc` 选择 | `latent_up ? moe_out_ : fo_`（`:1906`） | 同（`:2509`） | ✓ |
| CPU 输出 | `h_cpu_ + at*e_row`（`:2082`，e_row=out_w）· `axpy(..., n*out_w)`（`:2096`） | `h_cpu_`（整块）· `axpy(..., n*out_w)` | ✓（同 § 的 in/out 相等前提） |
| 尾部 | `moe_latent` 由外部调（`:2749/:2843`） | 同 | ✓ |

## §5 ★★ 给 builder 的**验证判据**（★ 一条最容易漏的）
> ★★ **5-token 的 canonical 不能验这个修复** —— 因为 `n < kStageRows(32)` ⇒ **走 `moe()` 非批路径**，**`moe_rows()` 根本不参与**。所以"5-token 逐位一致"**证明不了**修好了。
**建议三条（都能变红）**：
| # | 判据 | 变红条件 |
|---|---|---|
| **V1** | **同一 prompt（≥700 token）· `--prompt-batch 32`（批路径）vs `--prompt-batch 8`（非批路径）⇒ ids + `--top-probs` 逐位相同** | 有分歧 ⇒ **批/非批不等价 ⇒ 修复不完整**（★ 这条**不依赖旧 exe**，且**直指 `moe_rows` 与 `moe()` 的一致性**） |
| **V2** | `--prompt-batch 1024` 跑完整 prompt ⇒ **无 NaN/Inf**（输出不含 `nan`/`inf`）；输出行正常 | 出现 NaN ⇒ 仍有越界 |
| **V3（负控）** | 用**修前 exe** 跑同一条 ⇒ **必须 NaN/失败** | 修前也正常 ⇒ **该路径没被走到**（判据空转，须换 prompt 长度/`--prompt-batch`） |
★ 建议顺序：**V3 → V2 → V1**（先证明这条路径真的被走到）。
