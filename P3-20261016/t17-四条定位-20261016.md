## §2 ★ ④ 的诊断陷阱：为什么"日志里路径好看"会把人带向"权限问题"

引擎是 `main(int, char**)`（`main.cpp:809`）+ `fopen`（`engine.cpp:1697`）⇒ **不做宽字符/UTF-8 处理**（verifier 已列为其 (b) 条既有限制）。按这条推演一次编码往返：

```
.cmd 文件里的字节(UTF-8)  E8 A7 86 E9 A2 91   ← "视频"
   │ cmd.exe 在 CP936 下读 → 按 GBK 误解码
   ▼ 宽字符（已错）
   │ CreateProcess → 子进程 argv（宽）
   ▼ main(char**) 取 ANSI(CP936) 字节  →  又还原成 E8 A7 86 E9 A2 91
   ▼ fopen("E:\视频\…")  ← 这一串字节在 NTFS 上并不存在（真名是宽字符"视频"）
   ✗ 失败
   ▼ fprintf(stderr, "cannot write %s", path)  → 写进日志的又是那串 UTF-8 字节
读者用 UTF-8 打开日志 → 看到 "E:\视频\…" 完全正常
```

⇒ **打印出来正确 ≠ 传进来的正确**：往返把字节"还原"了，于是**日志是唯一会说谎的证据**。**判据必须看字节/看差分，不能看"像不像"**。
⇒ 这正是 verifier 警告的"**别按 t2 旧注（疑 `.tmp` 写法/路径权限）去改码**"的**机制层原因**：**照日志走，就会走到权限方向**。

**旁证（A）**：本席扫到 **8 个 log 全部报同一句**（`dump_cg_old/cgold/fix`、`dump_t3_fix`、`hookclean_reg`、`t13_regress`、`t5_regress`、`t5final_reg`），且 **`profile_p3.txt` 从未生成过** ⇒ 与 verifier 第 4 条独立吻合。
**另一处副作用（值得记）**：`EXIT=1` 是在**跑完之后**抛的（日志里位于各 dump 之后）⇒ **任何用 `%errorlevel%` 判"这跑成功"的脚本/CI 都会把本跑判失败**；`run_probe.cmd:14` 正是 `echo EXIT=%errorlevel%` ⇒ 复现时要区分"**读数有效但退出码非零**"。

## §3 负控实验设计：**2×2 矩阵**（verifier 的两条建议各只改一个因素，本件把它们拆开）

verifier 建议 ① 换成 **ASCII 路径**、② 把 `.cmd` 另存为 **GBK/ANSI**。**两条各改一个因素，但没给"哪个因素坏"的分离**。补一个 **2×2**（**四臂，每臂一次跑**）：

| 臂 | 脚本编码 | 路径内容 | 预言（若主因 = 传参编码） | 说明 |
|---|---|---|---|---|
| **A1** | UTF-8 | **中文** | ❌ **必失败**（现状） | 复现臂 = `run_probe.cmd` 现状 |
| **A2** | UTF-8 | **ASCII** | ✅ **应成功** | **≈ `run_e2e_opt.cmd` 已跑过的形状（§3.1）**；verifier 建议 ① |
| **A3** | GBK/ANSI | 中文 | ✅ **应成功** | verifier 建议 ② |
| **A4** | GBK/ANSI | ASCII | ✅ 必成功 | 正控（两因素都干净） |

- **判据（能变红）**：**A1 必失败**（否则整个假设被证伪）；**A2 与 A3 的成功会分别坐实"路径内容"与"脚本编码"两条**；**若 A2/A3 仍失败 ⇒ 主因不在脚手架编码**（回到引擎侧查）。
- **分辨率**：判"成功" = `profile_p3.txt` **存在** 且内容为 **`层 专家 次数` 三列**（`engine.cpp:1701` 格式）；判"失败" = 日志出现 `cannot write … .tmp`。
- **⚠ 跑法纪律**（`KP-UNI-0191`）：**改完 `.cmd` 存盘 → 另起一次跑**，绝不边跑边改。
