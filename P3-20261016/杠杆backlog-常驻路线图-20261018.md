## G. ★ 老师 decode 的历史基准（2026-10-18 01:40 挖到的，A 级，零 GPU）

> 出处：`情报-H-老师decode历史读数-20261018.md`；**没跑任何 GPU**（决策记录：有历史信息，不跑 GPU）。

| 口径 | 老师 3.8-Flash / IQ3_S（本机 4080S） | 对 B3=25.23 | 对 B0=14.25 |
|---|---|---|---|
| 最权威单条：`E:\strata\_staging\dec-pool2.txt:79`（200 tok / 1847.9 ms） | **108.23 tok/s** | **4.29×** | 7.59× |
| 221 条同机日志中位 | **122.58 tok/s** | **4.86×** | 8.60× |
| 区间（p25–p75 / 最好） | 116.8–125.3 / 141.80 | 4.6–5.0× / 5.6× | — |

**差距拆解**：`dec-pool2` = **76 轮 / 1847.9 ms = 24.314 ms/轮 × 2.63 token/轮**。
⇒ 老师 108 tok/s = **低轮时 + 高投机兑现**；我方 B3（25.23）**每轮只兑现 ~1.5 token**。
⇒ **decode 两个主攻方向**：① **tokens/round**（投机：`--window` / `--lookup` / MTP，**无损**）② **每轮时间**（CPU 工作量=命中率、线程放置、pcie 分流）。

**口径警告（照抄 scout-b）**：老师历史跑**全部带 MTP/投机（spec 4–6）**；我方 B3/B0 是 `--no-draft --lookup 0`，**不是同源**；8/45/64-token 短跑被首 token + graph 捕获 + swap ramp 主导，不可比；跨卡/跨版本不混。
**反证**：我们自己复跑原厂 0.1.43.1 只有 **61.91 tok/s**（`C:\sp3\q38_perf.log:54`，投机只兑现 1.12 tok/轮）⇒ 老师的 108 不是"默认就有"，是特定配置达成的。
**同机指纹（C）**：社区 4080S IQ3_S = 95–122；**"0 MiB free 悬崖"13.7 tok/s**（← 这条直接支持我们的 R21 显存余量纪律）。

## H. ★★ MTP 官方口径（2026-10-18，联网调研，来源件 `情报-I-Nemotron3.5-MTP官方口径-20261018.md`）

### H.1 官方原文引用（带 URL）
- **NIM 模型卡**：*"Multi-Token Prediction (MTP) **enables native speculative decoding**"*；Model Summary = **"Native MTP"**
  `https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3_5-super-vl-120b-a12b`
- **NVIDIA 技术博客**：*"MTP gives … an **internal drafter that proposes several tokens** for the main model to verify in one forward pass"* + *"A dedicated **MTP-boosting training phase** further aligned the drafter with the final model"*
  `https://developer.nvidia.com/blog/nvidia-nemotron-3-5-super-vl-powers-specialized-agents-with-multimodal-reasoning`
- ⚠️ **归因更正**：同页 "**up to 2.3× faster token generation**" 属 **LiLiCorr**（DGX Spark 推荐 drafter），**不是 MTP 的数字**；**官方没有公开 MTP 单独的加速比/接受率**。

### H.2 结构（A 级，官方 + 本地 GGUF 同构）
**1 个 MTP 头 + 递归链式**（不是并行多头）。NeMo：*"single, recursively shared MTP head（从 Nemotron 3 Super Base 两个头里取第一个、第二个丢弃）"* + **hidden-state mixing**（暴露于自己 drafted states）降低 recursive drafting 的 train–infer mismatch。
`https://docs.nvidia.com/nemotron/latest/nemotron/super35/pretrain.html`
本地 GGUF 完全同构：`nextn_predict_layers=1`、`blk.88` = 4 个 nextn 张量 + 整层 attention/MoE。

### H.3 官方推荐深度
| 来源 | 配置 | 出处 |
|---|---|---|
| SGLang cookbook（低延迟） | EAGLE MTP **top-k 1 / 3 steps / 4 draft tokens**；高吞吐 MTP off | `https://docs.sglang.io/cookbook/autoregressive/NVIDIA/Nemotron3.5-Super` |
| SGLang blog / NVIDIA cookbook | **5 steps / 6 draft tokens**（同 checkpoint 作 drafter），243.9 tok/s on RTX PRO 6000 | `https://www.lmsys.org/blog/2026-10-15-nvidia-nemotron-3-5-super-vl/` |
| **Unsloth（我们这份 GGUF 的出处）** | `--spec-draft-n-max 2` 起步、**1–6 扫**；GGUF **1.4–2.2×** | `https://unsloth.ai/docs/models/mtp` |

### H.4 我们 vs 官方 —— **MTP 被自己的代码常数掐住**
| 项 | 官方/实践 | 我们 |
|---|---|---|
| draft 链深 | **4–6** | **≤3**（`kBlockWindow=4` 硬卡，`main.cpp:64-66/:455`） |
| 验证窗 | 5 steps / 6 draft | `--window` 自动 8，但 `most=min(window,kMaxT=8)`；链只有 3 |
| 实测加速 | Unsloth 同款 GGUF **1.4–2.2×** | **+51%**（B1 21.31 vs 14.10） |
| MTP 状态 | — | 交付配置**关着**（`--no-draft --lookup 0`） |

⇒ **"`--window 8` 只 +1.2%" 的假说解释：链上限 3，窗口再大也吃不到**（未验）。

### H.5 三档路线
- **零改码**：开 `--draft`、扫 `--window 4/8`、`--lookup 0` ⇒ **先量兑现率**（`DONE` 行 `drafts accepted/offered`、`tokens/round=generated/reused`）
- **小改（Compile #2，一次编译）**：**`kBlockWindow` 4 → 可配 5–7**（对齐官方 4–6 / Unsloth 1–6）+ DONE 行**按 draft 深度报接受率** + 链深/验证窗拆名
- **大改（以后）**：EAGLE top-k>1 树 · 接受率自适应深度（现有 Guesses 框架可扩）· 深窗 Mamba 快照 rollback（官方 blog 明说 Mamba checkpoints 减少 replay；我们 `kSnapPlaces=3`）

**未验**：官方 MTP 单独数字没有；3.5 技术报告 "link pending publication"（直链 404）；HF `config.json` 未直接取到（`num_nextn_predict_layers=1` 仅由本地 GGUF 确认）；NIM/TRT-LLM 对该型号默认 draft 深度未查到。
