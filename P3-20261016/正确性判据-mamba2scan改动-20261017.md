# `mamba2_scan` 改动的**正确性判据**（① state→shared 用一套 · ② 切维/分块用另一套 · **不许混**）

> 靶子：`mamba2_scan_kernel` 占 prefill **67.9%**（1163/1896 ms，队长实测）。① = **state 从 global 搬进 shared**（已批）；② = **d_state 维切线程 / chunked scan**（后手）。
> **只读 + 零 GPU + 未改码**。**AI：deepseek-flash[1m]** ⇒ **自验，不构成独立验收**。证据 **A** = 本机读源码。

---
## §0 ★ 先把"算术顺序"钉死（A，读码 `PolyStrata\src\poly\kernels.cu:2546-2586`）
```text
h = blockIdx.x（128 个头）; i1 = threadIdx.x（< head_dim=64）; ii = h*head_dim + i1
sp = s + ii*d_state                       // :2558  ← ① 要动的就是这句
for (t = 0; t < rows; ++t) {              // 跨 token 串行
    thread0 算 sdt/sdA（:2562-2566）; 全员填 sB/sC（:2567-2570，strided）; __syncthreads(); // :2571
    for (st = 0; st < d_state; ++st) {    // :2574  ← 单个线程内的升序累加
        state = sp[st]*sdA + sB[st]*x_dt; sumf += state*sC[st]; sp[st] = state;   // :2575-2577
    }
    snap 写回（:2579-2582）; y 写出（:2583）; __syncthreads();                     // :2584
}
```
★★ **关键结论（支撑"① 应逐位一致"）**：**`sp[st]` 只被【拥有 ii 的那个线程】读写**（`ii = h*head_dim + i1` 与线程一一对应）⇒ **①（global→shared）只改【存储位置】，不改【运算次序、精度、参与项】** ⇒ **逐位一致是【可证伪的强预期】，不是"大概"** ✓（队长判断成立，本席独立读码确认）。
★ **但**：**① 的 shared 用量 = 64 线程 × `d_state`(128) × 4 B = 32 KiB/块**（＋`sB/sC`）⇒ ★ **可能压 occupancy** ⇒ **"kernel 变快"不是自动的**（见 §3 总口径）。

---
## §1 【① 用】"不许变"判据（**能变红**）
### 1.1 参照物（**写死，缺一即不成立**）
| 项 | 值 |
|---|---|
| 基线 exe | **旧 sha `978d64bc…`**（★ 两跑都要**再核一次 sha 并写进 log 头**；总纲 §6：**sha 一变，绑旧 sha 的读数全部作废**） |
| 新 exe | ① 改完的 sha（同上核 + 记录） |
| 跑法 | **canonical**：`--prompt-batch 1024 --stage-ahead 128 --stage-mib 48` + **冻结 profile**（每跑前 `cp` 母本）+ `--no-draft --lookup 0` |
| prompt | **同一份**（`tok700.txt`，prompt sha 同）；同 `--max-new`；**greedy** |
| **不带** | **`--dump-layers`**（观测掩盖律） |

### 1.2 判据（两条，缺一不可）
| # | 判据 | 门 | 变红条件 |
|---|---|---|---|
| **P1** | **token ids 逐位相同** | 比**共同前缀**（长度/停止点漂**单列**、按既有口径**不计违反**） | 有共同前缀分歧 ⇒ **FAIL** |
| **P2** | ★ **`--top-probs` 逐位相同（浮点级）** | **逐位**（打印分辨率内） | 有分歧 ⇒ **FAIL**（★ **只比 id 会漏"末位漂未翻 id"**，这是既有纪律） |

### 1.3 ★★ 负控（**必须先证明这套判据有鉴别力**）
| # | 对照 | 预期 | 判 |
|---|---|---|---|
| **N-A（主负控，保证可变红）** | **故意改坏**：把 `:2576` 的累加循环改成 `st < d_state - 1`（**少加一个 st 分量**）或漏掉一次 `sp[st]` 更新 | 相对误差 ~1/128 ⇒ **P1/P2 必须报红** | ★ **若它"判相同" ⇒ 判本套判据【无鉴别力】** ⇒ 换 §1.4 的更细比法 |
| **N-B（分辨率探针，**不是**失效判据）** | 把累加**改序**（`for (st = d_state-1; st >= 0; --st)`） | **只改 ULP**，**很可能在打印分辨率下看不出** | ★ **N-B 若"判相同"⇒ 判"打印分辨率不足以判这类改动"**（**不是**判据失效）⇒ 走 §1.4 |
★ **N-A 与 N-B 的区别必须写清**：**"判据失效"只在 N-A 不红时成立**；N-B 不红是**预期**（分辨率问题），**别混**。

### 1.4 ★ 更细的比法（**当 P1/P2 分辨率不够时用**）
**kernel 级对拍**：**只跑这一层/kernel**，把输出 `y` 与**状态 `s`** D2H 后 **`memcmp`/逐位比较**（旧 exe vs 新 exe）。
- ★ **与端到端跑法【分开】**：读回要同步，**但那是"对拍专用跑"**，**不用于任何性能结论** ⇒ **不违观测掩盖律**（该律禁止的是"用带观测的跑去证明不带观测的跑的行为"）；
- ★ **它的用途只有一个**：判"① 是否真的逐位不变"（**P1/P2 看不出的层级**）；
- ★ **不许**用 `--dump-layers` 当"更细比法"来证 ①（它每层加同步 ⇒ 改时序）；`--dump-layers` 只在 §2 的**逐层界**里当**辅助证据**。

## §2 【② 用】"允许变但要有界"判据
### 2.1 允许变的**理由**（写进结论）
②（d_state 维切线程 / chunked scan）**会改累加/结合顺序** ⇒ **位级必变**（不是缺陷）。
### 2.2 三层门（**从硬到软**）
| # | 判据 | 门 | 变红条件 |
|---|---|---|---|
| **Q1（硬）** | **多 token 端到端 ids 逐位相同** | 同 §1.2 的口径（共同前缀） | ★ **ids 变了 ⇒ 判 FAIL**，**不许用"只是末位漂"糊过去** |
| **Q2（浮点）** | **`--top-probs` 前 N 位相同** | 我们的打印是 **6 位有效数字** ⇒ **只允许【最后一位的 ±1】**（"末位漂"的严格定义）；**≥2 位差 ⇒ FAIL** | 超 ⇒ **FAIL** |
| **Q3（逐层，辅助）** | `--dump-layers` 下**逐层** `rel = \|Δ\| / max\|ref\|` | ★ **口径写全**（逐通道 or 整张量 / Σ or abs —— `abs(L1)` 不许用于闭合）；**预期量级**：128 项求和重排 ⇒ `~n·eps ≈ 128×6e-8 ≈ **8e-6**` ⇒ **门取 `1e-5`** | `>1e-5 且 <1%` ⇒ 判"**超出预期但非错误**"（单列 + 找原因）· **`>1%` ⇒ 判 FAIL**（**那是写错了，不是"顺序变了"**） |
★ ★ **Q3 的地位**：**辅助证据**（带 dump 的跑**不能**用来证明不带 dump 的跑的行为）⇒ **主判据仍是 Q1 + Q2**。

### 2.3 负控（**能变红**）
- ★ **若 ids 变 ⇒ FAIL**（唯一出口是 §5 的"人判"，不许自动放行）；
- ★ **§1.3 的 N-A（故意改坏）必须让 Q1/Q2 也变红**（同一套判据要能红）；
- ★ **Q3 的自证**：**故意把某层的 `rel` 抬到 1e-3** ⇒ Q3 必须报"超出预期"。

## §3 ★ 总口径：**"kernel 变快但端到端变慢"也算失败**
| # | 判据 | 门 | 变红条件 |
|---|---|---|---|
| **E1** | **端到端 prefill 中位（新）** | **≥ 旧 − `s_round`**（`s_round = 1.4826·MAD/median`，**≥3 跑 + 弃预热**） | **在噪声内【下降】⇒ 判失败** |
| **E2** | **端到端 decode 中位（新）** | 同上 | 同上 |
| **E3** | **必须同报**：端到端 prefill/decode（中位+MAD+极差+长度+`finish`）· **nsys 的 kernel 份额**（★ **只报份额、不报 profiler 绝对时间**）· 机制读数（命中/arena/`--prompt-batch`/是否 `--dump`） | 缺项 ⇒ **读数退回** | — |
| **E4 ★** | **读数链自检**：若 **kernel 份额显著降（≥10 点）而端到端【没变】/变慢** | —— | ⇒ 判"**读数链不通**"（份额口径错 或 该 kernel 不是关键路径）⇒ **必须查，不许写"优化成功"** |
★ **禁止**用 nsys 的 kernel 时间说"变快了"（profiler 改时序）⇒ **份额只作解释**。
★ **① 的专项提醒**：**若端到端没变快，先查 occupancy**（32 KiB shared/块，§0）⇒ **不许直接判"① 没用"**。

## §4 一句话总判据（**给 builder 的最小执行卡**）
```
① 改完：核两版 exe sha → 同 canonical 跑（冻结 profile、不带 dump）
        → P1 ids 逐位 · P2 top-probs 逐位  ⇒ 都同 ⇒ 通过
        → N-A（少加一项）必须让 P1/P2 变红  ⇒ 不红 ⇒ 判据无鉴别力、升级 §1.4 kernel 级 memcmp
        → E1/E2 端到端不得在 s_round 内下降
② 改完：Q1 ids 逐位（硬）→ Q2 top-probs 允许"末位 ±1" → Q3 逐层 rel ≤ 1e-5（>1% ⇒ FAIL）
        → E1/E2/E3/E4 同上
```

## §5 未验 / 边界
- **零 GPU、未跑**：本件是**判据**；§0 的"逐位一致"是**读码推得**（A），**未实测** ⇒ **P1/P2 就是它的实测**。
- **我未核**：① 的**实现方式**（shared 数组的声明与下标；`snap` 是否也从 shared 写）⇒ **这几处若动错，N-A 之外还可能出现"只在有 snap 的 token 上错"** ⇒ ★ **建议 P1/P2 的 prompt 覆盖到 snap 写回点**（即选一个**会触发 `snap_of()`** 的长度档）。
- **我未核**：② 的**具体切法**（d_state 切线程时跨线程归约的顺序未知）⇒ **`8e-6` 的预期量级可能偏大或偏小** ⇒ 首轮后按实测收紧（**改动留痕**）。
- **我未核**：`--top-probs` 的实际打印位数（**6 位有效数字**是既有读数；若实际更少 ⇒ Q2 的门要放宽并写明）。
- **C**：`67.9%`（1163/1896 ms）来自队长/nsys，**我未见原始剖面**。
