# 回执 · 情报-L：CPU 专家腿有效带宽为什么只有 ~21.4 GB/s（2026-10-18）

## 1. 任务
lead 追加（零 GPU）：① 读码回答 CPU 专家计算的访存模式（连续/分行/切分/线程归属/prefetch/每线程字节）；② 判定专家数据在宿主端的内存类型（VirtualAlloc+VirtualLock / 文件映射 / malloc）；③ 对照老师 `expert_source.cpp`/`kernels/cpu/*` 的 CPU 读法；④ 给 ≤3 条可能把 21.4 GB/s 抬上去的可执行改动（改哪/预计/风险/判红）。背景读数：`miss/token=496.7 × 144.7 µs` = 71.9 ms/token，反推 `3,096,576 B ÷ 144.7 µs ≈ 21.4 GB/s`。

## 2. 状态
**达成**（四问全答 + 3 条改动 + 判红）。零 GPU、零编译、不改码、未 spawn 子代理；只读 `PolyStrata` 与 `E:\strata`；只写本回执与详细件。

## 3. 结论（一句话）
**21.4 GB/s 大概率不是"DDR5 只用 1/3"的纯带宽读数**：① `144.7 µs/miss` 若取自 `cpu_us/miss`（CPU 腿**墙钟**）会把该层 GPU launch/交接算进去（另有 `cpu_busy = wall − launch_ms` 才是纯 CPU）；② 本机 **i7-13790F 16 物理/24 逻辑**，`--threads 24` 且默认 `--host-core off` 时**一条线程都不钉**，24 线程压 16 核、与 P 核超线程互抢；③ 访存是"3 段连续 blob、按行块（32/16 行）跨专家并行"，但每行一次间接 `vec_dot`、无 prefetch/unroll、AVX2-only。内存类型是 **GGUF 文件映射 + cudaHostRegister(ReadOnly)**，但 pin 只 3 ms / RAM free 不变 ⇒ 页未在注册时全部锁定，读的是 page-cache 文件页（第二种解释，未验）。

## 5. 三条可执行改动 + 最可能一条
1. **零改码分口径**：读 `cpu_busy_us/miss` vs `cpu_us/miss`（`main.cpp:786,792`）；`busy≪wall` ⇒ 21.4 是假口径（launch/交接投影），改法=重叠而非访存；判红：两行差 <10%。
2. **worker 只钉物理核 + 按物理核数定线程**（~40 行：`threads.hpp:231-234` 改物理核、`engine.cpp:1646` 默认取物理核数）。预计聚合 21.4→40–60 GB/s、CPU 腿 71.9→~30–40 ms/token、decode 13.36→~22–28 tok/s（D）；只挪线程零精度风险；判红 ids 漂/`cpu_busy` 不降。
3. **连续长流 + 多行 unroll + `_mm_prefetch`**（~60–100 行，`cpu_experts.cpp`：任务改全局行区间跨专家、粒度 32→64/96、内层 4 行 unroll+prefetch），照老师 `pool.cpp:383-419` + `expert.cpp:484/494`；预计单线程 +20–50%；判红 ids/`--top-probs` 漂或 `cpu_busy` 不降。
**最可能 = 改动 2**：证据最硬（A 级拓扑/代码 + C 级老师注释/实现）、改动小、零数值风险；但**必须先做改动 1**——若 busy≪wall，则最大杠杆变成"把 launch/交接移出 CPU 腿"。

## 6. 未验 / 边界
- **U1**：lead 的 144.7 µs 取自 `cpu_us/miss`（wall）还是 `cpu_busy_us/miss`——树里两行都有，盘上无法判（需那次跑的输出）。
- **U2**：59 GiB 专家页是否真正常驻：判别法 ① 首 token vs 稳态 `cpu_us/miss`（首 token 高 ⇒ 缺页/首次触页）；② 进程 WS 与系统可用内存（`GetProcessMemoryInfo`）。
- **U3**：本机 DDR5 实收带宽与单核流式上限未测（需一次 CPU 内存基准，非 GPU 作业）。
- **U4**：那次 alt-prompt 跑的 `--threads` 实际值未知（计划 §0 未写命令行）。
- **U5**：老师 `36.32 GB/s` 是 6 核开发机数字（`pool.hpp:80-82`），不是本机读数。
