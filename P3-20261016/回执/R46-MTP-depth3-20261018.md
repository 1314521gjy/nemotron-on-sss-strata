## 3. 为什么 depth 固定了还不确定（新发现）

- **窗口深度确实固定**：每轮 offered 恒 3（105/35、114/38 都是 3.0）——`Guesses` 的 det 分支 + `use.t=1+n_d` 生效。
- **但每轮被接受数仍变**（93 vs 90、轮数 35 vs 38）⇒ **draft 给出的 guesses 或 window 的数值路径 run-to-run 不同** ⇒ ids 漂 86/128。
- swap=0 已排除自适应层；剩余候选非确定性源（需另立隔离实验，不在本批）：
  1. **draft 块自身的 GPU 路径**（`Engine::draft()` → `draft_input`/`draft_step`/`likeliest`，含 host routing 与两次 stream 同步）；
  2. **window batch 的 GPU 累加**（`add_scaled`/`kSumRows` 的求和顺序、或 batched mmvq 在 count>1 时的归约顺序）；
  3. `hn_` 里"ahead"优化（`draft_rows(..., first=1/0)`）虽然由 token 决定，但它依赖上一轮的 `ahead_pos_/ahead_tok_`，若轮数变化会改变后续路径。
- ⇒ **"确定性窗口"只解决了窗口深度，MTP 的数值路径仍有非确定性**；要交付必须另行逐项隔离（成本高、收益已证不足 5%）。

## 5. 结论与建议（按 lead 预设执行）

1. **MTP 收口为 opt-in**（今天不再追）：交付锁定 **`sp_donly.exe` + `--threads 16` + `--no-draft --lookup 3`**（alt +28% / 交付形态 +17.7%，ids 逐位同）。
2. `--draft-vocab` / `STRATA_DET_WINDOW` 保留为 opt-in 开关（默认关/交付用 `--no-draft`），**零风险**；相关代码与实验（R39–R46）已留档。
3. 若以后重启 MTP 线，第一步应是**隔离"window/draft 数值路径的非确定性"**（用 `STRATA_PROBE_*` 已有打点：xq 输入、G/H/D 阶段、nd_acc），而不是继续调窗口参数。
