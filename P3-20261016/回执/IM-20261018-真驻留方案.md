# 回执 · 情报M："真驻留/真锁页"方案（2026-10-18）

## 1. 任务
lead 派专项（当前最大杠杆一号候选）：① 现状判定（专家 blob 是文件映射还是别的；`cudaHostRegister` 后 Windows 页表状态；mapper 预热范围；给"能判红"的常驻/不常驻判定）② 三候选实现（全量预触页 / 真锁页 / 只预热非驻留 45.7GB），每条给改哪/预计/代价/风险/验证/判红 ③ 一句结论：哪条最可能把 21–23 GB/s 抬到 40–60 GB/s 及为什么。**零 GPU、零编译、不改码**；`file:line`；区分读码/实测；不许 spawn。

## 2. 状态
**达成（3/3），但结论与 lead 前提相反（有 A 级实测支撑）**：现状判定完成；三候选均给出并可判红；结论=**三候选都到不了 40–60 GB/s**，因为页**已经**驻留、预触页臂已实测 0 收益，卡点是 CPU 专家腿的线程/内核效率。

## 3. 结论（一句话）
**专家页 = GGUF 文件映射页（`CreateFileMappingA+MapViewOfFile`，`gguf_reader.hpp:397-415`）；`cudaHostRegisterReadOnly` 只是整层 DMA 注册（`engine.cpp:1039-1047`），3 ms 锁不了 15.5M 页、RAM 不降即证；而 `map_pages()` 早在加载时就逐 4KB 页 touch 全部 63.42 GB 专家映射（`engine.cpp:163-179`，注释即 21.0 vs 11.0 ms/token 缺页教训）——**"全量预触页"已是现状**；R34 驱动实测运行期工作集峰值 **67,101 MB≈65.5 GiB**（avail 17.1 GB）⇒ 页确实驻留；团队 R34-P8 预触页臂 **15.83 tok/s / 103.2 µs vs 同线程 T8a/T8b 16.25/16.66 / 100.1/96.3** ⇒ 预触页 0（负）收益；poly 全量 grep `VirtualLock/SetProcessWorkingSetSizeEx/QUOTA_LIMITS`=0 命中，所以"未锁"属实但未造成可观测代价。**21–23 GB/s 是 T24 线程的 bad case；T8b 已是 32.2 GB/s；8→12→16 线程平台化（100.1/99.6/99.5 µs）⇒ 卡点是每线程有效算力（≈110–114 GFLOPS），到 40/60 需 ~142/214 GFLOPS，只能靠 CPU 专家内核提速或 pcie-frac 移专家到 GPU，不是驻留/锁页。最值得先做的是 `--threads 8–12`：13.36→16.27–16.66 tok/s（+22–25%），ids 与 T24a 逐位相同（329 B 全 True）。**

## 4. 证据（要点）
- **映射（A 读码）**：`CreateFileA` → `CreateFileMappingA(PAGE_READONLY)` → `MapViewOfFile(FILE_MAP_READ)`（`include\strata\artifact\gguf_reader.hpp:397-415`；POSIX `mmap` :423）。poly 只 include `artifact/gguf_reader.hpp`，无自己的文件读路径。
- **pin（A 读码+实测）**：`cudaHostRegisterReadOnly` 按整层，目的 DMA 直读映射（`engine.cpp:1009-1012` 注释；调用 `:1040-1047`）；R28-A3:82 `pinned 40 layers (59.06 GiB) … RAM 76.4→76.4 GiB free; took 2 ms` ⇒ 无逐页锁/无 commit（15.5M 页即便 0.1 µs/页也要 1.55 s）。
- **全量预触页（A 读码）**：spans=每 MoE 层 gate/up/down 全量（`:1648-1654`）→ 后台线程 `map_pages`（`:1675-1678`，`:169-179` 逐 4 KB 页读 1 byte；注释 `:163-168` 自述动机与"100 GiB/4 s"标定）。
- **运行期驻留（A 实测）**：`C:\sp3\R34-*`（团队 08:40–08:47 跑，驱动 `run_R34_all.ps1` 每 0.9 s 采 WS）：8 臂 WS 峰值 66,928–67,104 MB、avail 最低 17,076 MB；全部臂 ids 与 T24a 逐位相同。
- **预触页臂（A 实测）**：P8（先整文件预读 70 GB 再跑，threads 8）15.83 tok/s / 103.2 µs；T8a 16.25/100.1；T8b 16.66/96.3。
- **线程拓扑（A 实测）**：T24a 156.6 µs/10.41 tok/s；T24b 136.1/12.32；T8a 100.1/16.25；T8b 96.3/16.66；T12 99.6/16.27；T16 99.5/16.23；T6 106.9/15.34。
- **系统只读（A）**：无进程时 FreePhysical 85.5 GiB；`Standby Cache Normal=71,612.8 MiB`、`Reserve=6,070.3 MiB`、`Modified=152 MiB`；`\Memory\Cache Bytes=406 MiB`（无进程时）。
- **缺页算术（A 实测+D 推算）**：每 miss 3.0966 MB=756 页；逐页 fault 即使 0.5 µs/页 = 0.38 ms ≫ 96–157 µs ⇒ 不可能是每 miss 逐页 fault。
- **三候选**：C1 强化 `map_pages`（PrefetchVirtualMemory+多线程+日志，25–35 行，+0–11 s，0–3%，P8 已判红）；C2 `SetProcessWorkingSetSizeEx+VirtualLock`（40–60 行，锁 63–67 GB，风险大，0–5%，不推荐）；C3 只预热非驻留 14,759×3.0966 MB=**45.7 GB**（逐专家切片 spans，30–50 行，省启动 0.7–3 s/省 17.7 GB cache，**0% 提速**，要押就押它）。
