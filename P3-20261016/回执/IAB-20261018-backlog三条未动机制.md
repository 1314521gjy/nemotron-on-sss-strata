## 3. 结论（一句话）
**三条本体今天都不值得做（预期收益 0，前提不成立）：#3 只作用于"resident RAM 紧凑副本"模式（消除的是"换出专家 memcpy 回 RAM 副本"——我们 pin 的是整个 GHUF mmap，换出专家无需写回，这次拷贝在我们架构里不存在）；#4 只作用于"device residency table + 异步 adaptive tier"（我们 decode 无 device 表；swap 槽指针只在 event 落地后发布，host/device 不会不一致；#4 本身还是正确性修复，hook −1.1%，不是提速）；#5 只作用于"RAM 装不下全集"的低内存 resident 模式（96 GB、专家集 63.4 GB 全在 RAM，pin 整个映射 59.06 GiB、0 refused；CPU 腿是算力/线程受限而非 RAM 缺页）。**唯一值得今天做的是 #3 的本机变体 `#3′`：`follow_loop`（`engine.cpp:1926-1958`）对已 pin 层把"memcpy 进 `s->pinned` 再 H2D（`:1941-1944`）"改成"直接从 pinned 映射 `cudaMemcpyAsync` 进 VRAM"（与 prefill `stage()` 的 pin 分支 `:3317-3323` 同一机制）；~20–30 行、位精确（同一段字节）、预期 D 级 0–6%（按 R43/R44 约 16 swap/token ≈ 省 50 MB/token host memcpy ≈ 2.5 ms/token @20 GB/s）；swap 少的臂≈0。** 另：**老师 0.1.40.2 的 dec-pool2 run 也没有这三条**（T 树 grep 全 0；它用 expert arena 模式，arena 无 exchange/RAM move），三条对老师 24.3 ms/round 的账无贡献。**
