# 回执 · 情报-AK：老师的 KV 进内存 + 流式读取机制（2026-10-18）

## 1. 任务
需求记录（2026-10-18）：老师这边有专门的 KV 进内存和读取机制，不是每次读这么多。lead 初查：老师树有 `kv_stream.hpp/.cu`、`kv_q4/kv_q8`、`kv_stream_parity`、一串 `STRATA_KV_*` 旗标；我们树也编进了 `strata_kernels` 但从没启用；我们 `nemotronhmoe.hpp:61` 是朴素 `uint16_t* keys`。要查清：A 机制（KV 存哪/怎么进 VRAM/一次搬多少/prefetch/量化/各旗标/是否只对滑窗有效）；B 我们树里给谁用、nemotron 有没有接、接上去多少行；C 对 16K/128K/1M 的价值；D 判决。

## 2. 状态
**达成**（A–D 全答）。零 GPU、零编译、不改码、未 spawn 子代理；只读本机三棵老师树（`E:\strata` 0.1.20、`E:\strata-v01431` 0.1.43.1、`upstream-0.1.44.1`）+ 我们的 `PolyStrata` + `E:\llama-cpp-pin`。

## 3. 结论（一句话）
**这套机制是"QSA 稀疏注意力"的配套设施，不是 prefetch 魔法**：权威 K/V 放 **pinned + UVA host 内存**；VRAM 只放 `n_slots` 个 **page（=4 cells=1 个 indexer block）**，`page_table` 变驻留图；decode 前 `kv_stream_resolve` 只把**被 indexer 选中的 block 里未驻留的那些**从 host 拷进 VRAM（每 query 只选 **≤2,051 cells**，与上下文长度无关，靠 `idx_top_k=2048/idx_block=4`）。**Nemotron 的 8 层 attn 是稠密全注意力（GGUF 无 sliding_window/swa、无 indexer）⇒ 每 token 必须读全部 KV（8 KiB/token；16K=128 MiB、128K=1 GiB、1M=8 GiB）⇒ 这套机制对"少读"无效**。我们树里代码只是 QSA 产品线的遗产（`strata_kernels` 里编着，`src/poly` 0 命中，nemotron 没接）。**判决：不能用（对 Nemotron）；16K 不值得；128K/1M 只有 KV 量化（容量）有价值；流式化=白做；KV 量化 ≈200–400 行 + parity。**

## 5. 对我们的价值（16K / 128K / 1M）
- 我们的 KV：`1,024 B/层/token`（2 KV heads×128×2×2B），8 层 ⇒ **8 KiB/token**；**16K=128 MiB、128K=1 GiB、1M=8 GiB**。
- 稠密全注意力**每 token 读全部 KV**：VRAM 736 GB/s ⇒ 0.17/1.4/10.9 ms；PCIe 26 GB/s ⇒ **4.9/40/315 ms/token**。
- **16K**：流式省 128 MiB（≈0.7% 缓存）却多 4.9 ms/token（+7.4% 墙）⇒ **不用**；q8/q4 也只省 0.36%/0.54% 缓存 ⇒ **不用**。
- **128K**：流式 **40 ms/token**（≈60% 墙）⇒ **不可行**；q8 省 512 MiB≈169 slot(3.0%)、q4 省 768 MiB≈253 slot(4.4%) ⇒ **量化可选（低优先）**。
- **1M**：流式 **315 ms/token** ⇒ 不可行；q8 4 GiB≈1322 slot(23%)、q4 6 GiB≈1983 slot(35%) ⇒ **量化是唯一容量手段**（但 1M 非当前交付目标；全注意力 1M 还有算力/其它缓冲墙，未实测）。

## 6. 判决（用/不用/行数）
| 项 | 判决 |
|---|---|
| QSA 流式机制（老师原版） | **不能用**：依赖 indexer selection，Nemotron 没有；`resolve` 的 `ids/steps` 无输入。 |
| 16K 流式化 | **不用**：省 0.7% 缓存 vs +7.4% 墙。 |
| 128K/1M 流式化 | **不用**：PCIe 40/315 ms/token，引擎不可用。 |
| KV 量化（对我们 dense 8 层） | **128K+ 才有价值**；≈**200–400 行**（读 code+scale→fp16 scratch；q4 需 FWHT 旋转）+ parity/精度门；参考实现：llama.cpp `params.type_k/type_v`（量化 V 需 flash-attn，`E:\llama-cpp-pin\src\llama-context.cpp:388-389,3727-3756`）。当前交付 16K ⇒ 暂不做。 |
| MTP drafter 的 ring | 老师现成；我们 MTP 块 KV 按 `max_context` 分配（16 MiB@16K）但只读 window cells ⇒ ring 可省 ~16 MiB（5 slot），**~50 行**，收益小。 |
- **总判决**：**这套东西对 Nemotron 的 KV 问题基本不适用**；我们真正该做（若做长上下文）是 **KV 量化**，不是流式；16K 现状什么都不用做。
