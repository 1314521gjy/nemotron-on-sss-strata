> **⚠️ 追记（R11，2026-10-17 深夜）：本文有两处结论已被 R11 对账推翻，保留原文不删，在此留指针 ——**
> 1. **"1.54× 隐藏重复副本"是伪影**：多出的 14,418 次 = load 期专家填充 11,402 次（17.65 GB，`engine.cpp:1141-1144`/`:1297-1300`）+ decode 段整帧 swap 2,174 次（6.73 GB，`:1342`）+ load 权重上传 764 次 + 78 次舍入。prefill 窗口内真实副本 = **29,210 次 / 45.23 GB ≈ 引擎自印 29,132 / 45.10 GB（差 0.3%）**。
> 2. **"nsys 开销 +21.3%"是窗口算错**：本文的 4.638 s 窗口把 load 填充期也算进去了；真实 prefill 窗口 **3.631 s**（11.862–15.493 s），vs 无 nsys 对照 3.825 s ⇒ nsys 开销 ≈ **−5%（噪声内，未测出正开销）**。
> 3. 真实重叠率不是 61.4% 而是 **85.2%**（副本 1.952 s 里 1.663 s 被 st_ kernel 盖住）；真实气泡 = **每层边界 40 个 × ~10 ms、共 0.400 s**。

## 第一行结论（那 1.3 s 丢在哪）
**不是 compute 慢，是 DMA 排不上 + 副本量本身偏多**：prefill 窗口 4.638 s 里 compute 流（stream 13）只忙 **2.989 s = 64.4%**；专家副本共 **2.709 s，只与 compute 重叠 1.663 s（61.4%）⇒ 1.046 s 没藏住**；另有 **0.576 s 双空泡**；合计 ≈1.6 s（nsys 口径）⇒ 折算到干净墙 3.825 s ≈ **1.35 s**。且 **nsys 看到的专家副本量 = 69.6 GB，比引擎自印的 DMA 45.10 GB 多 1.54×，分布在 3 条流（14/7/13）** ⇒ 有一条**未被计数器覆盖/疑似重复的拷贝路径**（候选：ring 预取与 round-0 消费的列表不一致导致重复拷贝；或 swap 流重复）——这是"排不上"的直接来源，**需插桩确认（本轮禁改码，未做）**。

- R10 对照本身比 R9 交付跑（1731.7 tok/s / 3.9222 s）快 2.5%：窗口波动，属噪声级。

### 2) 每条流的总忙时（A，sqlite `CUPTI_ACTIVITY_KIND_KERNEL`）
- **只有 stream 13 有 kernel**（即 `st_` 计算流）：32,434 个 kernel；**prefill 窗口内 busy 2.989 s（64.4%）**；全程 busy 3.162 s（decode 段 kernel 看不到——decode 走 CUDA graph，只有 `CUDA_GRAPH_EVENTS`/`GRAPH_TRACE`，不单列）。
- 其它流（7/14/16）只有 H2D 副本，无 kernel（副本没上计算流）。
- 窗口内 copy 流（14+7+13 的拷贝）busy 2.709 s，**copy 流空闲 1.929 s**。

### 3) H2D 传输（A）
- 总计 **43,550 次 / 74.50 GB / 4.505 s / 平均 16.54 GB/s**（含 load 期，窗口内为主）。
- 按尺寸：**1,548,288 B（半专家）× 40,612 = 62.88 GB**；**3,096,576 B（整专家）× 2,174 = 6.73 GB**；其余：23.6 MB×80、12.4 MB×60、42.8 MB×40、18.9 MB×40、8.4 MB×40（dense/scratch 上传量级）、512 B×120 等。
- **按流**：stream **14 → 42.20 GB**、stream **7 → 22.36 GB**、stream **13 → 3.21 GB**、stream 16 → 6.73 GB（整专家 3,096,576 B 那批）。
- **与引擎计数器对照**：引擎自印 `direct DMAs=29,132`（45.10 GB）；nsys 专家尺寸副本折合 **≈44,960 个专家单位 = 69.6 GB** ⇒ **多 1.54×**。**这是本轮最重要的结构发现**（计数器只记了一条路径）。
- D2H：120 次 / 0.73 GB / 0.038 s；DTO D：24 次 / 0.07 GB。

### 4) 气泡（A）
- prefill 窗口 4.638 s：**GPU-any-busy = 4.061 s（87.6%）；双空气泡 = 0.576 s（12.4%）**。
- 最大气泡：**43.54 ms @ 0.867 s**（一次性，疑首层/首轮冷启动）；其后 13.47 ms @0.911 s、11.99 ms @3.689 s、11.47 ms @2.589 s、11.44 ms @3.427 s —— 后四个 ≈ 每 ~1 s 出现一次（疑每 341-专家轮边界 / 每 8-9 层的槽复用等待）。
- 窗口内 compute 空闲 = 4.638−2.989 = **1.649 s**，其中 1.663 s 与副本重叠 ⇒ **compute 等数据**占绝大多数。

### 6) 附带发现：**`dense_` 与 `scratch_` 的精确字节**（A，`CUDA_GPU_MEMORY_USAGE_EVENTS`）
- `dense_`（"the dense weights"）：**4,707.39 MB = 4.49 GiB**（单次 alloc，nsys 直接读数）⇒ **task-11 里 dense 的"未定量"可以关掉**（原区间 4.7–5.3 GiB 略高，实际 4.49 GiB）。
- `scratch_`（fbuf bump 总和，含 token/arch/常数/①b）：**4,059.99 MB = 3.87 GiB**。
- `stage_` / ring `stage2_`：各 **1,585.45 MB = 1.48 GiB**（与公式一致）。
- ⇒ 峰值归属可重算：arena 16.99 + dense 4.49 + scratch 3.87 + stage 1.48（+ring 1.48 ON）+ mq_/dx_ 等 1.2 + KV/桌面 ≈ 29.4–31.1 GiB，**"5.7 GiB 无归属"基本闭合**（详见 task-11 审计件 §6.6 追加）。
- 注意：nsys 报的 "peak live device bytes = 129.29 GB"（120.41 GiB）**不可信**——它把 VMM 的 map/unmap 与 pinned 混算/重复计数，**不作读数**。

## 未验 / 边界
1. **重复/未计数副本的确切来源未定**（nsys 只能看到 3 条流与体积；候选：ring 预取列表与 round-0 消费列表不一致、swap 流、或 `h_stage_` 分块路径）。建议编译那趟加 3 个计数器：`prefetch_copies` / `round0_copies` / `swap_copies`，并打印各自 bytes。
2. decode 段 kernel 在 graph 里不可见（只有 graph 事件），本轮只归因 prefill。
3. nsys 开销 +21.3% 是 A 级实测；但**开销对各段非均匀**（每 kernel/每次 copy 固定开销），所以"2.989 s compute"是 nsys 口径，**干净口径应按 ÷1.21 粗折（D）**。
4. 气泡的 11 ms 级周期性（疑每轮/每 8-9 层）**未逐层确认**（需要 kernel 名 + 层边界的 NVTX 标记，本轮无 NVTX 打点）。
5. 峰值 31,120/31,110 ≤31,700 ✓；一次一跑；跑前断言 sha/无引擎/显存。
