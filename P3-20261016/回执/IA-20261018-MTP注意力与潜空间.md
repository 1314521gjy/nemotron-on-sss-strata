# 回执 · 情报-S："潜空间注意力"与 MTP 的取法（2026-10-18）

## 1. 任务
用户提出"我们这个模型是有潜空间的注意力的，MTP 不应该取自那里吗？"——四问：① 本模型注意力是哪种（判断"潜空间"指什么）；② MTP（blk.88）的注意力该从哪取（自算 KV / 复用主模型 KV / 复用某层 KV）；③ 我们 `PolyStrata\src\poly` 怎么实现、有没有取错；④ 结论 + 若该改则改法/省多少，若不该改给 `file:line` 理由。

## 3. 结论（一句话）
**本模型没有"潜空间的注意力"**——注意力是**标准 GQA**（32 q 头 × 128、**2 KV 头** × 128、n_embd 4096；无 RoPE、无 q/k norm），**无 MLA**（MLA 类键/张量全 0 命中）；模型唯一的"latent"是 **MoE 的 1024 维**（`moe_latent_size=1024` + `ffn_latent_down/up`），与注意力/MTP 取法无关。**MTP 的正确取法 = 输入取自主模型最后的 hidden（h_nextn），attention 和 KV 自己算一套**（llama.cpp `graph_mtp` 同款：`il=88`、`build_attn_inp_kv`、自己的 Q/K/V、KV cache 按 `n_layer_all=89` 给第 88 层留槽；NeMo `*E` 的 `*`=Attention、`E`=Expert）。**我们没有取错**（`nemotronhmoe.cpp:371-381` 自己写/自己读自己的 KV；`engine.cpp:3900-3922` 才是"从隐状态取"的 eh_proj 融合；`:3940-3960` 自己的 attention+MoE+共享头）。"复用主模型 KV"语义上不成立，且即使能复也只省 per-guess 流量的 **3.4%**；MTP 的钱在**共享输出头 440 MB/guess（74.5%）**与自己的 MoE ≈107 MB。

## 5. 结论与建议
1. **"潜空间注意力" = 不存在**（无 MLA）；模型唯一的 latent 是 MoE 的 1024 维。用户这句话在实现上最接近的正确答案是"**MTP 的输入从主模型最后的隐状态取**"——设计与我们的实现都是这样，**没取错**。
2. **MTP 的 attention/KV 必须自算**（llama.cpp/NeMo 同款）；复用主模型 KV 语义错误且只值 3.4%，**不值得改**。
3. **若要提速 MTP**：砍输出头——`--draft-vocab N`（已实现，默认为全词表）：N=76,938 ⇒ 省 182 MB/guess（≈0.21 ms@864 GB/s）；N=32,768 ⇒ 省 330 MB。风险：只影响猜中率、不损 token（`engine.hpp:205-206`），但 `pixtral` 词表顺序未验，需 A/B acceptance。
4. 免费清理：`block_attend()` 里 `attn()` 重算并重写一次 K/V（`nemotronhmoe.cpp:374-377` 已写过），可加"只算 Q、不重写 K/V"分支（≈1.4 MB/guess，正确性不变）。
