## 3. 结论（一句话）
**原文找到了**：Strata 官方 `docs/A770_SPEED_SPEC.md` §**"GPU utilization: the GPU is mostly IDLE during decode (major finding)"**（`:688-714`）+ §"Per-stage breakdown obtained (decisive): the CPU pool handoff dominates"（`:734-761`）——A770 上 gputop 实测 decode 期间 GPU 计算引擎（ccs）**多为 0–20%、均值 ~20%、不饱和**；由此**推翻**"`ms_wait` = GPU 计算"的假设，结论是 **GPU 在等 CPU/handoff**，所以"**优化 kernel / 提高 GPU 占用**"是打错的靶（原文把 WP4/WP5 关闭为 mis-targeted），路径改为"cut per-layer handoff / overlap CPU pool with GPU"。**它说的是 GPU 利用率（util%），不是 SM occupancy、不是显存占用、不是功耗墙。** 我们**今天也在同一个陷阱里**：nsys 实测 decode 段 GPU kernel busy 仅 **3–4%**，墙 = CPU 腿 49.1 + router_wait 7.7 + host 3.4 + commit 5.6 ms/token（R49 账）；四个拐点全是"占用/并行↑ ≠ 更快"。

## 5. 机理（原文给的链）
1. GPU 不是算不过来：decode 期间 ccs 多数 **0–20%**、均值 ~20%（1 Hz 采样粗，但**活跃生成期间大量 0% 样本无歧义**）。
2. `ms_wait`（host 等每层 ring）里的 ring 迟到，不是 GPU 忙，而是 **GPU 卡在 CPU/交接**。
3. 交接 = host 每层等 GPU 的 ring（doorbell）→ 跑 CPU 专家池 → 把 CPU 结果 copy+combine 回 GPU；eager 分段表显示 `waitA`/`waitB`（GPU 空转等 CPU 池的 flag）+ `copy+combine` ≈ **87% 窗口**，真 GPU kernel 只几十 ms。
4. ⇒ **提高 GPU 占用（更大 kernel、更高 occupancy）不会缩短墙**——墙是串行的每层交接；原文因此关闭 WP4/WP5（kernel 优化）为 **mis-targeted**，改走"cut per-layer handoff / overlap CPU pool with GPU"。
5. 文档本身也记录了一次**自我纠错**：先假设"`ms_wait` = GPU 计算"（`:537-543`/`:559-561`/`:575-576`），后被 gputop 实测推翻（`:702` "This overturns…"）——**这就是需求所指的"撞墙的陷阱"的原始记录**。

## 6. 我们是否撞过（对照四个拐点）
- **结构性同型**：E6（decode GPU kernel busy 3–4%）+ E7（墙 = CPU 腿 49.1 + 交接 7.7/3.4/5.6）⇒ **我们的 GPU 比 A770 的 ~20% 还空闲一个量级**，墙同样在 CPU 腿+每层交接。
- **四个拐点全部命中"占用/并行↑≠更快"**：threads↑（CPU 侧超订）、reserve↓（显存占用↑ ⇒ 尾部被切）、window depth↑（tokens/round↑ ⇒ miss/token +147%）、pcie share↑（让 GPU 更忙 ⇒ 0%~−13%）。
- **代理指标陷阱**：命中率↑（swaps +3.5%）、tokens/round↑（lookup 异构 −2.8%）——都不是目标；只有 ms/token + ids。
- **边界**：A770 是 Intel Arc/SYCL/PCIe3.0x4 的 regime；老师 0.1.40.2 在 4080S 的 q38 短跑相反（`wait for rings 12.102` vs `pool 2.930 ms/round`）⇒ 引用"占用不是目标"这层**方法论**，不外推"GPU 永远空闲"。

## 7. 可操作结论（下一步提醒）
1. **判据**：把 **GPU util% / SM occupancy / 显存占用 / 命中率 / tokens-per-round** 正式列为"**只解释、不验收**"（依据 E1/E3/E8）；验收只看 **ms/token + ids**。可加进 `验收\decode判据表-v2-20261018.md`。
2. **优先级与教训一致**：先 **ReLU² 零跳过（砍 CPU 腿字节）**，再 **host+commit/每层交接打点**（我们 host 3.4 + commit 5.6 = 13.7% 墙；对应 §8.6 的 GPU 路由+整图/门铃，消 6.6 ms router wait + 逐层 launch）。**打点前先修"honest profiler"**——A770 的教训：stage 表被 host stamp 放大、eager 路径坏，要先把仪表修好（对应 `情报-K §5 P1 打点`）。
3. **专家表**：按 **ms/token** 判，不按命中率（R43 的 −8.4% 来自 draft head 字节，不是命中率）。
4. **不要做**：为"让 GPU 更忙"改 kernel/occupancy/批量（A770 WP4/WP5 已关闭；我们 R36 −1.1%、R41 反升；pcie 分流已测 0%~+5.6%）。
5. **自检问题**：任何新机制先问"它缩短的是 CPU 腿、交接、还是 GPU kernel？"——我们的墙只有前两者（R49 账）。

## 8. 未验 / 边界
- **U1**：A770 结论是 Intel Arc/SYCL + PCIe3.0x4 的实测，不是 NVIDIA 三卡；老师 4080S 的 q38 短跑是另一 regime（E4/E5 已标）。
- **U2**：原文自承 gputop **1 Hz 采样、ccs 归属**使数值粗；eager stage 表**被 host stamp 放大**（`A770_SPEED_SPEC.md:741-743`）⇒ 绝对值不引用，只看相对 split。
- **U3**：我们 nsys 的 kernel busy **不含 copy**；decode 段 3–4% 是 kernel-only 下界（结论由 R49 账独立支持，不单靠它）。
- **U4**：`ms_wait` 在两个引擎语义不同：老师 0.1.40.2 = host 等 GPU 逐层推进（`情报-J`：rings=GPU pre 半段），我们 `router_wait`（R49 7.7 ms/token）；引用别混。
