# 回执 · 情报-X：ReLU² 零跳过专项（2026-10-18）

## 1. 任务
lead 派（零 GPU，读码+可行性）：核实 `helgard-orlm/nemotron-super-8gb` 的 ReLU² 零跳过（92.5% 中间神经元=0、down 按神经元重排只读活列、他们 +12%）在我们 `PolyStrata\src\poly` 上能不能做、能省多少。三个问题：① helgard 到底怎么做（离线重排 vs 运行时索引、跳过粒度、量化格式、+12% 是字节还是时间）；② 我们 down 相结构 + 块级全零率（s=0.925 下 32/64/128 块全零比例，真实省字节上限）；③ 三条候选实现（改哪/多少行/新 kernel/ids 逐位/收益/风险）+ 最小可行验证。

## 2. 状态
**达成**。零 GPU、零编译、不改码、未 spawn 子代理；只读本机 clone（`C:\sp3\upstream-hist\nemotron8gb\`）+ 我们源码 + 已有日志；只写本回执与详细件。

## 3. 结论（一句话）
**能做，但省不了"就地跳块"的钱——必须先离线重排 down**。实测我们的 down 相 = **26.9 ms/token = 每 token 墙 65.9 ms 的 40.8%**（R49 三相账，A 级；纯带宽 31.1 GB/s，与 `情报-L` 一致）。**就地 32-块跳过在 x86 64 B cache line 粒度下字节收益 ≈ 0.014%（等于 0）**；只有 helgard 式 **neuron-major 重排（值 512 B/神经元连续 + scale 按块跨行连续，同尺寸）** 才能把 92.5% 的零变成省下的 line：down 字节 −83%、expert −42%、墙 −31% ⇒ **22 tok/s（+36%）**；**天花板 23.3 tok/s（+44%）**，到不了 lead 预估的 28–30（gate/up 25.3 ms/token 是稠密读、不可省）。代价：**31.7 GB sidecar** + 加载/内核 ~300–450 行 + ids 重测（求和顺序风险）。

## 5. 三条候选
- **(a) 就地 32 块掩码**（`cpu_experts.cpp:348-383` 换成按块循环 + 84-bit 掩码；~40–60 行；无新 kernel；跳过的项在整数域恰为 0、块序不变 ⇒ **ids 逐位安全**）：**字节收益 ≈ 0**（E7）⇒ 只省计算，而 CPU 腿是带宽受限 ⇒ **不推荐**。
- **(b) down-T sidecar（neuron-major 值 + block-major scale）+ 新 AVX2 down 内核**（内核 ~150–250 行 + 加载/repack ~100–200 行 + sidecar 31.7 GB；GPU/prefill 仍读 GGUF 原布局）：**down −83%、expert −42%、墙 −31% ⇒ 22 tok/s（+36%，天花板 23.3）**；**ids 风险**：rank-1（neuron 序）求和顺序变、不保证逐位；按块序 gather 可位同但更复杂 ⇒ 必须 1 跑 A/B ids 门。
- **(c) 只重排列顺序（按神经元活跃频率）+ 行对齐**：先验未知、且行级全零需 ~114 值全零（需极强聚类）⇒ 复杂/收益不确定，**不推荐先做**。

## 6. 最小可行验证
1. **零 GPU（已完成）**：现有 R49 三相账给出 down=26.9 ms/token（40.8% 墙）⇒ 值得做。
2. **1 编译 + 1 跑**：`cpu_experts.cpp` 在 `:344`（hq 量化后）加 `STRATA_PROBE_RELU2=1` 打点，统计每 use 的 2688 个 q8 零率（同时报 float 零率）、每 32 值块全零数、每行 64 B line 全零数、按 40 个 MoE 层汇总，结束时打一行（复用 R49 ledger 风格）。**判据**：s<0.85 ⇒ 杠杆变小；P32≈8%（i.i.d.）⇒ 就地跳块确认无效、走 (b)；P32≥40% 或 P_line64≥20%（结构化零）⇒ 先做便宜的"行对齐+整线跳过"再重估 (b)。
3. **（b) 落地前**：ids 门（45/64 + `--top-probs`）+ 盘/RAM 预算报批（sidecar 31.7 GB，等于给专家库加 1/2 大小的第二副本）。

## 7. 未验 / 边界
- **U1**：helgard 的 92.5% 是 **NVFP4 检查点 + fp32 激活**；我们 **Q4_K_M + Q8_0 激活**的 s **未测**（决定一切，需 §6.2 的 1 跑）。
- **U2**：q8 量化会**额外把非零小值变 0**（零率↑）但非零值有量化误差 ⇒ 实测要同时报 float 零率与 q8 零率。
- **U3**：31.7 GB sidecar 的**盘位与 RAM/page-cache 预算未核**（prefill 也读同一 GGUF，cache 被挤会反伤）。
- **U4**：+36% 假设重排后仍按 31.1 GB/s 供数；gather（512 B/神经元）可能只有顺序流的 80% ⇒ 现实 **+20~30%（20–22 tok/s）**。
- **U5**：天花板 23.3 依赖"gate/up 25.3 ms 不可省"——若 P1 打点（`情报-K` §5）证明 gate/up 不是纯带宽，天花板会上移。
- **U6**：helgard 的 +12% 是 NVMe/PCIe 架构下的数；我们是 DRAM 顺序读，相对收益理论更大，但 gather 开销未实测。
