## 3. 结论（一句话）
**三条都"该有条件地模仿"，优先级 C ≫ A ≫ B，且今天只有 C 值得动。**
- **A（device 路由+门铃+整图）**：老师一轮 = 每层两张图（pre/post）以 router 处 doorbell 切开（`core/session.cpp:186-187/658-740`；门铃 `layer.cpp:370-385`，ring 最后；host 每层 poll mapped volatile + 一次 `cudaEventQuery` `session.cpp:686-725`；GPU 半段先发 `hits(Launch)` `:727-730`；CPU pool `:732-733`；combine 本层 `:735-740`）。**device plan/整图只在其"全驻留 token graph"成立**（T `generate.cpp:2358/2391/2401` "decided on the device"），verify window 仍 host 建 plan（`expert_source.cpp:284-367`）+ 图内等 flag（`verify.cpp:558/587/595`）。**我们命中 41–57%（R49 miss 516.9/token），永远不全驻留 ⇒ 主体的 device plan/整图对我们不适用**；能仿的只有 "device top-k 写 mapped doorbell + 可选把 cached 专家段图化"，**预期 +3~7%（D），不是此前 +8~12%**；中改、风险高（`up_↔st_` 红线、device top-k 必须与 host 逐位一致、图捕获动态地址）⇒ **不是今天**。
- **B（resident 补集+交换）**：老师**实际 pin 50,295,996,416 B≈46.84 GiB**（`dec-pool2:26-30`，expert arena 模式，全部 expert 集）；resident 模式设计只把**非 VRAM 补集**拷进紧凑 pinned RAM（`generate.cpp:6960-6966`；老师 cache 11,428/24,576 ⇒ 补集 ~25GB，D 估），swap 把换出专家 memcpy 回被替换者 RAM 位置（`docs/DETAILS.md:168-169`），EXCHANGE_ROTATE（`fa1d1d1e`）消掉这次 copy。**lead 推演成立**：① `cudaHostRegisterReadOnly` 只是 DMA 注册、不锁页（3ms/0 RAM，`情报-M` 已证）；② 真正占 RAM 的是 `map_pages` 预热全部 63.4GB（WS 65.5GiB，`情报-M`）；③ 63.4GB 每块都有用途：非驻留 42.5GB = CPU miss（373–517/token×3.0966MB=1.16–1.60GB/token）+ prefill staging 来源 + 换出后读取；驻留 20.9GB = VRAM fill + 换出后读取 ⇒ 稳定态工作集仍趋 63.4GB；④ 只改 pin 范围省不出 RAM（要停预热并把非驻留改成紧凑提交副本=Stage D）；Stage D 后 RAM 账：42.5+sidecar 31.7+dense 6.7+OS 10≈91GB/96GB ⇒ **余量仅 ~3–5GB**，且有冷读 5.7GB/s（10% 冷页≈20–28ms/token，D）与 prefill 失去 DMA 直拷（pin 曾 +53.7%，backlog A）风险。**Stage D 是 sidecar 唯一解，但代价高、前置实验未做** ⇒ 今天不照搬，先做 `STRATA_PIN_ARENA_GIB=20` 零改码实验量 prefill 退化。
- **C（MTP 专属驻留）**：老师 MTP 块 512 专家**单独整块常驻 VRAM**（`mtp.cpp:138-151`；`dec-pool2:23` experts 675MiB、dense 111），draft head 106,299 行子集（`mtp.cpp:258-274`；`dec-pool2:47` 212.9MiB）。**我们可仿且最值得今天做**：给 blk.88 的 512 专家一个 **不占主 cache 的常驻区**——我们 blob=3.0966MB ⇒ 需 **512×3.0966MB=1.585GB**（老师的 675MiB 对应它 ~1.9MB/blob）；显存来源走 prefill staging/ring2 借槽（`情报-Z` 的 borrow）或先 `--stage-mib 512` 试验，**不动主 cache ⇒ 主模型算术/ids 不变**，draft 的 MoE 全 GPU ⇒ 去掉 draft CPU 腿（~4–5ms/round≈1.5–1.9ms/token）与 ids 漂根因；`--draft-vocab`（R43 −8.4%）才有机会进交付。**改动 30–80 行（fill_expert_cache 预留 512 槽/独立小 arena）、风险中低、预期 D 级 +5~15%（最差 ±0）。**
