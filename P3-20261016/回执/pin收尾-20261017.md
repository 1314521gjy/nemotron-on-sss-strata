## 3. ★ 天花板与原因
- **平均单次 DMA = 1.48 MB < 5 MB** ⇒ **小 DMA 是主要拖累**（次数 74,564）。
- 但**无法合并**（见 §4）⇒ **1.48 MB 是"无 host copy 直接 DMA"路线的下限** ⇒ **603.7 是天花板**。
- **40 层（59.1 GiB）在本机 ≥16 GiB 线附近，经常被拒** ⇒ 37 层是可靠上限。

## 4. ★ 已否路线：**"按 id 排序 → 合并成大 DMA"**
- **论证**：一轮 ~86 个专家从 512 里取，**按 id 排序后仍有间隙**；按 `[min_id,max_id]` 发连续 DMA 会**把间隙里不在本轮的专家一起搬（3–6× 字节）⇒ 更慢**。
- **根因**："集合 → 连续区间"的固有矛盾。**记此一笔，免得后人重走。**
- 另一条（每轮 host gather 到连续 pinned 缓冲 + 一次大 DMA）≈ 现在（host copy 又回来），**未实测**（见 §6）。
