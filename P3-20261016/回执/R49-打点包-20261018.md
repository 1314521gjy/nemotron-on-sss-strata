## 4. 与老师 `q38_perf` 同字段对比（折 per-round；我们取干净窗口 L1）

| 字段 | 老师（per round） | 我们（L1 per round） | 差 |
|---|---|---|---|
| router wait / rings | 12.378 ms | **7.7 ms** | 我们更小（0.62×） |
| CPU pool（gate/up + quant + down） | **9.91 ms**（6.019/0.079/3.891） | **49.1 ms**（25.3/0.17/26.9） | **4.96×** |
| host / launch | 0.101 ms | **3.4 ms** | 34× |
| commit / sync | 0.037 ms | **5.6 ms** | 151× |
| pool 有效带宽 | 18.4 GB/s | **31.1 GB/s** | 我们 1.69×（带宽效率更高） |
| 每轮总时间 | 24.3 ms | **65.9 ms** | 2.7× |

**读法**：我们的 **GB/s 比老师高**（31.1 vs 18.4），所以 CPU 腿的差距不是"内存效率"而是**工作量**（miss/token 496.7 vs 老师 ~0.35）＋**host/launch 与 commit/sync 两个固定开销各差 34×/151×**。老师 24.3ms 里 19.8ms 是 ring/pool 等待（其 CPU 腿极轻），我们 65.9ms 里 49.1ms 是 CPU pool、7.7 router、3.4 host、5.6 commit —— **下一步杠杆应在"host/launch 与 commit/sync 这两段 9ms/轮"和"pool 工作量"**。
