## 证据（A：sqlite 逐事件；D：推断已标）

### 1) 每个气泡的现场（39 个，≥3 ms；A）
- **前一个 GPU 事件**：39/39 都是 `mul_mat_q<ggml_type 12 或 14,128,false>`（该层最后一批 MMQ kernel）。
- **后一个 GPU 事件**：39/39 都是 **H2D `1,837,080 B`** —— 精确等于 `tab_` 上传：`(3*cap + 3*512 + 3 + kClasses*cb_row)*sizeof(int32)`，kClasses=3 ⇒ 1,837,080（`engine.cpp:2591-2594`，cap=rr=152,064、cb_row=513）。
- **气泡起点**：每次都固定在 **router logits 的 D2H 结束之后 4.8–5.6 ms**（大 D2H：`13,907,968 B = 6,791×512×4`，即 `h_rl_` 回读，`engine.cpp:2428`；另有 4,194,304 B×40 的 D2H）。
- **气泡内的 host 侧**：**无任何 CUDA API 调用**（重叠 API 仅边界的 `cudaMemcpyAsync(tab_)`，重叠 0.0–0.1 ms）；**无任何 SYNCHRONIZATION 事件**（`sync=` 全空）。⇒ **host 不是在等，而是在算**。
- **时长**：7.2–12.2 ms，平均 8.98 ms；分布见抽样（t 为相对 prefill 起点）：0.123s/8.00ms、0.204s/10.13ms、0.316s/9.77ms、0.480s/10.64ms、1.048s/10.91ms、2.698s/11.99ms、3.076s/10.61ms …（39 行全表在 sqlite 可复算，脚本见落盘）。

### 2) 分类总计（A）
| 类 | 次数 | 总时长 | 判据 |
|---|---|---|---|
| **③ host 计算（无 CUDA API、无同步，纯 CPU）** | **39** | **0.350 s（100%）** | 气泡内 API 重叠为 0；起点固定 = router D2H 后 ~5 ms；终点固定 = 下一层 `tab_` 上传 |
| ① host 侧同步（Stream/Event/DeviceSynchronize） | 0 | 0 | 气泡重叠的 SYNCHRONIZATION 行 = 0 |
| ② 依赖等待（event wait，等 up_ 拷贝） | 0 | 0 | 气泡内无 event-wait 行；副本流在气泡里也空闲（union 气泡定义） |
| ④ launch 间隙（host 来不及发 launch） | 0 | 0 | 气泡内无 launch API（只有边界 1 个 memcpy 调用） |
- **注意区分**：窗口内另有 **40 个 18–84 ms 的 `cudaEventSynchronize`（router 等待，`engine.cpp:2480`）**，它们**不是气泡** —— 那段 host 在等 GPU 的 router/dense/mamba/attn kernels，GPU 是忙的。

### 3) host 在算什么（A：代码 + 时间点对齐）
- 调用链：`moe_rows()`：`:2421` `on_card = route_card(...)` → **Nemotron 未 override ⇒ false**（`engine.hpp:338` 基类默认 false；只有 deepseek4/gemma4/glm5next/lfm2moe/qwen35 有 override，`nemotronhmoe.*` **没有**）→ `:2428` D2H `h_rl_`（13.9 MB）→ `:2480` `cudaEventSynchronize(ev_)` 等 router → **`:2495 parts = min(24, ⌈n/32⌉) = 24` 个 CPU 线程** → `:2497-2503` `workers_->run(parts, … route(il, h_rl_+t*512, …))` → 然后建表（`:2504-2590`：count_/spare_/chan_/group_/bounds/rel/cb）→ `:2591` 上传 `tab_`。
- **`route()` 本体**（`nemotronhmoe.cpp:362-385`）：每 token 先 512 次 sigmoid（`:367`），再做 **22 次"全 512 扫描找最大"**（`:371-379`，每次 `pick[e] > pick[best]`），共 **11,264 次比较/token**；6,791 tokens ÷ 24 线程 ≈ 283 token/线程 ⇒ ~3.2M 比较 + 145k sigmoid/线程/层 ≈ **8–10 ms/层** ⇒ 与气泡时长一致。
- ⇒ **气泡 = CPU top-22 选择 + 表构建**（`route()` 的 22×全扫是主项，D）。

### 4) 最小改法（给 lead 定编译内容）
- **推荐（最小、无数值变化、无新依赖）**：把 `nemotronhmoe.cpp:362-385` 的"22 次全扫"改成**单遍维护 22 槽有序 top（值降序、同值索引升序）**——选择语义与现实现**逐位一致**（现实现每次取 `pick[e] > pick[best]` 的第一个最大值 ⇒ 同值取小索引；单遍插入表按同规则即可复现）。预计每层 CPU 从 8–10 ms 降到 **1.5–3 ms** ⇒ 39 层省 **≈0.25–0.30 s**（D）。
  - 改点：`nemotronhmoe.cpp:371-379`（约 10–15 行）；不动 kernel、不加缓冲、不改 API。
  - 预期墙：nsys 真窗口 3.631→~3.33 s；干净 3.825→~3.42–3.47 s（≈1960–1990 tok/s，D；**到不了 lead 的 ~2200，因为还剩未藏副本 0.289 s**）。
- **备选（更大收益、中等风险）**：给 `NemotronHMoe` 加 `route_card()` override，用 **poly 自带的 GPU 路由 `route_rows()`**（`src/poly/kernels.cu:2293`，支持 ≤512 专家/≤32 experts-per-token；LFM2Moe 的现成用法 `lfm2moe.cpp:302-306`，`gate=1`），需要：①为每层路由 bias 建 device 副本（照 `lfm2moe.cpp:118` `B.probs_b_dev = upload(...)` 的写法）②只在 prompt（`n >= kStageRows`）返回 true，decode 仍走 host（避免动 `:2297` 的 decode 分支）③用 `route_test.cu` 的对照法验"同一 token 同一批专家"。**收益同量级或略大**（host 只剩 `std::copy(h_ids_,…)` 1.2 MB），但多 1 个 device 缓冲 + parity 验证，风险高于推荐项。
- **不建议**：GPU top-k 的 `native_router_topk`（`src/kernels/cuda/native_router.cu:236`）——**只支持 (512,10) 和 (256,8)，我们是 (512,22)**，不是 flag 能开。

### 5) swap +133（2,174 次 vs 自印 2,041 个专家；A/D）
- 2,174 次全在 **decode 期 15.802–19.052 s**（流 16=`swap_st_`，`engine.cpp:1342` 的 `slot_down()+d_bytes=3,096,576 B` 整帧拷贝）。
- 时间结构：**2,173 个独立簇**（相邻间隔 >0.2 ms 才并簇，最大簇 2 次）⇒ **一次一个 swap、没有成对重复**；无相同时间戳的重复拷贝。
- `virtualAddress` 字段为 NULL（nsys 未记录）⇒ **无法按目的地址去重**（明写：查不到）。
- 计数器语义：`engine.cpp:1377` `++stats_.swapped_experts` 是**每次 swap 完成 +1**（不是按不同专家去重），打印发生在生成结束时 ⇒ **+133 最可能是"stats 打印后仍有在途/收尾 swap"与"同专家被重复换入"的混合**；**没有证据表明是重复拷贝（D 级，未证实）**。

## 未验 / 边界
1. 最小改法的收益是 D 级推算（8–10 ms → 1.5–3 ms），**未实测**；`route()` 单遍实现的"逐位一致"需一次对照（可用 `poly_expert_parity`/ids 45/45 + probs 对照）。
2. 气泡计数口径差：R11 报 40 次/0.400 s，本件精确复算 **39 次/0.350 s**（阈值/窗口边界差异，同一现象）；以 39/0.350 s 为准。
3. 表构建（`:2504-2590`：count_/spare_/group_/bounds/cb）本身的耗时未单独拆出，含在 8–10 ms 里（D）。
4. 本件不动码/不编译/不跑 GPU；`native_router_topk` 的 (512,22) 缺支持是 A 级读数。
5. swap +133 未证实为重复，只证明"无成对重复 + 计数器是 per-swap 语义"。
