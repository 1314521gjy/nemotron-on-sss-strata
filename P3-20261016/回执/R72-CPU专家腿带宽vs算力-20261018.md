**结论：带宽受限（算力被隐藏）⇒ "PCIe 边搬边算"无额外 DRAM 带宽窗口，预期 ≤5%（与 R39 +5.6% 吻合）。零 GPU、零编译（除自写 Python 读脚本）、未改码、未 spawn。**

- 单线程原生顺序读（`copy /b downT.bin NUL`，29.53 GiB）：冷 4.92 GB/s、**热 5.20 GB/s**。
- 多线程读（Python 参考）：1/8/16 线程 = 2.18 / 8.04 / **15.77 GB/s**（受解释器读路径限制，不作结论）。
- **引擎 16 线程实测**：ledger `down=2009.4 ms / 128 tok`、**自报 41.3 GB/s** ⇒ down 15.7 ms/token；带宽时间/use = **1.548 MB / 41.3 GB/s = 37.5 µs**（若按 516 uses/token 折算则 30.4 µs/use）。
- **纯算力（16 线程）**：`stageC-parity-topt.exe` = **10.7 µs/use**（1 线程 171.8 µs/use；5.54 ms/token ÷ 516）。
- **⇒ 带宽时间 ≈ 3–3.5× 算力时间 = 带宽受限**；不是"vec_dot 算力打满"，也不是"理论 89.6 GB/s 还有 40% 可挖"（单线程实测上限 5.2 GB/s、16 线程聚合 51 GB/s 已接近该读路径上限）。
- **PCIe 结论**：正确专家的数据无论如何都在同一块 host DRAM；CPU 原地算要读、PCIe 搬也要从 host 读 ⇒ 无额外带宽 ⇒ 只有调度空档可蹭 ⇒ ≤5%。
