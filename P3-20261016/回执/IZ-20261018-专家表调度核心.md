## 3. 结论（一句话）
**表不是"运行期派发/预取顺序"的核心，而是"驻留资格 + 容量/打包 + 借槽受害者 + 多卡放置预测（U）+ 学习闭环（U）+ 离线工具"的核心。T 树（老师 0.1.40.2）对表的运行期消费共 6 类：① `expert_cache.cpp:12-70` 只读 rank 前缀（文件里的 per-layer rank 逆表引擎不读）；② `generate.cpp:1577-1588` 表存在 ⇒ 驻留策略从 compulsory-miss 切到 profile（`--expert-cache 0`⇒auto）；③ `:1583-1586` 显式 `--expert-cache N` 截断 rank 列表；④ `:1623` auto 槽数 `min(slots, profile.size())`；⑤ `:1628-1646` native `open_sized` 按 pair 大小/rank 顺序打包；⑥ `:1761-1775` 按 rank 一次性填满、decode 不 admit（"the only place the plan is applied… runs ONCE… the decode-time admission finds no room"）。**唯一真正的"表→运行期调度"是 prefill 借槽**（`:1619` 表存在才借；`:2455-2492` 从 cache 尾部=最低 rank 借 k 个；`:2511-2535`/`:3112-3152`/`:3484-3559` 借出+refill；日志 chunk auto 6912、borrow 2387 槽/4.55 GiB、refill 213 ms、prefill 2997.9 tok/s）——**它不依赖命中率**。**U 树新增**：多卡 layer-split 放置预测（`generate.cpp:3719-3894` 把 rank 前缀当覆盖曲线 `mass[r]`；`make_profile.py` 文首自述"reads this RANKING as if it were a frequency curve"，并记录 94.9% claimed vs 69.2% measured 的误差）；peer/remote GPU 按 rank 装（`peer_experts.cpp:81/143`、`remote_experts.cpp:126/148`、`STRATA_PEER_HOT` `generate.cpp:3693`、`--expert-cache-remote-placement stripe|layer`）；学习闭环 `rank_learned_profile`（`expert_cache.cpp:141-168` resident→heat→prior-rank；写盘 `:170-207`；serve `generate.cpp:10364-10367`）。**表不驱动**：门铃/ring 时机（`layer.cpp:370-385`、`verify.cpp:796-844`）、prefill 流式顺序（`prefill.cpp:73/832`：逐层+层内 expert id 序）、verify/CPU pool 派发（`expert_source.cpp:284-367/403-424` routing 顺序）、adaptive 候选（`generate.cpp:2651-2690` usage 计数）、跨层预测（T 无；U 是 `RouterLookahead` 用 **l+1 层 router 权重**，`expert_source.hpp:241-246`，不读表）。**`--reorder`**：只在 U 树**工具层** `tools/make_profile.py`（参数 `:98-100`，`rank_profile()` `:86-112`）；默认序=base 全部→trace 频次→补齐，因 shipped base 已排满 24,576，普通
