## 2. 判决与机理

### D1（换驻留槽）——**判红**
- 装载时驻留 **5924**（比 D0 多 203、fill +599.5 MB），但**解码有效驻留反而变差**：VRAM 服务率 43.3% → **32.3%**、miss/token 496.7 → **595.2（+19.8%）**、decode −15.4%。
- **定因（读码）**：`engine.cpp` 的 `cover()`（KV 缓存按 `kKvGrow` 增长）在 `free_b < more + quarter`（`quarter = reserve/4`）时调 **`shrink_cache()` 从专家缓存尾部切走 VRAM**。reserve 2400 时 quarter 只剩 600 MiB，KV 增长时把刚填进去的槽切掉 ⇒ 印刷的 5924 只是装载时点，**解码时有效驻留低于 D0**。
- 峰值 31,389 ≤31,700（余 311）**没被峰值门判红，但 decode/ids 已判红**；ids 63/64 不同、max|Δp|=**0.9998@pos34**、9/64 位置 >0.05、near-flip pos0(0.0341) dp=0.0338 ⇒ **非无损**。
- ⇒ **"换更多驻留槽"不成立**：reserve 降了会被 KV 增长吃回去；reserve 3000 的 1/4=750 就是现在能稳住的线。

### D2（PCIe 第二带宽通道）——**不达门、非无损**
- CPU miss 砍 26%（496.7→368.2）靠 PCIe 取了 **131.29 专家/token**；但：`cpu_us/miss` **+29%**（96.1→124.0）、`cpu_busy` **+15%**（90.3→103.9）、PCIe 搬运 **400 MB/token（25.61 GB/整跑）**，净 decode 只 **+0.8%（<5%）**。
- 质量：ids 1/64 不同、max|Δp|=**7.54e-2@pos26**、**4/64 位置 >0.05**（near-flip pos63 dp=5.9e-2）⇒ **类 E 近分跳变**，与 R26 的 class-E 结论一致。
- ⇒ PCIe 分流 v1 在 alt 上**不赚且非无损**，不采纳。

### D3（lookup 3 的异构 prompt 成本）——**纯成本**
- decode **−2.8%**（16.63→16.17）、miss/token +4.6%（+22.6 个 CPU uses/token）、prefill 127.5→126.0（基线）；**ids 0/64 全同、top-probs 逐位同（Δp=0）** ⇒ lookup 链在 alt 这种无重复 prompt 上只付窗口开销、拿不到兑现（1/4 中）。
- 交付带 lookup 3 是为 p6792（重复模板兑现 100%）服务的；**异构 prompt 上它是 −2.8% 的成本项**（用户若在意异构 prompt，可改为自适应/关闭，另议）。
