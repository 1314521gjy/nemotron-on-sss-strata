## 3. 两个真 bug（这是本件的核心内容）

### 3.1 pinned bounds 表被逐批重写 + `cudaMemcpyAsync`
第一版把 `h_rel_local_` 每个 batch 重写一次并用异步 H2D ⇒ host 与在飞 DMA 竞争。已改成**一个 call 一张表、一次 `cudaMemcpy`（pinned，返回即完成）**，call 内不再重写。

### 3.2 ★ mmq 的 q8 布局是 `[K block][row]`，不是行主序
- 依据：`E:\llama-cpp-pin\ggml\src\ggml-cuda\quantize.cu`：`ib = k_block*ne1 + row`；`mmq.cuh`：`by0 = y + ncols_y*(kb0*qk/ne_block)*sz`。
- ⇒ **`mq_ + r0*xq_row` 切片不成立**；且 `ncols_y`（`total_rows`）必须是**该 xq 缓冲的真实行数**，不能传 batch 行数。
- 第一版因此输出退化为 `1278,2879,1044…`（有限但错）。
- **修法**：tiled 路径不再切 `mq_`，而是把该批的行整批重量化到 `mq_tile_`：
  `Mmq::quantize(in, d_tok + r0, mq_tile_, gt, in_w, in_w, rows_batch)`，再以**局部 bounds + 局部 ids(iota_) + `total_rows=rows_batch`** 做 up。
  `down` 的 `mq2_` 本来就是按 batch 量化（行数一致），不受影响。
- 这也是对已批方案 §6.5「`xq_row = native_q8_1_bytes(in_w)`」的**代码级更正**：方案假设了行主序，实际布局不成立。

## 5. 未达成 / 未验

1. **pb=6912 驻留 5890，未到 ~6900**。原因：①b 只压了 `gu_/hx_/mq2_`；pb 从 1024→6912 后，**其余按 `rows_` 缩放的缓冲**（`mq_` 约 700 MB、`r_/cur_/xn_/ao_/fo_/g_/u_/h_/moe_in_/moe_out_/xq_/q8_` 等）与固定的 2 GiB staging 仍在。要再拿 ~3 GiB 需继续压 `mq_`/token 缓冲，**超出 ①b 批准的 scope，未做**。
2. **DMA 体积 134.8 GB，未到 <121.7 GB**。121.7 GB 是 pb=1024 旧路径的体积；同口径 pb=6912 的负控是 166.4 GB。按同口径，本刀 **−19%**。要 <121.7 需要驻留继续上升（见 1）。
3. **`maxc > 8192` 兜底路径未触发/未验证**（数学上 pb ≤ 6912 时不可达；代码是懒分配 + WARNING，未构造用例）。
4. 未跑第三次重复（时间/轮次约束）；单跑数字，噪声未锁。
5. 未做 pb 扫、未做 ring/借槽、未改其它任何路径。

## 6. ★ 609.6 vs 336.9 的差异归因（已结案）

- **根因 = 缺 `STRATA_M2_SCAN_SMEM=1`**，不是机器变慢。
- pin 时代 609.6 的完整命令（从 builder 会话记录复原）：
  `STRATA_PIN_ARENA_GIB=59.1 STRATA_M2_SCAN_SMEM=1 ./sp_pin3.exe --max-new 45 --max-context 16384 --prompt-batch 1024 --stage-ahead 128 --stage-mib 2048 --cpu-share 0.55 --expert-swaps 64 --tail-skip 0 --threads 24 --vram-reserve-mib 2500 --no-draft --lookup 0 --expert-profile p_run.txt`
  其中 `sp_pin3.exe` 是当时 `build-p3\strata-poly.exe`（sha `6b349ee5…`）的副本，cwd `C:\sp3`。
- 今天的第一次 tile=0 跑**没带 SMEM=1**，prefill 336.9/339.5；补上后同日 A 跑 = **624.8**（+85%），与 609.6 同量级（差 2.5%，在单跑噪声内）。
- 其余差异逐项核过：`--max-context 16384`（今天先前用 8192）不影响驻留（6982 相同）；`--stage-ahead 128`（默认 1024，n=1024 时同样走 ahead）；`--expert-swaps 64`/`--tail-skip 0` = 默认；`--cpu-share 0.55` 只影响 <1024 的尾块。**没有其它解释项。**
