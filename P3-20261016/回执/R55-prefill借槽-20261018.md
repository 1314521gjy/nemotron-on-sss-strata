## 4. 判决（一期）

1. **机制 PASS**：默认关、可开、自证、回填逐字节可验、冲突响亮失败、N1/N3 回旧值、V1/S1 ids 全逐位同、lend 路径 V2a bit-identical。**"借槽不降级"成立**（decode 不降级反升，ids 不漂）。
2. **收益（一期=借给 decode 缓存）**：decode 驻留名义 5721→**6724**（+1025；装 5721 与 prompt 开头 cover 的 ~21 槽切槽两边相同）；**miss/token 516.2→468.3（−9.3%，确定性读数）**、experts from VRAM 41.3%→46.7%；decode 成对 +4.9%~+14.4%（最佳 +12.1%），cpu_pool/token −7~14%；alt prompt 干净批 **+16.2% 中位**（§8）。
3. **成本**：refill 143 ms 计入 prompt ⇒ **prefill −3~4%**（同条件对 1899.2→1818.9 = −4.2%）；一期借槽**不产生 prefill 收益**。
4. **峰值不增**：正常臂 30,900–31,073（REF-OFF 与 R1 同轮均 30,901）；C1 边界臂 31,434；全部 ≤31,700。
5. **同步 refill 可接受**：143 ms < 300 ms 线。

## 5. X1 臂与"二期空间"量化（lead 追加）

- **X1 = `--stage-mib 4096`：无效**——启动自证行仍 `1512 MiB of staging = 511 expert slots`，staging **42.01 GB**（P0 = 41.97 GB，+0.1%）、resident 5721、prefill 1536.3（同批 REF-OFF 1440–1566 噪声内）、ids 64/64 同。原因：`stage_bytes_ = max(min(stage_mib<<20, n_expert*one_expert), one_expert)`，**512 专家即钳位 1512 MiB**（R54 也实测"钳位 1512"）。
