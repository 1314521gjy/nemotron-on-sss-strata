## 红臂（这些判据怎么变红/本席怎么验证）

- **dec-pool2 与 q38 不一致的判定**：不是靠"数值不一样"就下结论，而是先核 **engine 版本**（`dec-pool2:42`=0.1.40.2 vs `q38_perf:28`=0.1.43.1）与**配置**（workers/ctx/window/min-p/cache 全列）⇒ 若有人说"108 在 q38 上复现了"⇒ 红（当前日志无此读数）。
- **同 prompt 对照"从未做过"**：q38 prefill 行（L55/L60/L61）的 prompt 长度 699/4095/6791/6791，**没有 293**；若有人拿 alt 16.23 与老师 61.91 直接比 ⇒ 红（本件 §4.2 列 7 条不可比）。
- **"我们缺 wait for rings"** 的负控：grep 我方 `src/poly` 的全部 `route_wait_ms`（`engine.cpp:2236,2777`）与 ring 事件（`:2759-2767`）——只有 router event 计时，**没有任何 ring wait 累计** ⇒ 缺项成立；若谁声称"有"⇒ 让他指出 print 行（目前没有）。
- **假读数负控**：`main.cpp:799` 字符串里 `pcie_us/miss=0` 是字面量；`main.cpp:780-781` 分母 `st.tokens`（含 prefill）⇒ 任何用 summary 的 "CPU experts ms/token" 当 decode 指标的比较会被判红（正确用 decode-only `main.cpp:796-810`）。

## 关键决定

1. **四份 q38 段账原样保留**（不摘要、不合并），并标注每行的 file:line；`per token`/峰值两字段**老师日志也没有**，不伪造。
2. **dec-pool2 与 q38 的差异归因拆成"版本+配置"两组**，不把 108 vs 62 归给单一变量；受控实验（同版本仅窗口不同）列为待补。
3. **TOP-3 打点按"对账价值/成本"排序**：① 四段账+轮账（20–30 行，1 编译）② speculation 账（15–25 行）③ decode-only 修复 + pool 分相（20–40 行）；并明确零改码可补项（per-token 推算、tokens/round 推算、pcie share、峰值用 R21 sampler）。
4. **先修假读数**（pcie 硬编码 0、summary 稀释）再谈补段账——否则新打点会叠在假口径上。
