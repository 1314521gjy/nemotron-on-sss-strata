## 3. 结论（一句话）
**75 ms/token 里约 72 ms 是"CPU routed-expert 腿"——`decode: miss/token=496.7 × cpu_us/miss=144.7 = 71.9 ms/token`（R28-A3 的 decode-only 计数器，A 级），其中 busy 65.3 + 交接/发射 6.6；剩余 wall 14.2 ms 是 router 等待 + lm_head + 同步/图缝隙。计划里的"CPU experts 11.1 ms/token、其余≈57 ms 未拆"是分母含 prompt token 的稀释打印（`main.cpp:767`；`route_wait` 还被 prefill 的 `moe_rows` 污染，`engine.cpp:2157` vs `:2681`）⇒ "57 ms 未拆"就是被稀释掉的 CPU 真值，decode 是 CPU 专家计算/读取瓶颈，不是 GPU、不是 kernel 发射、不是 PCIe。**

- **四问**：Q1 `mamba2_scan_kernel<true>` grid=128×block=64、SMEM 33,024B、每线程 `for st=0..127`（串行维=d_state，非时间步）（`kernels.cu:2554-2610/2925-2927`）；每层状态 4MiB 读+4MiB 写 ⇒ 推算 15–25µs/层（未验）。Q2 图内 ≈2,640 kernel/token（"some thirty a layer up to the router" `engine.cpp:3200-3202`）+ MoE 段掉出图（`moe_card()` 非门控直接 false `:2489`；每层 ~15 host 发射×40 ≈600）⇒ ≈3,200 kernel/token、host 调用 ≈820/token；图只有 per-layer heads/shared/tail（`:3211-3226`）+ lm_head（`:3413-3429`）。Q3 层内 CPU∥GPU cached（`meanwhile`，`:2252-2257/:2430-2432`），层间不重叠（单 host 线程，`:3366-3374`）。Q4 每 token 稠密 4.707GB + cached 专家 1.187GB = 5.894GB ⇒ 6.82ms@864 / 8.42ms@700；CPU miss 1.538GB 宿主读 ⇒ 下限 ≈22ms@70GB/s（实测有效 23.6GB/s ⇒ 65ms）。
- **三大延迟源**：① CPU 专家腿 71.9ms（83.5%）；② CPU→GPU 交接/host 发射 6.6ms（7.7%）；③ router+GPU 残差 ≈14.2ms（含 lm_head 0.7–1.0、logits D2H/sync、图缝隙、真 router 等待未验）。每项的便宜实验：`--threads 24→8`（1 跑）、`--expert-swaps 0 vs 64` 同 prompt 2 跑 + `--no-graphs` 1 跑、加 1 行 decode-only route_wait 或 nsys 1 跑。
- **打点方案**：`STRATA_DEC_PROFILE=1`（默认 0）——host 阶段墙钟、GPU 段 CUDA event（图内不可加 event ⇒ `--no-graphs` 臂/nsys）；自证 7 条（Σ段/wall∈[0.9,1.1] 否则响亮 MISMATCH、dense_bytes/token=4706.8MB 静态核对、`STRATA_DEC_PROFILE_SLEEP_US=N` 注入负控 moe 段须 +40N、profile ON/OFF ids 逐位同且 tok/s 差<1%、`--no-graphs` ids 同、threads 反证、decode-only router 与既有读数一致）；开销 ~200 点×40ns≈8µs/token（<0.02%）。

## 5. 未验
1. R28-A3 是 `sp_pcie1.exe` + `--expert-swaps 0` 的读数，非当前交付 exe/配置（交付 `--expert-swaps 64`、hit 51.7% vs 43.3%）⇒ 绝对值需在交付 exe 上复核（同 decode-only 计数器）。
2. mamba2 每层 µs、per-layer GPU 时间、CPU 专家内部 4 阶段、decode-only router 等待**全部未验**（需 §5 P1 打点）。
3. CPU 腿是 **compute 还是 memory bound 未判**（有效 23.6 GB/s 与 ~84 GFLOPS 都可能；需 4 阶段计时）。
4. `--pcie-frac` 若用于救 CPU 腿：1.538GB/token ÷23GB/s ≈67ms，静态看不划算（除非与 GPU 深度重叠，需另算）——本件未做。
5. 计划 T4（≥20 tok/s=50ms）与 CPU 下限：§3 Q4 给 CPU 侧理论 ≈22ms（45 tok/s），但当前 CPU 腿 65ms 距下限 3×。
