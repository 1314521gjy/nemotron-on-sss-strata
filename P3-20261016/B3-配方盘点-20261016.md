# B3 配方盘点（只读）：`moe_rows()` 支不支持非门控 = 配方 还是 构造？（2026-10-16）

**结论一句话：偏「配方」，非「构造」。** 现有构件（`slot_up()/slot_down()`、`relu2`、`mmq`、`stage`）**都在**；是 `moe_rows()`/`stage()` **没去调它们**、把门控宽度/激活**写死**了。**没有需要新建的内核。** 但**非零工作量**（≈11 处几何改调现有配方 + 一个 `relu2` 分支 + 闸门去 `L.gated &&`）。

---

## ① 那些"像门控专用"的几何 —— **写死了门控，但配方本就存在**

| 位置 | 现状 | 判定 |
|---|---|---|
| `engine.hpp:110-111` | `slot_up() = gated ? gu_bytes : 0`；`slot_down() = (gated?2:1) * gu_bytes` —— **已是参数化「配方」** | ✅ 配方在 |
| `engine.hpp:116` | `gu_bytes` 注释 = *"one expert's **gate (or up)**, and its down"* ⇒ **单矩阵**，非 gate+up | ✅ |
| `Engine::moe()`（单 token）`:1967` | `gu_w = L.gated ? 2*n_ff : n_ff` | ✅ **单 token 路径已按 gated 参数化** |
| `Engine::moe()` `:1978` | `down.w[j] = c.slot + L.slot_down()` | ✅ **单 token 已调配方** |
| **`moe_rows()` `engine.cpp:2266`** | `const size_t gu2 = 2 * L.gu_bytes;` | ❌ **裸 2×，未调 `slot_down()`** |
| **`moe_rows()` `:2298`** | `const int64_t ff = n_ff_exp_, ff2 = 2 * ff;`（并用于 `mmq_->mul(..., gt, ff2, ...)` `:2323/:2359`） | ❌ **写死 2×** |
| **`moe_rows()` `:2326-2327`,`:2360-2361`** | 只调 `geglu_rows` / `swiglu_clamp_rows`（**门控激活**） | ❌ **无 relu2 分支** |
| **`stage()` `:2089`** | `gu2 = 2 * L.gu_bytes`；拷贝 `i%3==0` 拷 `exp_gate`、`i%3==1` 拷 `exp_up` | ❌ **无条件拷 gate** |
| **`relu2`** `kernels.cu:2658`（`include/…/kernels.hpp:118`） | **扁平 elementwise relu2，行无关** | ✅ **已存在 ⇒ `relu2_rows` 名为新函数、实为调它，不必新内核** |

⇒ **几何确实写死了门控**（2× 宽 + 门控激活 + 拷 gate），**但每一处都有现成配方可调**（`slot_up()/slot_down()`、`relu2`）。这正是此前所指的"部件都在、没合理调配"。

## ② 闸门 —— **唯一的 `L.gated` 在第 `1621` 行的合取首项**

- `engine.cpp:1621`：`L.mmq = **L.gated** && opt_.gpu_experts && rows_ >= kStageRows && Mmq::fits((int) L.gu_type, **2 * n_ff_exp_**, n_embd_) && …`
  ⇒ 除 `L.gated` 外，其余条件是 **`gpu_experts` / `rows_ ≥ kStageRows(=32)` / `Mmq::fits(2*n_ff, …)`**。
  ★ 注意 `Mmq::fits(..., **2 * n_ff_exp_**, ...)` 里那个 `2*` **又是门控宽度假设**（非门控该是 `n_ff_exp_`）。
- `batched()` `:1875`：`= mmq_ && L.mmq && n >= kStageRows`（`kStageRows=32`）。
- `--stage-ahead` 触发条件 `n >= opt_.stage_ahead`（默认 1024）**只写在 `moe_rows()` 里**（`:2123`）。

⇒ **放开非门控还需同时处理**：`L.mmq` 去 `L.gated &&`（并修它的 `Mmq::fits(2*n_ff)`）；确认 `mmq_`（= `Mmq::built()`）与 `rows_≥32` 对本模型成立。

## ③ 一行结论

**配方 vs 构造 ⇒ 配方。** 逐项：
- `ff2 = 2*ff` → `L.gated ? 2*n_ff : n_ff`（或用 `L.slot_down()/L.slot_up()` 派生）；
- `gu2 = 2*L.gu_bytes`（`moe_rows` + `stage`）→ `L.slot_down()`；
- 激活 → 非门控走**已存在的 `relu2`**（把 `geglu_rows/swiglu_clamp_rows` 的调用点按 `L.gated` 分叉）；
- `stage()` 的 gate 拷贝 → 按 `slot_up()` 门控（非门控不拷 gate）；
- `L.mmq` 的 `L.gated &&` 去掉 + `Mmq::fits` 的 `2*n_ff` 参数化。

⇒ **无新内核、无新构件**；本质是「把单 token 路径已用的那套配方，搬到批路径」。**方法上属"调配方"**。
