## §5 字节口径命中率（任务指定口径，A 级）

### §5.1 算式与数值

```
命中字节  = Σ_{被选中(层,专家)} count × 每专家帧字节
全部字节  = Σ_{所有 count>0}    count × 每专家帧字节
命中率    = 命中字节 / 全部字节 = Σcount(选中) / Σcount(全部)      （帧字节全相同，约掉）
```
- 每专家帧 = **3,096,576 B**（A：`pair_D_pb6912.log:3-82` 0.5×756.0 MiB/512 + 同）。
- **命中事件 36,851,956 / 全部事件 53,957,200 = 68.2985%**
- 字节形：**114.115 TB / 167.083 TB**（profile 会话尺度：该 profile 由 **61,315 token** 的会话生成 ⇒ 53,957,200 = 40 层 × 61,315 × 22）。
- 曲线（同 profile、同一贪心规则，D 级外推）：
  | 槽数 | 4,244 | **5,890** | 6,900 | 7,388 | 8,010 |
  |---|---|---|---|---|---|
  | 字节口径命中率 | 58.33% | **68.30%** | 73.47% | 75.74% | 78.43% |
  ⇒ 5,890→6,900（+1,010 槽）预测 **+5.17 pt**；→7,388 **+7.44 pt**（**给 R1 的"涨驻留"一个 D 级收益曲线**）。

## §6 "改成 per-layer 配额能多命中多少字节"（D 级推导）

**结论：不会多，会少。** 分两个口径说清（这两个口径的差别是本件最容易被误读的地方）：

1. **事件/字节加权口径（任务单指定，§5）**：等配额 147 ⇒ **−0.3906 pt = −210,773 次命中 = −652.7 GB**（= 210,773 × 3,096,576 B，profile 会话尺度）。floor=110 ⇒ −15.2 GB；floor=120 ⇒ −58.3 GB。
2. **提示路径的"去重搬运"口径（这才是 DMA 体积的直接来源）**：`moe_rows()` 对每个 (层,专家) **每轮搬一次、该轮所有 token 复用**（`engine.cpp:2254-2312`、`:2709`），所以 **DMA 体积 ∝ 去重后被路由的 (层,专家) 对数**，不是事件数。
   - 现贪心：20,275 个被触碰对中常驻 5,890 ⇒ **需搬去重对 = 14,385**（40 层合计）。
   - 等配额 147：常驻 5,880+10 ⇒ 需搬去重对 = **14,385（几乎不变，±10 对）**。
   - ⇒ **per-layer 配额对提示路径的 DMA 体积基本零影响**（±0.1 GB 量级）；它改变的是"哪些专家常驻"，只影响**事件加权的命中率**（decode 与 CPU 份额相关）。
3. **唯一可量化的好处**（若 P1 的动机是"层间搬运公平/最慢层"）：现分布下最坏单层"需搬去重对" = **396（L74）**；floor=120 时 **391（L21）**，floor=147 时 **365（L1）**（−7.8%）。**总搬运不变，只是把最坏层压平。**

**建议配额值（D，给 P1）**：
- **首选：不动**（保持现贪心 = §2 表；它已是全局最优）。
- 若必须有下限：**floor = 110 槽/层**（代价 −0.0091 pt ≈ −15.2 GB 命中字节，最坏层仍 396）。
- **不建议 147 等配额**（−0.3906 pt，且提示路径 DMA 体积并不因此下降）。
- 若 P1 想"压最坏层"：floor=120（−0.035 pt）把最坏层 396→391；floor=132（−0.115 pt）→380；floor=147 →365。**每压 1% 最坏层约付 0.03–0.05 pt 命中率**（由上述三点斜率）。

## §8 未验 / 边界

1. **【未验】profile 分布 vs 真实 p6792 prompt 分布**：本件所有命中率都是 **profile 会话（61,315 token）** 的口径。真实 prompt 的路由分布无落盘（没有 per-layer 路由 dump）⇒ 68.2985% 是**代理值**，不是 p6792 那一跑的实测命中率。**要让本件结论进 R1，需在 D 跑加一个按 (层) 的计数输出（零 GPU 不可得）。**
2. **【未验】"按层质量比例配额"是否会因 profile 漂移而优于贪心**：若真实 prompt 的层内分布与 profile 不同（例如更平坦），贪心可能被反超。本件只能证明"**在 profile 分布下**等配额必亏"。**这是 P1 唯一值得留的翻盘口。**
3. **【未验】概率化估计**：若把"prompt 的 6,792 token"当 profile 会话的随机子样本，则几乎每个被触碰的 (层,专家) 都会出现在 prompt 里（平均计数 2,661、p=4.3%），去重需搬 ≈ 14,385 对；与 D 跑计数器反推的 45,538 个副本差 3.2×（重复搬运，见情报A 前一件 §2.5）⇒ **两者一致，但"3.2× 重复"的成因未拆解**。
4. **【未验】第 5,890 名并列**：2,937 计数 × 5 个候选 ⇒ 每层分布有 **≤4 槽**的不确定性（表按引擎确定性序给出）。
5. **【未验】负控文件的来历**：`no-such-profile.txt` 文件名与内容（p_run/84 的缩放）提示它是人工/短跑生成的"假 profile"；本席未追其生成脚本（不在本任务范围）。
