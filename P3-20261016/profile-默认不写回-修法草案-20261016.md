# 修法草案：`--expert-profile` 默认不写回（只写草案，未改码）

> 依据：根因 = **profile 跨运行耦合**（`P3-20261016\pc_*.log` + `m5_*.log`：冻结 profile ⇒ 5 跑逐位同；不刷新 ⇒ 漂）。
> 本件**只是草案**，**未改任何码**，等队长批。

## 1. 现状（A 级 file:line）

| 行为 | 位置 | 条件 |
|---|---|---|
| **读** profile → `prior_`（决定驻留集合） | `engine.cpp:1488` | `if (!opt_.profile.empty()) read_profile(...)` |
| **写** profile（跑完/退出/服务应答后） | `engine.cpp:1696` `save_profile()` | 开头 `if (opt_.profile.empty()) return;` —— **只要传了 `--expert-profile` 就写** |
| 调用点 | `main.cpp:672` / `main.cpp:937` | 每次都调 `save_profile()` |

⇒ **传了 `--expert-profile` ⇒ 读 + 写都开** ⇒ 下跑加载的是上跑写下的 ⇒ **驻留集合跨跑变 ⇒ 数值变**（非确定）。
⇒ **不传 ⇒ 都不开**（`opt_.profile.empty()`）⇒ **正常用法不中招**。

## 2. 目标

**默认：只读、不写回** ⇒ 同一份 profile 反复用 ⇒ 逐位可复现。
**想让它"学习"的人显式开写** ⇒ 旗标门控。

## 3. 改法（旗标门控 · 只加不删 · 1 个新成员 + 1 个新旗标）

### 3.1 新成员（`runtime.hpp` 的 `Options`，或 `engine.hpp` 同级）
```cpp
bool profile_write = false;   ///< --expert-profile writes back only with this (default: read only)
```

### 3.2 新旗标（`main.cpp` 的 arg 解析，挨着现有 `--expert-profile`）
```cpp
else if (a == "--expert-profile-write") o.profile_write = true;   // 只加这一行
// 可选：env 等价 STRATA_PROFILE_WRITE=1（便于脚本）；两者取或
```

### 3.3 写侧守卫（`engine.cpp:1696` `save_profile()`，**只加一行**）
```cpp
void Engine::save_profile() const {
    if (opt_.profile.empty()) return;
    if (!opt_.profile_write) return;    // ★ 只加这一行：默认不写回
    ...
```
- **只加不删**：`read_profile`（`:1488`）与两处调用点（`main.cpp:672/937`）**不动**。
- 加一行后，`save_profile()` 在未开旗标时**提前 return** ⇒ **不建 `.tmp`、不改文件**。

### 3.4 默认行为变化（说清）
| 场景 | 改前 | 改后 |
|---|---|---|
| 不传 `--expert-profile` | 不读不写 | **不读不写**（不变） |
| 传 `--expert-profile` | 读 + **写** | **只读**（默认） ⇒ **跨运行确定** |
| 传 `--expert-profile --expert-profile-write` | 读 + 写 | 读 + 写（**与改前一致**，opt-in） |

### 3.5 帮助文本（`main.cpp:740` 区，只改文案）
```
--expert-profile FILE   read to choose the cached experts; written back only with --expert-profile-write
```

## 4. 负控（怎么变红）

| 臂 | 命令 | 判据 |
|---|---|---|
| **默认（不写回）** | `--expert-profile p.txt`（无 `-write`）**跑 2 次** | `md5sum p.txt` **跑前 = 跑后**（**必须不变**）· 2 跑的 `--top-probs` 逐位同 |
| **旗标（写回开）** | `--expert-profile p.txt --expert-profile-write` 跑 1 次 | `md5sum p.txt` **跑前 ≠ 跑后**（必须变）⇒ 证明写侧确实被旗标打开 |

⇒ **两条都成立**才叫修好（默认不变 / 旗标会变）。**只有一条 = 没鉴别力。**

## 5. 性能影响（应当为零）

- **驻留决策仍读同一份 profile**（`read_profile` 未动）⇒ **选谁在 VRAM 的逻辑不变**。
- 写回发生在**跑完/退出**（`main.cpp:672/937`），**不在生成路径上** ⇒ **不占 tok/s**。
- ⇒ 预期 **decode/prefill 中位数不变**（按跑法纪律报机制散布核对）。

## 6. 未验 / 取舍

- **未验**：改后实测（本件未改码）。
- **取舍**：默认不写回 ⇒ **引擎不再自动"学到"新 profile**；要更新须显式 `--expert-profile-write`（或另设"离线攒 profile"流程）。**这是有意的**：把"跨运行状态"从隐式变显式。
- **替代方案**（备选，不推荐）：默认仍写但**写成后带上内容哈希**、下跑只读"同名同哈希"——复杂且仍会变 ⇒ 不取。
