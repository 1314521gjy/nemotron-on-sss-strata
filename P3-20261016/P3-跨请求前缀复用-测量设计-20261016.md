> 队列项 P3（`后续计划-夜间-20261016.md`）："`--prompt-cache` 默认开，我们单跑没吃到"。
> ★★ **本件的定性：这属「测量口径」，不是「引擎未开」**（**不许记成缺陷**）—— 见 §1。
> **只读 + 零 GPU**（我在本机读源码；未跑 serve、未占窗口）。**AI：deepseek-flash[1m]** ⇒ **自验，不构成独立验收**。

## §1 ★ 为什么"单跑吃不到"—— 读码定死（A），**三句话**
1. **缓存是【进程内】的，不落盘** —— 载体是 `Conversations<Engine>`（`main.cpp:302`，`Session` 的成员），checkpoint 是 **host 内存里的 blob**（`conversations.hpp:179-187` `Blob`/`Checkpoint`；parking 也只在 RAM，`park_mib` 默认 **0 = 不 park**）。⇒ **跨进程复用【结构上不可能】**。
2. **默认确实"开着"** —— `CacheOptions{checkpoints = 6, every = 2048}`（`conversations.hpp:30-31`），**不给 `--prompt-cache` 也是 6**（`main.cpp:852` 只在显式给时改）。
3. **但单跑只有一个请求** ⇒ `resume()` 找不到任何"留下的"对话（`conversations.hpp:60-64`：`at == 0 ⇒ e_.reset()` ⇒ **全量重读**）⇒ **一次都吃不到**。
★ ★ **而且单跑【连"复用了多少"都看不见】**：`once()` 的进度回调是**空 lambda**（`main.cpp:712`），而 `RESUME`/`reused` 只在 **serve** 路径打（`main.cpp:642-651` · `:666-668`）。
⇒ **⇒ 本项的结论：要吃到它，必须【同一个进程里有 ≥2 个请求】** —— 这是**跑法口径**，不是引擎缺功能。

---

## §2 ★ 四种复用形态（读码定死，决定"怎么跑"）—— **A**
`resume()` 取 `at = max{ checkpoint pos ≤ min(共享前缀长, n−1) }`（`conversations.hpp:216-223` `reach()`）；checkpoint 只在三处取：**每个 prompt 的最后一个 token 之前**（`:93-96` `before(at,last)`）· **每 `--prompt-cache-every` 个 token**（默认 **2048**）· **`turn_at=` 指定的 turn 起点**（`:81`）。

| 形态 | 怎么跑 | `at`（复用起点） | 第二次读多少 | 需要额外配置？ |
|---|---|---|---|---|
| **A 追加/续写**（第 2 个 prompt = 第 1 个 **+ 更多**） | 同一进程发两请求 | **`at = n₁`**（引擎"就在那儿"，`:218` 特例） | `n₂ − n₁` | **零** |
| **B 全前缀、非追加**（第 2 个以第 1 个**整个**开头但更短/相等） | 同上 | **`at = n₁ − 1`**（prompt 末尾前那个 checkpoint） | `n₂ − n₁ + 1` | **零** |
| **C ★ 部分前缀**（只共享前 L 个，L < n₁−1） | 同上 | `at = ≤L 的最大 checkpoint` | `n₂ − at` | ★★ **必须 `--prompt-cache-every ≤ L`**（默认 2048 时 **`at = 0`、reuse 归零**） |
| **D 多轮对话** | 带 `turn_at=` 发请求 | `at = turn 起点` | 新 turn 的长度 | 调用方要知道模板的 turn 起点（server 侧） |

- ★★ **形态 C 是本靶最容易踩空的一条**：**700 token 的 prompt 配默认 `every=2048` ⇒ prompt 内【一个 checkpoint 都没有】**（只有末尾那个）⇒ **任何"共享 300~400 token"的请求都会 `RESUME 0`**。
  ⇒ **做 P3 实验时必须显式给 `--prompt-cache-every`（建议 128/256）**，否则会**误判成"缓存不生效"**。
- ★ 注意 **`reach` 用 `min(共享前缀, n−1)`** ⇒ **最后一个 token 永远要重读**（注释 `:91-92` 明说：留一个 token 才有 logits）⇒ **"复用率"的上限 ≈ (n−1)/n，不是 100%**。

## §3 ★ 怎么跑（可执行）—— `--serve` 是本靶**唯一**能观测复用的路径
**协议**（`main.cpp:6-7`）：`GEN <max_new> [key=value …] <ids csv>` 进；`RESUME/PP/T/DONE/ERR` 出；`QUIT` 结束。`turn_at=<n>` 是合法键（`main.cpp:514`）。
```bash
# 形态 B，最省事的一次自证（同进程两请求，前缀完全相同）
IDS=$(cat tok700.txt)          # 700-token prompt 的 id 序列（现成件）
{ printf 'GEN 1 %s\n' "$IDS"; printf 'GEN 1 %s\n' "$IDS"; printf 'QUIT\n'; } \
  | strata-poly --model <gguf> --serve --prompt-batch 1024 --stage-ahead 128 \
      --no-draft --lookup 0 --vram-reserve-mib 2500 --prompt-cache-every 256 --expert-profile p_run.txt
```
**每请求的读数**（**都在 stdout，逐请求**）：
- `RESUME <at>` —— **复用起点**（第 2 次请求应有 `at > 0`）；
- `DONE <produced> <n> <prompt_ms> <decode_ms> <finish> <g_right> <g_offered> **<resume>** <hits> <hits+misses> 0 0 0.0 **<read>** 0`（`main.cpp:660-668`）
  ⇒ ★ **判据就取 DONE 的【第 8 字段 = resume】与【第 14 字段 = prompt tokens read】**；
- `PP <at> <total> <ms> <tok/s>` —— 读的进度。
**退出时的聚合行**（stderr）：`N of M prompt tokens were not read again (X%)`（`main.cpp:679-682`）—— **一行就是总复用率**。

## §4 ★★ 判据（**能变红**）
| # | 判据 | 门 | 变红条件 |
|---|---|---|---|
| **C1** | 第 2 个请求 **`RESUME at > 0`** | 形态 A ⇒ `at = n₁`；形态 B ⇒ `at = n₁−1`；形态 C ⇒ `at ≥ 最小可用 checkpoint` | **`RESUME 0` ⇒ 缓存没生效**（先查 §2-C 的 `every`） |
| **C2** | 第 2 个请求 **`read`**（DONE 第 14 字段） | **= `n₂ − at` ± 1**；且 **≪ n₁** | `read ≈ n₂` ⇒ 没复用 |
| **C3** | 第 2 个请求 **`prompt_ms`** | **显著低于**首次的 `prompt_ms` | ★ **不降 ⇒ 复用没落到时间上**（**注意**：**不许假定线性** —— 报 `ms / read-token` 两个值，别只报倍数） |
| **C4** | **聚合行** `reused / asked` | ≈ `(n₁−1)/(n₁+n₂)`（形态 B） | `= 0` ⇒ 没吃到 |
| **C5** | ★ **正确性：复用不改输出** | 复用跑与"全量读"跑的 **`T` id 序列逐位相同** | 有分歧 ⇒ **复用在数值上不等价**（本应"bit for bit"，`:8`） |
| **C6** | ★ **`--top-probs` 浮点级**（**本靶做不到，见 §5**） | —— | —— |

### §4.1 ★ 负控（**必须能变红**，否则判据是废的）
| # | 负控 | 做法 | 预期 |
|---|---|---|---|
| **N1** | **不同前缀** | 第 2 个请求换**完全不共享前缀**的 prompt | `RESUME 0` · `reused 0` · `prompt_ms` 与首次同量级 ⇒ **C1~C4 必须报红** |
| **N2** | **关缓存** | 同前缀，但加 `--prompt-cache 0`（`conversations.hpp:85/94/110` 全部早退） | 第 2 个请求也 `RESUME 0` ⇒ **证明读数确实来自 cache** |
| **N3** | ★★ **跨进程（= 我们现在的跑法）** | 两次**单跑**（两个进程） | 无复用、**且 `RESUME` 这一行根本不出现**（`once()` 不打印）⇒ **这就是"单跑吃不到"的实证** |
| **N4** | **部分前缀 + 默认 `every`** | 形态 C，**不给** `--prompt-cache-every` | `RESUME 0` ⇒ **实证 §2-C 那条坑**（这是本件最值钱的负控） |
### §4.2 正控
- **同进程两请求 + 全前缀相同 ⇒ `reused > 0`**（已知会动的量）—— 与 N1/N2/N3 成对。

## §5 ★ 两个**必须写清的限制**（否则会误判）
1. ★ **`--serve` 路径【不打印 `top-probs`】**：`print_top` 只在 `once()` 里调（`main.cpp:709`），serve 的 T 回调只有 `printf("T %d")`（`:638-641`）⇒ **C6 浮点级在 serve 下取不到**。
   ⇒ **C5 只能降为 id 级（`T` 序列）**；**若要浮点级，需要 builder 在 serve 的 T 回调旁加 `print_top(ss.picked_from, …)`** —— **属改码，须报队长批**（本席不改码）。
2. ★ **复用只对【多请求】工作负载有意义**（agent 多轮 / server 场景）；**对单跑性能基线它【不贡献】** ⇒ **不许把 P3 的收益算进 `G0''` / 四档基线的读数**。
