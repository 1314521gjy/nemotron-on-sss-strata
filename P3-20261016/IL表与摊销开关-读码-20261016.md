## 1.3 ★ `docs/MMVQ_IL_TABLE.md` 的关键规则（原文）

| 规则 | 原文 | 行 |
|---|---|---|

**★ 对我们的一个精确点（A）**：表的数据结构是 **`struct IlRows { int type; uint8_t r[3][5]; }`**（`native_mmvq.cu:2885`）⇒ **只覆盖 type 23/12/13/14 = IQ4_XS/Q4_K/Q5_K/Q6_K**（`:2886-2891`）。

⇒ **出 sm_89 表时，"IQ4_NL 那行"根本不存在**（不是"测出来是 0"，而是**表里没有这个 type**）；**别为它拼 env 条目**（拼了也不会被任何投影用到 —— 除非将来换量化类型）。

## 1.4 ★★ `STRATA_MMVQ_IL_ROWS`：确切语法 + 解析（`native_mmvq.cu:2966-2996`）

```cpp
// STRATA_MMVQ_IL_ROWS="type:ncols:r0,r1,r2,r3,r4;..."   ← 原文注释 :2966-2967
sscanf(..., "%d:%d:%d,%d,%d,%d,%d%n", &t,&n,&r[0..4], &used) >= 7 && n >= 1 && n <= 4
```
| 项 | 规则 | 出处 |
|---|---|---|
| **语法** | `type:ncols:r0,r1,r2,r3,r4`，**多条用 `;` 分隔**；**末尾分号可有可无**（`find(';')` 到串尾即止） | `:2976-2979` |
| **type** | ggml type，**表内有效的是 12/13/14/23**（Q4_K/Q5_K/Q6_K/IQ4_XS） | `:2886-2891` |
| **ncols** | **1–4**（代码判据 `n>=1 && n<=4`；文档写 2–4） | `:2981` |
| **r0..r4** | **每个 ∈ {0,1,2,4}** ⇒ 否则**该条被丢弃并打 stderr** | `:2984-2986` |
| **五个数的含义** | **五个 n_out 行数类**：`<2048` / `<4096` / `<8192` / `<12288` / `≥12288`（**不是 token 数**） | `:3002`、`docs:27-28` |
| **格式读不出** | **打 stderr 后忽略该条**（**不致命**） | `:2987-2990` |
| **解析次数** | **只解析一次**（函数内 `static`） | `:2970` |
| **★ 覆盖优先级** | **env 表在 arch 表之前查** ⇒ **对任何卡（含 sm_89）都生效**，且**优先于** `kIlArch`/`kIlRowsShared` | `:3003-3004`（env 在前），`:3014-3017`（arch 在后） |

**照敲示例**（给 Q4_K、3 列、行数≥4096 的类都取 1）：
```bash
export STRATA_MMVQ_IL_ROWS="12:3:0,1,1,1,1;12:4:0,1,1,1,1"
./strata-poly.exe …                      # git-bash：必须 export 或 VAR="…" ./exe（`env VAR=… exe` 会静默不执行）
```

**★★ 一条"自证"方法（本席提出，非读到的）——因为拼错是静默失效**：
env 只在不合法时打 stderr，**合法时不打任何东西** ⇒ 你**无法从输出判断它到底生效没有**。⇒ **零成本自证**：先跑一次**故意非法**的值，例如
```bash
export STRATA_MMVQ_IL_ROWS="999:x"      # 故意非法
./strata-poly.exe … 2>&1 | grep STRATA_MMVQ_IL_ROWS   # 期望看到 "cannot read '999:x' …- ignored"
```
**能看到那行 ⇒ env 通路是通的**（这也同时证明 git-bash 没把 env 吞掉）；**看不到 ⇒ env 没传进去，后面所有"设了却没变化"的结论全部作废**。（与 t17 的"双向自证"同一思路。）

# §2 ★ 摊销两条的语义（回答"可摊销还差什么"）

## 2.1 各自是什么、默认值、与 MTP 的关系（A）

| 开关 | 机制 | 默认 | 出处 |
|---|---|---|---|
| **`--lookup N`** | **prompt-lookup 起草**：「guess what followed an earlier repeat of **the last N or more tokens**」⇒ 在会话历史里找**上次出现相同后缀**的那段，把它的续写当草稿 | **默认 3**；**0 = 从不** | `main.cpp:750-751`（help）、`:817`（`int top_probs = 0, lookup = 3`）、`:841` | 
| **`--no-draft`** | 关掉"向前猜"的块 | 默认 **开**（`Options::draft = true`） | `main.cpp:752`、`:842`、`engine.hpp:70` |
| **`--draft-model FILE`** | ★ **"a file of the same model to take that block from, when `--model` has none"** ⇒ **备选来源**，不是 MTP 的载体 | 空 | `main.cpp:753-754` |
| **`--draft-vocab N`** | 草稿只在词表**前 N** 个 token 里猜（`-1` = 按架构的 `guess_vocab()`；`0` = 全词表） | `-1` | `main.cpp:755-756`、`engine.hpp:71`、`:172` |
| **`--window N`** | 一次 `window()` 最多取多少 token（含草稿） | **8**（其中草稿 3） | `main.cpp:748-750`（help 前段）、`engine.hpp:68-69` |
| **`--prompt-cache N`** | 会话保留的检查点数（个，RAM ~150 MB/个） | **6**；`0` = 只在上次 token 相接时续读 | `main.cpp:772-773`、`:852` |
| **`--prompt-cache-every N`** | 除"prompt 末尾那一个"之外，**每 N 个 prompt token 再存一个** | **2048**；`0` = 不存 | `main.cpp:774-775`、`:853` |

## 2.2 ★★ MTP 的载体**不是** `--draft-model` —— 是**模型文件自带的块**（A，含既有判定）

- **读码（A）**：`engine.cpp:686-690` —— `nextn = meta_in("nextn_predict_layers")` ⇒ **`n_layer_ = block_count − nextn`**（本靶 = 89 − 1 = **88**）；`probe = blk(n_layer_, "nextn.eh_proj.weight")`；**命中 ⇒ `block_ = gg_.get()`（同一个模型文件）**；`draft_ = block_ && !nextn.embed_tokens && !nextn.shared_head_head`（`:696-697`）；`drafts()` 返回 `draft_`（`engine.hpp:239`）。
- ⇒ **本引擎没有 `--mtp`（正确）**；**MTP = `draft` 这条通路**；**我们的模型自带 MTP，不需要外挂文件** —— **`--draft-model` 只在"主模型文件没有这个块"时才用**。
- **★ 既有判定（引用，不重做）**：`G2b-MTP通路判定-20261016.md:13-14,46` 已判 —— **poly 的 MTP 是"内置"且默认开**；`nextn_predict_layers=1`、`n_layer_=88`；且本靶**不**自带 `nextn.embed_tokens`/`shared_head_head` ⇒ 正好走**"共享 lm_head"**那条（`engine.cpp:688-689` + `draft_step` 的 `Dev head = output_`）。
- **★ 实存性（A）**：`E:\models\Nemotron-3.5-Super-VL-120B-A12B-Q4_K_M\` 下**只有两个 GGUF 分片**（`-00001-of-00002` / `-00002-of-00002`）+ `expert-profile*.txt` / `p_master.txt` / `p_run.txt` / `sha256_local.txt` / `aria2.log` ⇒ **没有任何独立的 draft/MTP 文件**（全机 `E:\models\` 顶层也没有 MTP/draft 件）⇒ **`--draft-model` 在本机无从可指，也不需要**。
- ⚠️ **但仍不能开**：`G2b` 已判 **"机制齐、接线缺 3 处"**（缺 `block_attend()`、`L.ffn_norm` 从不被设 等）⇒ **现在打开 MTP 是"半载运行"**。（本件**只引用**该判定，不重述。）

## 2.3 ★ 性质：**两者都是"改结果"的近似开关** ⇒ 不能进基线

- **`--lookup` 是"用历史重复猜"** ⇒ 猜错就改了输出（日志有 `N of M guessed tokens right`，`main.cpp:719/724`）；
- **draft/MTP 是"用草稿块猜"** ⇒ 同。
- **⇒ 按项目纪律**：canonical **必须钉死 `--no-draft --lookup 0`**（`跑法纪律 §2.3 D6`）；要测投机**单独成档 + 必配正确性判据**（`token ids` + `--top-probs` 逐位）。
- **库内两条同族**：`KP-MOEDEP-0029` 把投机列在**"已排除清单"**；`KP-MOEDEP-0028`：**"质量走 CLI 非推测路径；serve+MTP 只做速度实验"**（干净率 0/4 vs 8/8）。⇒ **方向与我们的 D6 一致**。

## 2.4 ★ `--prompt-cache`：**引擎默认就开着**，是我们**单跑**用不上 —— 属"测量设计"

- **默认值（A）**：`--prompt-cache 6`（6 个检查点，每个 ~150 MB RAM）、`--prompt-cache-every 2048`（`main.cpp:772-775`、`:852-853`；`CacheFlags` 的 `checkpoints`/`every`）。`0` 的语义：`--prompt-cache 0` ⇒ "prompt 从头上读，除非它从上一次最后一个 token 接着写"。
- **为什么我们一次没吃到**：**每次都是新起的单跑进程 + 单请求** ⇒ 没有任何"跨请求"的机会去命中检查点（检查点是**内存里**的，进程退出即失）。
- **★ 要吃到它得这么跑**：**一个 `--serve` 进程连发多个请求**，且**后一请求的 prompt 与前面某次的 prompt 有公共前缀** ⇒ 前缀部分**不必重读**。`--prompt-cache-every N` 决定"多密"存点（默认每 2048 token 一个 + prompt 末尾一个）⇒ **前缀越长、点越密，命中越多**。
- **★ 读数在哪**：`--serve` 退出时打 **`strata-poly: N of M prompt tokens were not read again (xx%)`**（`main.cpp:679-682`）⇒ **这就是"摊销吃到没吃到"的自证读数**。
- **⇒ 分类**：**这是"测量设计"问题，不是"引擎没开"**；引擎**默认开 6 个检查点**。**⇒ 别写"引擎不支持前缀复用"**（那会错）。
