## §1 新 canonical 与**三道默认闸门**（这是"照默认跑 = 把 prefill 关掉"）

**现役 canonical**：`--prompt-batch 1024 --stage-ahead 128 --stage-mib 1024` + **冻结 profile** + `--no-draft --lookup 0`
⇒ **prefill 中位 169.8**（166.6 / 174.7 / 169.8，**MAD 2.8%**）· decode ~60 · 命中 97.1%。

**三道闸门（照引擎默认跑，每一道都会把 prefill 关掉或压住）**：

| 闸门 | 引擎默认 | 为什么是"关" | 出处 |
|---|---|---|---|
| **① 批路径的门** | `--prompt-batch 1024`（但**旧 canonical 是 8**） | `--prompt-batch 8` ⇒ **不进批路径**（`batched()` 要求 `n ≥ kStageRows = 32`） | `engine.cpp:1877`、`engine.hpp:50` |
| **② 重叠的门** | `--stage-ahead 1024` | **门 = `n ≥ sa`**，`n` = **本次调用的 token 数**；我们 prompt **700 < 1024** ⇒ **一次预取都不做**（= `sa=0`） | `engine.cpp:2197`；本席 `stage语义与sa门-读码-20261016.md` |
| **③ 缓冲配比** | `--stage-mib 2048` | **默认落在平台（768–1024）之外**（2048→125.6 vs 1024→169.8） | `engine.hpp:51-53`；§3 |

**★ 三条齐开：29.5 → 169.8 = 5.76×**（`--prompt-batch 8` = 重叠关着的旧口径）。
**★ `--help` 逐字**：`--stage-mib N` 的默认值写的就是 **"default 2048, or what a layer's experts take when that is less"** ⇒ **引擎自称的默认值与"我们这靶的最优"差了 36%**。

## §2 重叠的净贡献 = 9.26×（单变量、可复现、机制交叉印证）

| **`G2a` `sa=0`（无重叠）** | 13.7/13.6/13.2 | **13.6** | 1.09% | 59.9 | **9.0%** | **66.4/67.1/69.3** | **2.5** |

## §3 `--stage-mib` 配比：**+36%，且是连续机制**（默认在平台外）

| `--stage-mib` | **768** | **1024** | 1200 | 1400 | 1536 | **2048（默认）** |
|---|---|---|---|---|---|---|
| prefill | **170.2** | **169.8** | 145.8 | 128.0 | 125.1 | **125.6** |

- ⇒ **平台 = 768–1024**；**从 1024 到 1536 是连续下降**（145.8 → 128.0 → 125.1），**不是台阶**。
- **★ 第 6 点否掉了我早先的一个候选**（见 §11 自纠）。
- **另一条 A 级旁证（运行级）**：`sm768_r1.log`（`sm=768`）arena = **7144 对 / 20.6 GiB**，而 `p0cb_sa1024_sm8192.log`（`sm=8192`，被夹到 **1512 MiB**）arena = **6892 对 / 19.9 GiB** ⇒ **差 252 对 = 744 MiB = 1512−768** ⇒ **① `stage` 与 arena 是 1:1 抢**；**② `--stage-mib > 1512` 被 `n_expert_×one_expert` 夹住**（本靶 = **1512.0 MiB**）。
  ⚠️ **但命中在 `sm` 扫描里恒 97.1%** ⇒ **arena 少那 252 对不足以解释 36% 的速度差** ⇒ **主因不是"抢显存"**（本席读码结论）。

## §4 `--stage-ahead` 的门 = `n ≥ sa`（长 prompt 上被验证）

- **门原文**（`engine.cpp:2197`）：`ahead = stage_ahead > 0 && (n >= stage_ahead || shared_ahead_)`，**`n` = 本次 `eval` 调用的 token 数**（不是 prompt 总长、不是批上限）。
- **我们 700-token prompt + `n_calls == 1`** ⇒ **700 < 1024 ⇒ `ahead=false`** ⇒ **等价 `sa=0`** ⇒ 拿到 `G2a` 那组（13.6 / 命中 9.0% / CPU 67）**逐项吻合**。
- **★ 直接验证**：**长 prompt（2100 token）下 `sa=1024` = 219.7**（**不是 13.6**）⇒ **门判读成立**（`shared_ahead_` 那条支路在"一次读多个调用"时才起作用，见 §11 与 verifier 的对齐）。
- ⇒ **纪律**：**`--stage-ahead` 必须 ≤ 你的 prompt 长度**（我们钉 **128**）。

## §9 ★ 负结果（同等重要）：**MMVQ ILP 表对本靶无收益 ⇒ 不改码**

- **前置**：`mmvq_il_parity` **逐位对拍全过** ⇒ **表可用**（`mmvq_il_parity: OK (every case, T 1-4, rows 1/2/4 and the table, bitwise)`）。
- **★ 但 emit 出来对我们是"全 0"**：
  ```
  {23, {0, 1, 0, 1, 0}},   // IQ4_XS
  {12, {0, 0, 0, 0, 0}},   // Q4_K   ← 我们的主类型
  {13, {0, 0, 0, 0, 0}},   // Q5_K
  {14, {0, 0, 0, 0, 0}},   // Q6_K
  {11, {0, 0, 1, 1, 1}},   // Q3_K
  ```
  ⇒ **`ffn_up_exps` / `latent_*` / `sh_up` = Q4_K(12) → 表给 0（走 plain kernel）**；**`ffn_down_exps` = IQ4_NL（ggml type 20）→ 根本不在表内** ⇒ **三个投影无一能吃到 IL**。
- **且**：**新 canonical 的 prefill 走 `moe_rows()`（`Mmq::mul`），不过 `native_mmvq`** ⇒ **表的作用面本就只剩 decode**（我方推论，**未逐处核**）。
- **⇒ 建议：不改码**（加表 = 加一段对本靶**恒为 0 的死表**）；**若将来把 `ffn_down_exps` 换成表内类型（IQ4_XS/Q4_K），再重跑该 bench**。
- **出处**：`回执\R-20261016-P0-b.md`（= `回执\P0-b.md`）· `il_bench.log`（全量 BENCH + emit 块）· 本席 `IL表与摊销开关-读码-20261016.md`。

## §10 口径纪律收获（可并入卡）

1. **命中率必须同报 `--prompt-batch` 与是否 `--dump`**（批/prefill 路径**不进**那个比值的分子；`--dump ⇒ rows_=1 ⇒ 全非批路径`）⇒ 跨配置比命中率 = 口径不一致。出处：本席 `命中率分段取数方案-20261016.md`（已入 `KP-UNI-0245`）。
2. **弃预热 + 用 MAD**（**别用 `s_max` 式**：对单点过敏，一个坏点会永久卡死一条线）。
3. ★ **"别人的数字/默认值不能照搬"四例**：`--cpu-share 0.55` · `--expert-cache 11000`（**本引擎无此旗标**）· `--vram-reserve-mib 256` 当反组（实测**反向**）· **引擎自带的两个默认值 `sa=1024` / `sm=2048`**（依据分别是"8 GB 卡 + 约 1000 token"与"Q2_K 模型的一层漏出量"，**都是别的卡/别的模型**）。
4. **机制分工必须分两段报**（prefill / decode 各一个中位；**两臂 decode 相同 ⇒ 该变量只作用于 prefill**）。

## §11 ★ 自纠一条（本席早先的候选被这 6 点曲线否掉）

- **我早先（`stage语义与sa门-读码-20261016.md` §1.3）基于 4 点表**（768/1024/1536/2048）判为**"两个平台"**，并给出首选候选：**"默认把整层塞进一轮 ⇒ 无轮间流水；小缓冲拆 2 轮 ⇒ 更快"**。
- **★ 现在这 6 点（含 1200→145.8、1400→128.0）显示是"连续下降"** ⇒ **"轮数台阶"说的预测（台阶）不成立** ⇒ **该候选被否**。
- **改判（现采信）**：**`stage_bytes_` 越大 ⇒ 越多非缓存专家被列入 `L.ahead`（上限 = `stage/(2·gu+d)`）⇒ 预取量与"可隐藏窗口"失衡 ⇒ 多出来的搬运摊在关键路径上** ⇒ **连续变慢**；**上限 1512 MiB 的夹取仍成立**（1536 ≡ 2048 ✓，两臂 125.1 vs 125.6 相等）。
- **仍成立的**：① `stage` 与 arena **1:1 抢**（§3 的运行级旁证）；② `--stage-mib > 1512` 被夹（**A 级**）；③ **主因不是"抢显存"**（命中恒 97.1%）。
- **待验（能变红）**：若"预取失衡"说成立 ⇒ **在 `sa` 固定为 128 时，`sm` 从 1024 往下（512/768）应当持平或更慢**（因为 ahead 太小、后段要路由后才拷）⇒ **扫 512 即可判**。
