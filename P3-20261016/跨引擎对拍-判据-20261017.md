## §2 可以并列 / 不可以并列
### 2.1 可并列（**且仍须满足 §3 的硬前提**；缺失即降为"仅量级"）
| 量 | 并列时的口径 | 备注 |
|---|---|---|
| **同一 prompt 长度档下的 `prefill tok/s`** | 同长度档 · 同"有无投机" · 同 ids 数 | ★ 但**跨模型** ⇒ **只能作量级**（§1） |
| `decode tok/s` | 同上 + **同报长度与停止原因** | 同上 |
| **端到端墙钟** | 同 `--max-new` | 与 tok/s 同源，冗余 |
| **显存峰值** | ★ 必须写明**含不含**：权重 / KV / 专家缓存 / CUDA context | 口径不清 ⇒ 退回 |
| **装载时间** | ★ 必须写明**制品格式与读取方式** | **GGUF vs `.ninfer` 不同族，且 70 GB vs 113 GB** ⇒ **只作量级** |

### 2.2 **不可并列**（写死）
| 量 | 为什么不行 |
|---|---|
| **`experts from VRAM` 命中率** | **是我们引擎的私有定义**（实例计数、`main.cpp:715-722`），**且是 decode-only**（批路径命中去 `batch_*`，`engine.cpp:2367-2368`）⇒ 两侧**同名不同物**、**别家没有这个量** |
| **每轮产量 / 接受率** | 取决于**各自投机实现**（我们的 `Guesses`/`DraftPolicy` vs 他们的 `--spec`/`draft-tokens`）⇒ 不具可比性 |
| **任何"档内数字"** | `--stage-mib` / `--prompt-batch` / `--vram-reserve-mib` / `--window` 等**都是本引擎私有旋钮**；对方的是 **env `NINFER_*`** ⇒ ★ **同名不同物，不许把对方的档位名当我们的旗标** |
| **"我们比它快/慢 N 倍"** | ★ **纪律禁止**（无量级限定的表述）⇒ 见 §4 |

## §3 ★ 并列的硬前提（**缺一即可比性作废**）—— 逐条给"若如何则不可比"
| # | 前提 | **若如何 ⇒ 不可比** | 现状 |
|---|---|---|---|
| **P1** | **同模型** | 不同模型 ⇒ **tok/s 不可并列**（只作量级） | ❌ **两侧不同模型**（§1）⇒ **永久不满足** |
| **P2** | **prompt 长度档对齐** | 长度档不同 ⇒ **prefill tok/s 不可并列**（prefill 是长度敏感量） | ❌ 我们是 `{700, 2100, 4096}`；对方脚本是**一句英文短 prompt**（`run-baseline.ps1:38`，约 25 词） |
| **P3** | **是否无投机** | 一侧开投机 ⇒ **decode 数字不可比**（每轮产量不同） | ⚠️ 对方有 `--spec none/dflash2` 分臂；我们 canonical = `--no-draft --lookup 0` ⇒ **必须同侧** |
| **P4** | `--max-new` / ids 数 | 不同 ⇒ 端到端与 decode 均不可比 | ✅ **两侧都是 64**（对方 `:94`；我们 canonical）—— **这一点恰好对齐** |
| **P5** | ★ **是否开 CUDA graph** | 一侧关 ⇒ 数字不可比（发射结构不同） | ❌ **对方 argv 里是 `--no-cuda-graph`**（`:94`）；**我们 canonical 开着**（决策记录，`engine.hpp:65`） |
| **P6** | KV 精度 / ctx / chunk | 不同 ⇒ decode 与显存不可比 | ❌ 对方 `--kv-dtype fp8 --max-context 32768 --prefill-chunk 128`（`:92-94`）；我们 KV 由引擎定、ctx 未在 canonical 固化 |
| **P7** | **机器 / 制品** | 不同 GPU/带宽/内存 ⇒ 只作量级 | ❌ 跨机（且制品 113 GB vs 70 GB） |
| **P8** | **档位与取数方式** | 一侧**单跑**、一侧**中位+MAD** ⇒ 比"中位"时分母不可比 | ❌ 对方脚本是**单跑 + sha 闸门**（无重复、无散布） |

⇒ **P1/P2 已经触发** ⇒ **本次【不能】做数字对拍**，只能出**量级**与**机制对表**。

## §4 ★ 等级与用语纪律（照 KB）
- **外部来源一律标 `C`**（他人机器、未见其原始 log）。
- ★ **"配不出完整配置档的只当量级、不许进阶梯"**（`KP-ENGSPEED-0013`）⇒ 对方的**完整配置**（env 全表 + argv + 制品 + 卡型）**多半配不齐** ⇒ 其数字**不得进我们的配方阶梯**。
- ★ **"别人的配方不能当我们的参数"**（`KP-UNI-0171`）。
- **句式白名单（写死）**：
  - ✅ `同长度档下、量级为 X（C 级，不同模型）`
  - ✅ `两引擎在各自模型上的 prefill 量级相当 / 相差一个量级`
  - ❌ `我们比它快 N 倍` · ❌ `它对标我们` · ❌ 任何**没有"量级/限定词"的倍率**

## §7 顺带评估：`run-baseline.ps1` 的 **64-id sha 闸门**（`193AC9FB…`）值不值得借
**它是什么（A，我读了脚本）**：三臂 `off / tree / sabotage`；把 `r.err` 里的 generated ids 落成 `ids.txt`（**ASCII、一行一 id、CRLF、末尾换行**），再 **SHA256** 与 `193AC9FB01A8…A36BCA` 比对（64 个 id、**369 B**）⇒ **"输出确定性闸门"**（D-3 gate）。

### ★ 值得借的两点
1. **把 ids 落成"字节格式写死"的文件再摘要** —— 脚本原文：*"A digest computed any other way is an **incomparable number**"* ⇒ **这正是我们的"口径三要素"**（格式本身就是口径）。
2. ★★ **它有 `sabotage` 臂**（故意让判据该红），并引 *"**A judgement nobody has seen fail is not a judgement**"* ⇒ **与我们"负控必须先能变红"是同一条纪律** ⇒ **可引作跨引擎旁证**（两家的工程纪律在此处撞上了）。

### ★ 不建议照搬的三条
1. **全长 sha 会把"长度/停止点漂"判成红** —— 而我们的口径**明确不计违反**（timing 依赖，`确定性回归判据 §1`）⇒ **会误报**；
2. **整串 sha 无法定位分歧**（我们要的是"**共同前缀 + 首个分歧位置 + 两侧 token 对**"）；
3. **它只是 id 级** —— 我们**吃过"只比 id 会漏（末位漂未翻 id）"的亏** ⇒ 必须配 `--top-probs`（浮点级）。

### ⇒ 我的结论（**只评估、不改码**）
- **借思想，不借闸门**：若要一个**快速冒烟**，用 **"固定长度前缀的 sha"（长度取两侧共同前缀的下界）+ 共同前缀长度 + 首个分歧位置**，**不要全长 sha**；且它**只能当冒烟，不能替代 id + 浮点双判**。
- **我们不必引入新工具**：`perf_baseline.py` 已内建"共同前缀 + 每跑序列落报告"的判据 ⇒ **零收益、不动码**。
- ★ **唯一值得抄的是"三臂结构"**：`off / 变体 / **sabotage**` ⇒ 我们做 `O-4 首个真反例` 时，**把 sabotage 臂也当一等公民**（我们已有负控，但可把"故意该红的臂"写进跑批脚本，而不是口头约定）。
