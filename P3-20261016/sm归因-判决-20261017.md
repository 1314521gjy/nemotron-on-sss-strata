## §2 ★★ 判决（三步，全部可复算）
### 2.1 (a) 的灵敏度 = **由独立对照臂直接测得**：≈ **0.5% / GiB**
**D3**：只动 `reserve`（`+1000 MiB`）⇒ **arena 21.3 → 20.3 GiB** ⇒ prefill **378.0 → 376.2 = −0.5%**（**口径：同配置、同日、相邻跑**）⇒ **prefill 对 arena 的灵敏度 ≈ 0.5%/GiB**。
★ **这一臂同时实证了两条结构读码**：① **`reserve` 与 `arena` 1:1**（+1000 MiB ⇒ −1.0 GiB）；② 见 2.3。

### 2.2 ⇒ **(a) 在整个 sm 区间上至多解释 ≈ 0.7%**，而实测 **+192%** ⇒ **(a) 被否**
- `sm 2048(=1512 钳位) → 48` 释放给 arena 的差 = **(1512 − 48) MiB = 1464 MiB ≈ 1.43 GiB**；
- ⇒ **(a) 的贡献上界 = 1.43 GiB × 0.5%/GiB ≈ **0.7%**；
- 而实测 **126 → 369.6 ≈ +192%** ⇒ **(a) 至多解释 0.4% 的效应** ⇒ ★★ **判：(a) 不是主因**。
- ★ **D1 vs D2 同向印证**：`sm48` 与 `sm128` 的 **arena 只差 0.1 GiB、命中完全相同**，速度却 **+2.8%** ⇒ **纯粹由"粒度"贡献**（若是 (a)，0.1 GiB 应给出 ~0.05%）。

### 2.3 ★ 我的上界**没有被推翻，而是被实测【收紧】**（→ 红臂 **R3 未触发**）
- 我在设计的 §2 给过 `(a) ≤ ΔN/20480 = 490/20480 = **+2.39%**`；实测灵敏度给出 **≤+0.7%** ⇒ **实测比上界更小，方向一致** ⇒ **R3 的红臂条件（Arm4 到 367）未出现**。
- ★★ **并且 §1.4 的结构读码被实测【证实】**：arena **19.9 GiB（6892 对，sm=2048）→ 21.3 GiB** ⇒ **+1.4 GiB**；我的预测是 **+1448 MiB ≈ +490 对**，实测 **≈ +494 对**（21.3 GiB ÷ 2.9531 MiB − 6892）⇒ **预测与实测差 < 1%** ⇒ **"stage 与 arena 同池、1:1"成立**（**红臂 R1 未触发**）。

## §3 ★★ 我在判决书里必须写清的两条限制（否则这份判决会被误用）
1. ★★ **本判决【不能】用命中率作证据**：三组命中率都是 **97.1%（完全相同）**，而 **`experts from VRAM` 是 decode-only**（`gpu_experts` 只在非批路径累加；批路径的命中去 `batch_cached/batch_staged`，`engine.cpp:2367-2368`）⇒ **prefill 的收益根本不经过这个读数**。
   ⇒ **判决依据 = `prefill` + `arena` 的直接读数**（本条即 `KP-UNI-0245` 的又一落点）。
   ⇒ 若要给 (b) **一个 prefill 段的机制读数**，须等 **`O-1` 钩子**（`batch_cached/batch_staged`）—— **本判决不依赖它，但它能把 (b) 从"排除法"升级为"直读"**。
2. ★★ **`--stage-mib` 与 `--vram-reserve-mib` 同池**（D3 实测：+1000 MiB ⇒ −1.0 GiB arena）⇒ **这两个数必须【成对】写进 canonical**；**只写一个 ⇒ 复现会漂**。

## §4 canonical 能否定死为 `--stage-mib 48`？—— **还差一步；给最小要求（四条）**
**判决（归因）已足以定**；但**"把 sm=48 写成 canonical"** 我建议补四条，**总成本 ≤ 6 跑**：
1. ★ **确认"已到平台"**：在 **`{32, 48, 64}`** 各 **≥3 跑（弃预热）** ⇒ 判 **相邻中位差 ≤ `s_round`** ⇒ 才算"48 在平台内"。
   **理由**：现数据 `64→367.1` vs `48→369.6` 只差 **+0.7%（噪声内）**，**峰可能在 32 甚至更低**（**但不会低于 `one_expert = 2.9531 MiB`**，见设计 §1.3）。
2. ★ **成对写死**：canonical 记 **`--stage-mib 48 --vram-reserve-mib 2500`**（或你们选定的那一对），**并注明"两者同池、改一个必须重测另一个"**。
3. ★ **报峰值显存**（`nvidia-smi`）：sm=48 把 stage 从 1512 MiB 压到 48 MiB，**arena 多吃 1.4 GiB** ⇒ **缓存外余量变薄** ⇒ 必须确认没有踩"Windows 超配静默掉速"（`engine.cpp:988-993` 先例）。
4. ★ **绑 exe sha**：canonical 的读数**必须绑定跑它的那个 exe sha**（总纲 §6；若 P0-b 只编 parity、未动引擎，则与现役 `978d64bc…` 同 sha —— **请核一次**）。

**⇒ 一句话**：**归因判决 = 成立、可入册；canonical 定死 = 差上面第 1 条（`{32,48,64}` 平台确认）+ 第 2 条的成对写法。**
