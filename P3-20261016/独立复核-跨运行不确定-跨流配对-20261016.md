- 假设（待核）：「`stage(..., **up_**)` 的独立流与计算流 `st_` 之间的 **event/wait 没接住** ⇒ 累加读到 down kernel 还没写完的 `d_`」。
- 口径三要素（队规）：行号 = 当前工作树；每条判定标证据 **A**（读码确定）/ **D**（推理）。

## §0 我的结论（先给）

1. **在 `up_` / `st_` 的配对里，我找不到"没接住的等待"** —— 逐条见 §1。**假设按字面不成立**（至少我没有找到缺口）。
   - 且假设里"**读到 down 还没写完的 `d_`**"这一句**本身不成立**：`d_` 的写（down MMQ）与读（`add_scaled`）**都在 `st_`** ⇒ 同流有序（`engine.cpp:2387/2355` 一带）。
2. **但我找到一条更符合症状、且同样必须修的候选**（§2）：**驻留集合由 `cudaEventQuery` 的时序决定** ⇒ **"谁在算"随时序漂移** ⇒ **数值漂移** ⇒ 跨运行不确定；**它不需要任何"未写完的数据"，也不会被 §1 的配对检查发现**。
3. **两条都留**，并给**一次就能分开它们的判决实验**（§3）：**`--expert-swaps 0`**（最锋利）+ `--stage-ahead 0`。
4. ⇒ **严重性判断我同意（正确性缺陷、必须修），但归因我不同意**（不是跨流等待缺失，更可能是**时序决定的驻留/分工**）。

## §1 假设 1 逐条核：`up_` 与 `st_` 的 event/wait 配对

`up_` 是**专用**的 staging 流（`engine.cpp:1677-1679` 创建；与 swaps 的 `swap_st_`（`:1094-1096`）**不是同一条**）。

| 事件 | 记录在 | 谁等它 | 覆盖范围 | 判定 |
|---|---|---|---|---|
| `ev_free_` | **`st_`**（`:2390`，`card()` 末尾） | **`up_`**（`:2189`，在 `stage(...up_)` 之前） | "buffer 被复用前，上一轮已读完" | ✅ 接住 |
| `ev_ahead_` | **`up_`**（`:2191`，紧跟 `stage(...up_)`） | **`st_`**（`:2374`，**仅 `r == 0 && early` 分支**） | "读 `stage_` 前，up_ 的拷贝完" | ✅ **接住** —— 因为**只有 `early` 分支由 `up_` 写 `stage_`**（`:2186-2191`） |
| 其余轮次的 `stage(...)` | **`st_`**（`:2376`，参数是 `st_`） | ——（同流） | 同流有序 | ✅ |

**唯一"看起来像缺口"的地方**：`mine && kept == r` 分支（`:2371-2372` "// the buffer has it"）**不做 `ev_ahead_` 等待**，直接用 `stage_`。
**为什么它仍然接住（D，但推理链完整）**：
- 该分支只在 **`staged_il_ == il` 且 `staged_ == L.ahead`** 时命中（`:2184`），即"上一次调用留下的 buffer"；
- 而**任何缓存/缓冲变化都会把 `staged_il_` 置 `-1`**（`follow()` 两处 `:1313`、`:1384`；`stage()` 开头也置 `-1`）⇒ 复用只发生在"**中间没变过**"的情况；
- 若那份 buffer 是**由 `up_` 写**的（只有 `early` 会），**写它的那次调用已在 `r==0` 等过 `ev_ahead_`**（`:2374`）⇒ **那次等待进入了 `st_` 的流历史** ⇒ 后续任何 `st_` 工作天然在其后 ✅。
⇒ **结论：按字面，假设 1 不成立。**

⚠️ **两处仍需兜底（我没有 100% 排掉）**：
- `ev_ahead_` 是**单个**事件（不是每轮一个）⇒ 若 `up_` 在同一 `st_` 序列里被**重记两次**，语义取"最近一次"；本次推理依赖"两次之间 `st_` 必走过 `r==0` 的等待"（在"一层一次 `card()`"的现状下成立，**但它是个隐含前提**）。
- §1 的整个结论**依赖"`staged_il_ = -1` 的写点齐全"** ⇒ **建议 builder grep 全列该变量的写点复核**（我核到 `:1313/:1384` 与 `stage()` 开头）。
⇒ 所以**不能用 §1 单独结案**：见 §2 与 §3。

## §2 ★ 我的独立候选：**"谁在算"由时序决定**（不是"未写完的数据"）

**读码链（A）**：
1. `follow()`（`:1296-1316`）：对每个 `kSent` 的 swap 做 **`cudaEventQuery(s.done)`**；
   - **`if (arrived == cudaErrorNotReady) continue;`**（`:1306-1307`）⇒ **"这一轮到底换成了没有"取决于拷贝跑多快**；
   - **只有 arrived 才 `layers_[s.il].slot[s.e] = s.slot;`**（`:1309`）⇒ **`L.slot[]` 的内容是时序函数**。
2. `follow()` 的换入决策还用 `recent_` 衰减，衰减量 = `written`（`:1318` `keep = exp2(-written / kSwapHalf)`）⇒ **决策也随调用节奏**。
3. 而 **verifier 已证：decode 的"谁算"由 `L.slot[e]` 决定**（命中 ⇒ 卡上算；不命中 ⇒ CPU 算）⇒ **`L.slot` 漂 ⇒ 分工漂**。
4. **两条路径的数值不同**（CPU：ggml 的 q8_0/q5_0 点积；GPU：`native_mmvq`/MMQ；**量化与归约序都不同**）⇒ **同一输入两跑可以给出不同的输出**。

**⇒ 为什么它比"跨流等待缺失"更符合我们观察到的全部症状**：
| 观察 | §2 的解释 |
|---|---|
| **长负载**不确定、短跑确定 | 短跑里 swap 几乎没有空间/per-token 调用少（`follow(n<kStageRows?n:0)`，`:2469`）⇒ 时序自由度小；长负载下 `follow()` 每 token 一次、`recent_` 累积 ⇒ 自由度大 |
| **`--dump-layers` 是混淆项**（有 dump 时分叉晚、无 dump 时 pos 0） | `dbg()` 里**每层每阶段一次 `cudaStreamSynchronize`**（`:1814`）⇒ **改变拷贝到达时序** ⇒ 换入节奏被改 ⇒ 随机性被压掉/换形 ✅ |
| 现象是"值不同"而非"崩溃/垃圾" | 两条路径都是**正确但精度不同**的实现 ⇒ 得到**合法但不同**的数，不会崩 ✅ |

**⇒ 判定（我的）**：**这更像"时序决定的驻留/分工"，而不是"读到未写完的数据"。** 两者的**严重性一样**（跨运行不确定 ⇒ 正确性缺陷），但**修法完全不同**：
- 若是 §2 ⇒ 要**把"谁算"钉死**（例如：跑之前冻结驻留集合 / 让 `follow()` 的发布不等时序 / 或提供"确定性模式"）；
- 若是 §1 ⇒ 要补一处 `cudaStreamWaitEvent`。

## §3 判决实验（**一次分开两条** —— 零成本旗标，不需改码）

| 刀 | 配置 | 结果 ⇒ 判读 |
|---|---|---|
| **R0（红臂，必跑）** | 现状（含 swaps + stage-ahead） | **必须复现"3 跑不同"**；否则整轮作废（`KP-UNI-0203` 同族：先让判据变红） |
| **R1 ★** | `--expert-swaps 0`（`start_swaps` 直接 return，`:1093` ⇒ **不建 follower 线程、无 swap**） | 不确定性**消失** ⇒ **是"驻留/分工的时序"（§2）**；**仍在** ⇒ 与 swap 无关 ⇒ 转 R2 |
| **R2** | `--stage-ahead 0`（使 `ahead` 恒 false，`:2123`） | 不确定**消失** ⇒ 在 `up_`/staging 路径（§1 那条，需回头找隐含缺口）；仍在 ⇒ 再往纯 compute |
| **R3** | `--expert-swaps 0 --stage-ahead 0` | 仍有 ⇒ **两条都不是**，另起一条线（下次会话） |

- **判据（口径写死）**：同 exe、同 prompt、同旗标，**跑 3 次**，比 **token ids（+ dump 行）**；**逐位/逐 id**。
- ⚠️ **别混判据**：`--expert-swaps 0` **也会改速度** ⇒ 本实验的判据是**确定性**（3 跑是否相同），**不是 tok/s**。
- ⚠️ **别用"两次独立跑 sha"当唯一判据**（§9.4：跨运行逐位在本线不成立）—— **但这里恰恰要看的就是跨运行**，所以**"3 跑 3 个 id"就是 R0 的红臂**，**"3 跑同 id"就是绿**。
- **顺带（零成本）**：R1/R2 的跑**同时收 §2 想要的读数** —— 每次打印 `experts from VRAM %` 与 `swapped`；若 R0 的三跑**这三个数也各不相同** ⇒ §2 直接得到旁证。
