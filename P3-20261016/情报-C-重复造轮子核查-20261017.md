### 6.2 一条"零改码等价候选①"的参数推导（**未跑数，标未验**）

`--prompt-cache-every` 取 **`rows_`（=prompt_batch）的整数倍**时，mid marks 恰好落在 call 边界，`engine.cpp:3142` 的 `min(rows_, mark-at)` 不会再额外切一刀 ⇒ 对 `n ≤ read_rows_` 的单发 prompt，call 数 = ⌈n/rows_⌉（与"不打 mark"相同）。
- 例：pb=6912、n=6791、`--prompt-cache-every 6912` ⇒ 无 mid mark ⇒ **1 call**；
- 反例：`--prompt-cache-every 8192`（**不是** 6912 的倍数）在 n>8192 时会在 8192 处切出 6912+1280 两个 call ⇒ **"随便调大"不等价**。
- **未验**：本席未跑 `--prompt-cache-every 6912`（零 GPU 纪律）；这只是从 `engine.cpp:3139-3147` + `conversations.hpp:112-115` 的推导，**是否真 1 call 要用日志/DMA 计数器证**（候选①的 `0` 已被 R1a 实测证过，本推导只是它的"保留 checkpoint 版"）。
