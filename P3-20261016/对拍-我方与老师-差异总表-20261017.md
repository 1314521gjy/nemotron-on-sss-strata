## 0. 一句话

## 3. 我们比老师多做对的三件事
1. **去重**：把 conversation-cache 每 2048 token 切 4 call、每 call 重搬 ahead 整表的浪费砍掉（141.0 → 44.58 GB，−68%）。老师的段里没有这个坑（它是单 chunk + 自有 profile 路径）。
2. **ring 双缓冲**：**机制上游有**（per-blob N 槽），我们把结构按 poly 线的 round 布局**重写**（round-slot 2 槽），**−19% 墙**（驻留/DMA/ids 全不变、pos0 Δp=0）。
   ⚠️ **更正（2026-10-18 00:30）**：先前写"老师 prefill 日志里没有 ring 流水 ⇒ 它没用"**判据过松** —— 日志不打印槽状态，不能由"没打印"推"没使用" ⇒ 改判 **未验**。可确认的只有：它 prefill 明写 **borrow 2,387 槽（4.55 GiB，回填 213 ms）**，而 ring 类结构在 verify/decode 表里出现（`wait for rings 12.378 ms/round`，是否为专家环仍**未验**）。
3. **带宽利用率**：13.97 → 17.7 GB/s（我们没有输在搬运速度上）。

## 4. 老师有、我们该拿的（按性价比）
1. **per-layer 槽配额**（零 GPU 先量化；可能免费提命中率）← 重点项
2. **reserve 真守住 1 GB**（flag 或码；便宜）
3. **借槽**（省 ~2 GB 独立显存 / 或抬常驻；prefill 收益≈0，主要解决显存挤占）
4. **MTP / 投机**（decode 专项，后期）
5. **任务画像 profile**（需 agent 负载模拟，暂记）

- 老师那次是否真跑了 `--expert-profile-save`（无 argv）。
- `wait for rings` 是专家环还是 KV/投机环（**可能是 KV**）。

## 6. ★ 2026-10-18 01:00 更正（情报D，A/B+ 级）—— **本节推翻上文三处判断**

1. **老师那次 ring 是开着的（B+）** —— 不是"未验"，更不是"没开"。上游 prefill 的 N 槽流水**默认开、无 CLI 开关**（仅 env：`STRATA_PREFILL_STREAM_AHEAD=0` / `STRATA_PREFILL_RING=N` / `STRATA_RING_BYTES=0`；`prefill.cpp:164/2341`，**chunk ≥ stream_all_min=1024 才启用**，低于则走 STAGE=8）。
   证据：4 份 **0.1.40.2** 日志在 chunk≥1024 时都满足 `experts streamed == 24576 − resident`（dec-pool2 `15535 = 24576 − 9041`；trace-work 15623；trace-long32k 62844/4=15711），而 chunk=220 的 trace-tiny 只有 3562（routed-only 反例）⇒ **只有"整表流经 ring"的那条分支在跑**。
   **具体 N 槽未验**：N 由 pinned 比例与字节预算定（384/96，cap 512/1024；`prefill.cpp:257-314`；锚点 Q2_0 384 槽、IQ3_S 199 槽）。
   **版本前提更正**：`dec-pool2` 自报 engine **0.1.40.2**（`:42`）；`0.1.43.1` 只是本机 `C:\sp3\strata.exe`/help。
   槽形态：**每槽 = 一个整专家 blob**（`prefill.cpp:121`），槽从 prompt 的 **borrowed 区**切（`:1923-1936 / :1318-1335`），每槽一对 copied/used 事件（`:1127-1128`）。
2. **`wait for rings` 不是专家环、也不是 KV 环** —— 是 **decode session loop 的逐层门铃**（唯一出处 `generate.cpp:13935-13940`；机制 `core/session.cpp:658/686/716/723`）。§5 那条"可能是 KV"**作废**。
3. **borrow 与 ring 不是替代关系，是同时存在**：**borrow 是"资金"（从缓存尾借来的区域），ring 是"流水"（在这块区域里排 N 槽）**。老师那句 `prompt path borrows 2387 slots (4.55 GiB)` **已含 ring 的字节**。
4. **所以我们的 ring 不是独创，是把上游"默认开着的"东西补上**（我们原来是 0）⇒ 这正好解释为什么"抄它"就有 −19%：我们是在补一个本该有的机制，不是在发明。
5. **另一处口径更正**：§8.5.1 说的"compute ≈55 TFLOPS ⇒ 接近打满"**错**——4080S 规格稠密 FP16 ≈165 TFLOPS / INT8 ≈330 TOPS（C 级）⇒ 55 只到 1/6~1/3，**不能据此关闭 compute 优化**。上游真候选 = **FP16/BF16 prompt 计算路径**（`QUANTS.md:37`：Q4_K 在 CUDA 上 prompt 默认 FP16；我们 `engine.cpp:2031-2033` 走 int8 MMQ）。
