## ④ ★ 容差依据（正确性侧，**不复用 t8 的性能噪声**）

**t8 的 ±26–29% 是 perf 口径噪声（墙钟/换页），与正确性无关，禁止套用**（两回事）。正确性侧是对拍（确定性计算），依据如下：

1. **打印精度（主依据，A）**：`llama-eval-callback` 打印 **4 位小数**（如 -0.3953），`engine dbg` 打印 **`%.6f`**（`engine.cpp:1821-1822`）。⇒ 参考侧单值舍入 ±5e-5；两侧相减，**|Δ| 的本底 ≈ 1e-4**。
2. **同计算地板（实证，A）**：已知**正确**的 layer 0 两侧差 **0.02%**（`dump5.log:3` vs `evalcb-pos0.log`）⇒ 引擎与 llama.cpp 在"同口径逐元素"下的**基线一致度 ≈ 0.02–0.05%**。
3. **判据阈值 1%** = 上述地板的 **~20–50×**：既**远高于印刷/累积本底**（不误报），又**远低于坏态 ~900%**（必报红）。

**判定式（逐通道，然后取 3 通道最大）**：
```
rel  = |eng - ref| / max(|ref|, 1e-4)          # 1e-4 防除零
超标  = (rel > 0.01)  AND  (|eng - ref| > 2e-4)   # 2e-4 = 两侧印刷本底之和的安全余量
```
- **两条件同时满足才算「分叉」**：加 `|Δ|>2e-4` 是为了排除**「参考值本身极小、4 位小数印刷导致相对差爆表」**的假阳性（已踩过：layer1 v0 = 0.0004 vs 0.000468 报 17%，实为印刷噪声）。
- 若 `|ref| < 1e-3` ⇒ **该通道标「不可比（量级太小）」，不计入分叉判定**，改用同层其它通道或绝对差。

## ⑤ 口径纪律（违反即作废）

1. **同 token / 同位置**：参考 `evalcb-pos0.log` 是 **pos=0**（首个 prompt token）⇒ 引擎必须比 **`pos=0`** 的行（`dbg` 打印 `pos=`）。
2. **比「前 3 通道」**（`first=`），**不比其他**。
3. **⛔ 禁止拿两侧 `sum` 直接比**：llama.cpp 每行 `sum` = **整张量（含 5 token）之和**；引擎 `dbg` 的 `sum`/`abs` = **单 token**。口径不同 ⇒ 已作废一轮。**只比 `first=` 的 3 个数**。
4. **同 prompt / 同 token 序列**：参考就是 `-p "The capital of France is"` = tokens **`1784,8961,1307,5498,1395`**（5 token，`evalcb-pos0.log` 自证 `number of input tokens = 5`）；引擎必须跑**同样这 5 个 id**，**不许**用 16-token 带 `<think>` 的跑法对拍。
5. **`--vram-reserve-mib 2500` 必带**；**一次只跑一个 GPU 作业**；**跑前核 exe sha**。
