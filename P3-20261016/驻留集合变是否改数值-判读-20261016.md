# 「驻留集合变 ⇒ 数值变」—— 核心一环独立判读（只读）— verifier

> 任务（优先）：判队长新假设的**核心一环**：**同一专家在 CPU 路径与 GPU 路径算出的结果是否逐位相同**？
> **只读**：未跑 GPU、未编译、未改码。**AI：deepseek-flash[1m]** ⇒ **自验，不构成独立验收**。证据 **A** = 本机读源码。

---

## 判定：**假设的机制【成立】** —— 两边**不可能逐位相同**（**两条独立原因**，各自都足够）

### 原因 ①：**两侧激活量化格式不同**（A，file:line）
| 侧 | 激活量化 | 出处 |
|---|---|---|
| **CPU** | **ggml 的 `vec_dot_type`** ⇒ 对 Q4_K 权重是 **Q8_K** | `cpu_experts.cpp:174` `a_bytes = ggml_row_size(tg->vec_dot_type, n_embd)`；`:187-188` `act_from = traits(tg->vec_dot_type)->from_float` ⇒ 把激活量化成 **Q8_K**（block=256）。类型映射：`E:\llama-cpp-pin\ggml\src\ggml-cpu\ggml-cpu.c:311-314` `[GGML_TYPE_Q4_K] { .vec_dot_type = GGML_TYPE_Q8_K }` |
| **GPU** | **引擎自带的 Q8_1** | `engine.cpp:1889` `native_quantize_q8_1(moe_in_, xq_, in_w*n, 1, st_)`；`:1913` `xq_row = native_q8_1_bytes(in_w)`；`:1637-1638` 缓冲按 `native_q8_1_bytes` 分配 |

⇒ **Q8_K（256 值/块、每 16 值一组 6-bit 尺度）vs Q8_1（32 值/块、fp16 d + fp16 s）**：
**两者的量化误差分布不同** ⇒ **每条 dot 的中间精度不同** ⇒ **同一个专家的 up/down 点积在两侧必然有位差**，不是"可能"。

### 原因 ②：**累加分组/顺序不同**（A，file:line）
| 侧 | 怎么加 | 出处 |
|---|---|---|
| **CPU** | 一个 token 的 22 个专家**按给定次序逐项乘加** | `cpu_experts.cpp:253-259`「a token's sum **in the order its experts were given**」 |
| **GPU** | cached 专家**按 kSlots 批量**加进 token 行；host 部分另算，最后由 `moe_add()` 再加一次 | `engine.cpp` `moe()` 的 `launch()` 路径 + `moe_add`（少 token 的 host 和攒在 `h_cpu_`） |

⇒ **驻留集合一变 ⇒ "谁在 GPU 加、谁在 CPU 加"的划分一变 ⇒ 加法的分组一变**；浮点加法**不满足结合律** ⇒
**即便两侧单专家逐位相同，总和也会因分组不同而生位差。**

**⇒ 两条原因各自都足以推翻"逐位相同"** ⇒ **驻留集合变 ⇒ 数值变** ⇒ **队长假设的机制成立**。

## 判据（★ 必须能变红 —— 明确写出"若如何则假设被否"）
| 观测 | 判读 |
|---|---|
| **能举出一对（同一专家、同一输入）在 CPU 与 GPU 侧逐位相同** | ❌ **假设被否** ⇒ 必须另找"A 与 B 都 loaded 20267 条却输出不同"的解释 |
| **固定 profile（3 跑读同一份、不写回）后，3 跑输出一致** | ✅ **假设成立，且升为【因果】**（不是相关） |
| 固定 profile 后**仍不一致** | ❌ 假设不是（唯一）根因 ⇒ 回"多线程投递/读回同期"那条线 |
| **不固定 profile**：3 跑输出不一致（现状 A/B/C） | ⚠ 仅**与假设相容**，**不构成因果**（与"多线程投递"那条同样相容） |

**★ 建议的最小因果实验（一次 GPU 作业，builder 执行）**：
`--expert-profile` 指到**同一份文件**、并在跑前**把它复制一份只读固定**（或跑完立刻还原），其余全同，跑 3 次：
- **3 跑一致 ⇒ 因果成立**（profile 是根因）；
- **仍不一致 ⇒ 排除 profile**，与 §C 那条（投递交错）并列继续追。
（**变量只有一个**：profile 是否被改写 ⇒ 符合总纲"一次一变量"。）

## 未验 / 边界
- **只读**：未跑 GPU ⇒ **"两侧逐位相同"这一否定结论是【读码级】的**（量化格式 + 累加分组都不同 ⇒ 逐位相同需要巧合），**未做运行对照**。
- **可做的"可执行的正控/负控"**：把**同一专家同一输入**分别喂两侧各算一次、比 `float` 位（**这是把本条从"读码结论"升为"实测"的唯一办法**；需改码插桩 ⇒ 归 builder）。
- 我**未穷举**所有驻留相关旋钮（`--expert-profile` / `--vram-reserve-mib` / `--expert-swaps` / 启动时的 `fill_expert_cache` 排序细节）—— 本条只判"**数值会不会变**"这一环，**不判"起始集合到底怎么变"**（那是 builder 步 0 的另一半）。
