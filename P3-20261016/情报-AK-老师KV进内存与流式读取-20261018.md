## §1 机制细节（老师树，`file:line`）

### §1.1 核心抽象（`include/strata/kernels/kv_stream.hpp`，0.1.44.1 7,328 B）
- **权威 K/V 在 pinned host 内存**：`KvHostPools { uint16_t* k_pool/v_pool（fp16）; int8_t* k_q/v_q + uint16_t* k_scale/v_scale（int8）; uint8_t* k_q4/v_q4（q4_0） }`——全是 **UVA device-mapped 指针**，布局与"全驻留池 + identity page table"完全相同（`:32-43`）。
- **VRAM 一侧是页池**：`page = page_size = 4 cells = one indexer block, all KV heads, K and V`；`KvStreamMap { page_table(block→slot/-1), slot_block, slot_stamp(epoch), slot_ref(clock bit), ctl, miss_block, miss_slot, n_blocks, n_slots }`（`:45-64`）。
- **`kv_stream_resolve`（每 decode 调用，图内）**：1024 线程扫描 selection ids：命中块打 epoch/ref；未命中块 `-1→-2` 认领一次进 miss list；CLOCK 二次机会选受害者（**不选本调用正在用的槽**）重指 page table；copy kernel 从 host copy 零拷贝（PCIe）搬 miss 页（`kv_stream.hpp:8-24`；`kv_stream.cu` 的 `resolve_kernel`+`copy kernel`）。
- **写者**：append 永远写 host copy，只有"该块当前驻留"才同时写 VRAM ⇒ 槽永不过期、无需失效（拒绝的 draft / 会话缓存恢复都不用处理）（`:22-27`）。
- **ring**：MTP drafter 只读最后 `window` cells ⇒ 用静态表 `block→block%n_slots`、**无 resolve**，resume 时从 host copy 重填（`:25-27`；`kv_ring_table/kv_ring_restore`）。
- **prefill 暂存**：`kv_stage_from_host` 把 host copy 前 n_blocks 拷进"全驻留 identity 布局"的 staging pool（每层一次；DMA，不可捕获）（`:103-110`）。

### §1.2 为什么"不是每次读这么多"——**靠 QSA 选择，不靠 prefetch**
- 老师模型（Qwen3.8-Flash-Next 系）：`idx_block=4`（每 4 cells pool 一个 indexer key）、`idx_top_k=2048`（选择预算）⇒ **每个 query 只看 ≤2,051 cells，与上下文长度无关**（`geometry.hpp:45-46`；`qsa.hpp:127-135`）。262K 上下文时 = **0.8% 的 cells**。
- 因此每 token 的真实 KV 流量 ≈ `width × cell_bytes × n_qsa_layers`（QSA 层数 = n_layers/interval；老师模型 **12 QSA 层**，见 `kv_q8.hpp:1-10`），而不是"全部上下文"。
- **`STRATA_KV_PREFETCH` 不是这个机制**：它只把 prefill 的逐层 KV 上传挪到旁路 stream（`docs/KV_PREFETCH.md`：32K −5.3%、64K −4.1%、8K 0、**decode 0**；"The copies still execute; they are not eliminated"）。decode 侧"少读"来自 **QSA 选择**。

### §1.3 实测口径（老师文档，C）
- `docs/INTEL.md:354`："KV streaming (`--kv-resident`) keeps the **whole KV in pinned host memory and only the attended window in VRAM**"；`:68` `--kv-resident 32768` 从 64K 起生效；同文档早期版本给 "**256K decodes at 31 tok/s（from 4-5）**"。
- `docs/DETAILS.md:80`："Q2_0 at 262K: **50.9 → 62.6 tokens/s**"（KV 驻留 32,768 cells 时更多专家能进 GPU）。
- `docs/A770_SPEED_SPEC.md:266-267`：`--kv q4_0` 在该卡**中性**（12.0/12.3/12.6 tok/s，与 int8 持平）⇒ "KV VRAM 不是当时的绑定约束"。
- `docs/BATCHING.md:99`：长上下文"unless the KV cache streams（`--kv-resident`: 只有 attention 的 32K 窗口在 VRAM）"。
- 机制前提：`--kv-resident` / `qsa_set_kv_resident` **只在 `g.n_qsa_layers() > 0` 时出现**（`generate.cpp:4394-4410` 的启动打印；`layer.cpp:634-660` 的 `kv_plan` 只对 QSA state 生效）。

## §2 KV 量化（`kv_q8` / `kv_q4`）实现与精度

| 格式 | 存储 | 每 cell/层字节 | 相对 fp16 | 精度/parity |
|---|---|---|---|---|
| fp16 | `[page][kv_head][page_size][head_dim]` | 2,048 B（2 KV heads × 256 × 2 × 2B） | 1× | 基准 |
| **int8**（`--kv int8`） | codes + **每 64 值一个 fp16 scale** | **1,056 B**（1,024 codes + 32 scales） | **0.516×** | `kv_q8_parity.cpp:1-10`：codes/scales 与 host 参考**逐位同**；gather 逐位同；对 fp16 路径误差 ≤ **0.624 个量化步** |
| **q4_0**（`--kv q4_0`） | **256 点 Hadamard 旋转**后 q4_0（18 B/块，144 B/head/cell） | **576 B**（2 heads K+V） | **0.281×** | `kv_q4_parity.cpp:1-8`：FWHT/量化/打包/append+gather 逐位对 host；`(Hq)·(Hk)=q·k` 旋转不变；质量在 `bench/results/2026-09-27-kv-q4`（老师侧实测，未读具体数） |
| K8V4（`--kv k8v4`） | K=int8、V=旋转 q4_0 | **816 B** | 0.398× | `kv_stream.hpp:56-73`（hybrid 两半）、`kv_q4.hpp` 注释 |
- **流式 parity（关键）**：`kv_stream_parity.cpp:1-16` 对 **fp16/int8/q4_0/K8V4** 四种池子验证"**streamed 路径 attention 输出与全驻留池逐位相同**"，并验 page_table/slot_block 互逆、miss/lookup 计数、ring restore 值相同。⇒ 流式本身**位精确**（不引入数值差；只有量化格式本身有损）。
- `STRATA_KV_ROT=1`：让 **int8** K/V 也走 Hadamard 旋转（q4_0 本来就用）。老师文档给的首 token KL：NVFP4 包 **0.0066→0.0051**（改善），IQ2_XS **0.0022→0.0054**（变差）⇒ **opt-in、不通用**（`generate.cpp:2552-2557`）。

## §5 对我们的价值（C：16K / 128K / 1M）

### §5.1 我们的 KV 数字（A，读码 + 计算）
- 每层每 token：`n_kv(2) × head_dim(128) × 2(K+V) × 2 B = 1,024 B`；8 个 trunk attn 层 ⇒ **8 KiB/token**（含 MTP blk.88 ⇒ 9 KiB）。
- 总量：**16K = 128 MiB**（+MTP 16 MiB）；**128K = 1 GiB**；**1M = 8 GiB**。
- 稠密全注意力**每 token 必须读全部 KV**（8 层各读 0..pos）：16K 读 128 MiB/token、128K 读 1 GiB/token、1M 读 8 GiB/token。
- 对照带宽：VRAM 736 GB/s → **0.17 / 1.4 / 10.9 ms/token**；PCIe（host→VRAM，26 GB/s）→ **4.9 / 40 / 315 ms/token**。

### §5.2 结论表
| 上下文 | KV 体积 | 若"进内存+流式"（每 token 从 host 读全量） | 若 KV 量化 | 判决 |
|---|---|---|---|---|
| **16K（现交付）** | 128 MiB | PCIe **4.9 ms/token**（+7.4% 墙）只为省 128 MiB（≈41 slot，**0.7%** 缓存） | q8 省 64 MiB=21 slot(0.36%)；q4 省 96 MiB=31 slot(0.54%) | **不用**（流式与量化都不值） |
| **128K** | 1 GiB | PCIe **40 ms/token**（≈60% 墙）⇒ **不可行** | q8 省 512 MiB≈169 slot(**3.0%**)；q4 省 768 MiB≈253 slot(4.4%)；attention 读带宽也减半 | **流式不用；量化可选（低优先）** |
| **1M** | 8 GiB | PCIe **315 ms/token** ⇒ 完全不可行 | q8 4 GiB≈**1322 slot(23%)**；q4 6 GiB≈**1983 slot(35%)**；但 8 层全注意力 1M 的算力/显存还有别的墙 | **流式不用；量化是唯一容量手段，但 1M 不是当前交付目标** |

**关键判据**：老师那套"不是每次读这么多"= **QSA 选择**（≤2,051 cells/query，与上下文无关）；**如果靠 prefetch 只是隐藏延迟、字节不变** ⇒ 对稠密全注意力的我们，长上下文仍受**全量 KV 带宽**限制。**我们没有 QSA，所以这条杠杆在 Nemotron 上不存在。**

### §5.3 我们真正能用的替代（若要长上下文）
- **KV 量化**：`--kv int8` 思路（codes + 每 64 值 fp16 scale）对我们 1,024 B/层/token ⇒ 528 B（≈0.516×），q4 旋转 ⇒ 288 B；**但**我们 attention 内核读的是 `uint16_t` 池，需要"读 code+scale 去量化到 fp16 scratch"的路径（老师已验证这种路径可逐位/0.624 步误差）；**llama.cpp 也有通用参考**：`params.type_k/type_v` + 量化 V 需 flash-attn（`E:\llama-cpp-pin\src\llama-context.cpp:388-389,3727-3756`；`ggml-cuda/cpy.cu`）⇒ 移植面 ~200–400 行 + parity/精度门。
- **MTP drafter 的 ring（老师现成）**：我们的 MTP 块 KV 目前按 `max_context` 分配（16 MiB@16K），但 MTP 只读它自己的 `window` cells ⇒ 可改成 ring（~window×1 KiB×2）**省 ~16 MiB（5 slot）**；收益小，只有在重启 MTP 线时才顺手做（~50 行）。
- 若未来模型支持 QSA/滑窗：才可能搬 `kv_stream_resolve`（那时页表/选择都已存在）。

## §6 判决（D）
| 问题 | 判决 |
|---|---|
| **能不能用** | **不能用**（对 Nemotron 的 8 层稠密全注意力）：这套机制**依赖 QSA 的 indexer selection**；我们没有 selection，`kv_stream_resolve` 没有输入。**只有老师的 12 层 QSA 模型能用**（我们树里代码是给那条产品线的遗产）。 |
| **16K 值不值得** | **不值得**：省 128 MiB≈0.7% 缓存，而每 token 多 4.9 ms PCIe（+7.4% 墙）。 |
| **128K/1M 值不值得** | **"进内存+流式"不值得**（PCIe 40/315 ms per token，等于引擎不可用）；**KV 量化（q8/q4）在 128K+ 才有容量价值**（3–35% 驻留），但它要改 attention 内核（~200–400 行 + parity），且当前交付 max-context=16K ⇒ 暂不做。 |
| **要多少行** | 流式化（若硬做）= **白做**（无 byte 收益）；KV 量化 = **≈200–400 行**（dense KV 的 q8 codes+scale 读路径 + 去量化 scratch + parity）；MTP ring = **≈50 行**（省 16 MiB）。 |
