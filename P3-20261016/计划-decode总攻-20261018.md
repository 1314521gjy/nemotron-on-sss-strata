## 2. 四条攻击线（按杠杆排序）

### 线 A · 机制移植（最大杠杆 · 情报先行）
**问题**：Strata 每轮 24.3 ms 里，`wait for rings 12.378 / pool 7.269 / host 0.101 / commit 0.037`（合计 19.8 ms）——**说明它的时间主要花在"专家池/环"的等待与搬运**，而不是稠密计算。我们对应位置是什么？我们有没有等价机制？
**要挖**（scout-a）：
1. 老师 decode 每轮的时间账（`E:\strata\_staging\dec-pool2.txt` + 0.1.43.1/0.1.44.1 源码）——把 12.378 ms 的 ring 等待拆开：在等谁？
2. **专有机制清单**：expert pool / ring / borrow / lend / kv-resident / adaptive tier / per-layer quota / pcie-frac / host-core / pool-workers / batch / serve 队列 / CUDA graph / fused kernels / router 优化 / 量化路径
3. 每条判：**我们有/无**（grep 我们的 `src/poly`，全量计数）+ 宣称收益 + 移植代价（行数/是否需新 kernel/是否需编译）
4. **重点回答**：他们为什么 batch=1 也能 24.3 ms/轮？是**机制**（流水/重叠/预取）还是**几何**（层数/专家数）？——**这条决定我们该不该移植**

### 线 B · MTP 修好（通用无损 · 已修 80%）
**已知**：blk.88 半移植已补齐（acceptance 0–4% → 84.6–94.9%），但 decode 只 +2.2%，且 ids 漂（draft 机制占 VRAM ⇒ 驻留 −212 专家）。
**要验**（builder2）：
1. `STRATA_DRAFT_LOAD_ONLY=1` 隔离：接线但 block_* 空转 ⇒ 若 ids 仍漂，说明是 VRAM 代价；若不漂，说明是 block 计算
2. reserve 补偿：把 −212 专家换回来（reserve 3000 → 约 2788？）⇒ 重判 ids
3. 若 ids 可救 ⇒ 再看 MTP 真实收益（当前 +2.2%，门 5%）
4. **同时量**：draft 机制的 VRAM 精确账（state_/r_/块权重/KV 各多少 MB）

### 线 C · 单 token 延迟（我们自己的账）
**要挖**（scout-b，零 GPU 代码审计）：
1. decode 主循环每 token 发射多少 kernel × 88 层（`engine.cpp`/`kernels.cu`）
2. **40 层 mamba2**：batch=1 时的实现（是否 128 步串行链？smem？）——mamba 常是 hybrid 模型的 decode 瓶颈
3. CUDA graph 是否覆盖整段 decode；哪里掉出图
4. CPU experts 路径的 11.1 ms + router wait 6.6 ms 能否藏进 GPU 时间（重叠）
5. 给一张**可测打点方案**（每个打点加在哪、怎么读、怎么变红）

### 线 D · 度量与验收
- **多样 prompt 台**（≥3 类：问答/代码/中文长文）——没有它，decode 结论会再被基准骗（这是昨晚最大的教训）
- 判据表更新 + 独立复核（reviewer）

## 4. 判据纪律（继承 + 本轮新增）

1. 所有 decode 数一律 **alt prompt 口径**；p6792 只做历史对照。
2. **一次一跑**；每臂报 decode / tokens/round / 兑现率 / peak / ids。
3. **确定性对照用 `--expert-swaps 0`**；probs 对比**静默窗口**（不挂 VRAM 采样器）。
4. 类 E（计算路径变化）门：ids 逐位（≥2 prompt）+ 文本逐字同 + 确定性 + 无 >0.05 Δp 跳。
5. 编译：改 hpp **先删 `build-p3\CMakeFiles\strata-poly.dir\src\poly\*.cpp.obj`**；一次编译原则。
6. 每批开跑前**报预算**（臂/分钟/显存）。
7. **停止条件**：同一方向第三次失败 ⇒ 停手换方向（不许磨）。
