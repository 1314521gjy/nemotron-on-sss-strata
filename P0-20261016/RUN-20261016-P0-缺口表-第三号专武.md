## 0.1 更正条（20261016b — `block_count` 89 vs 88 口径）

> **缘起**：team-lead 拿到 lmstudio GGUF Q4_K_M 头部，`block_count = **89**`、`attention.head_count_kv` **89 项**、非零在 `7,16,25,36,47,58,69,78,**88**`。
> **判定：两边都对，是口径差；本件原文一处措辞有误（"MTP 另加 2 层"）已改。** 证据 + 换算如下（新增等级 `C(码)`＝线上/本地 llama.cpp 源码实测）。

**三种口径（互不矛盾）**：

| 口径 | 主干 | MTP | 合计 |
|---|---|---|---|
| HF config `layers_block_type` | **88** | 不在其中（另有 `mtp_layers_block_type=["attention","moe"]`） | 88（config 内） |
| HF safetensors 命名空间 | 88（`backbone.layers.0..87`） | **2**（`mtp.layers.0`=attn, `mtp.layers.1`=moe） | **90 命名空间** |
| **GGUF `block_count`（权威）** | **88**（`blk.0–87`） | **1**（**折叠块** `blk.88`） | **89** |

**为什么 GGUF 是 89（不是 90）**：GGUF 转换把 MTP 的两个子层**折成 1 个块**。本地 llama.cpp 源码坐实（`E:\llama-cpp\prism-b10687\`，与 `E:\strata` 无关）：
- `conversion/nemotron.py:220-222`：`hparams["num_hidden_layers"] = len(layers_block_type)` ⇒ 主干 = **88**；
- `:256-261`：`self._mtp_bid = self.block_count`（88）；`self.block_count += 1` ⇒ **block_count = 89**；注释原文 *"**The folded MTP block carries both an attention sub-layer and a MoE sub-layer**, so register it as both so the per-layer metadata arrays cover it"* ⇒ `_attn_layers.append(88)` **且** `_mlp_layers.append(88)`；
- `src/models/nemotron-h-moe.cpp:13`：`GGML_ASSERT(hparams.n_layer_nextn == 1 && "NEMOTRON_H_MOE MTP currently supports **a single MTP block**")`；`:18` `const int il = hparams.n_layer();` ⇒ MTP 块号 = `n_layer()` = **88**；
- `src/models/nemotron-h.cpp:14-16`：`is_recr[i] = i < n_layer() && n_head_kv(i)==0 && n_ff(i)==0` ⇒ **追加的 MTP 块是 dense（非 recurrent）**。

**三个子问题的答案**：
1. **88 是否只算主干、MTP 不在 `layers_block_type`？** —— **是**。`layers_block_type` 88 项＝主干；MTP 靠 `num_nextn_predict_layers` 单独追加（`nemotron.py:248-261`）。
2. **GGUF 89 是否 = 88 主干 + 1（MTP）？** —— **是**。89 = 88（`blk.0–87`）+ **1 个折叠 MTP 块**（`blk.88`）。**不是 90**（HF 的 2 个 MTP 命名空间折成 GGUF 1 块）。
3. **第 88 号是什么层？** —— **MTP 折叠块本身**。它**同时**含 attention 子层与 MoE 子层（源码明写 + 块 88 同时登记进 `_attn_layers` 与 `_mlp_layers`）⇒ **`head_count_kv[88] ≠ 0`（因为它有 attention 子层）**。它**不是**第 9 个普通 attention 主干层。

**换算表**（GGUF `blk.i` ↔ HF）：
- `i ∈ [0,87]` = 主干层 `i`（= HF `backbone.layers.i`）；
- `i = 88` = MTP 折叠块（= HF `mtp.layers.0` 的 attention 子层 **+** `mtp.layers.1` 的 MoE 子层）。

**对本件结论的影响**：
- **主干 88 层**（40 mamba + 40 moe + 8 attn）、**attn 位置 `[7,16,25,36,47,58,69,78]`**、**非等周期** —— **全部不变**（GGUF `blk.0–87` 与之逐项吻合）。
- **闭合不变**：折叠 MTP 块自带 MoE 子层 ⇒ 专家块仍 = 40（主干）+ 1（MTP）= **41** ⇒ `41 × 512 × 帧字节` 不变（§3）。
- **唯一更正**：本件 §2.1 原写"MTP 另加 2 层"**错** —— 应为 **MTP = 1 个折叠块（`blk.88`，内含 attention 与 MoE 两个子层）**；**模型总块数（GGUF 口径）= 89**。

## 3. 判据：闭合（能变红）

**公式**：`专家层数 × n_expert × 每专家帧字节 ≈ 落盘量`

| 模型 / 帧格式 | 专家帧字节 | 专家层 | 层×专家 | 乘积 | GiB | 落盘量 | 闭合 |
|---|---|---|---|---|---|---|---|
| **Qwen3.8-Flash-Next** NVFP4 | 2,764,800 | 48 | 24,576 | 67,947,724,800 B | **63.281** | (已知) | ✅ 见 §4 |
| **Nemotron** BF16 | 11,010,048 | 41 | 20,992 | 231,122,927,616 B | **215.25** | 231.84 GiB | ✅ 专家占 92.9% |
| **Nemotron** NVFP4(g16) | 3,096,576 | 41 | 20,992 | 65,003,323,392 B | **60.54** | 69.86 GiB | ✅ 专家占 86.7% |

- 每专家帧字节推导（`D`，由 `C` 形状 + `C` 配方）：
  - BF16 = 5,505,024 参 × 2 B = **11,010,048 B**
  - NVFP4 = 5,505,024 × **0.5625**（4bit + 每 16 元一个 FP8 尺度 = 0.5+1/16）= **3,096,576 B**
- 非专家部分：BF16 `231.84−215.25=16.6 GiB`（嵌入 1.07 + lm_head 1.07 + mamba 8.2 + attention 0.5 + latent 0.6 + shared 3.5 + router 0.16 + 视觉/connector + norm ≈ 16.6 ✓）；NVFP4 `69.86−60.54=9.3 GiB`。
- 交叉验收（`D`）：活跃参数 ≈ 22×5.505M×40 + shared 1.76B + mamba 4.38B + attn 0.29B + latent 0.34B ≈ **11.6B ≈ A12B** ✓ 与官方标称自洽。
- index `metadata.total_size` BF16 = 248,906,833,960 B = **231.81 GiB**；HF API 文件求和 = **231.84 GiB**（88 文件 / 64 分片）。

> ⚠️ **修正项目书**：§1 说 BF16 = "115.91 GiB, 65 文件"。实测 = **231.84 GiB**（正好 2×），BF16 参数 124.45B（`safetensors` 元数据）⇒ 该读数有误，建议以本表为准。
